# 初期ウィンドウ配置の変更・確認

## 変更先と座標

初期サイズ・座標は `frontend_ide/デスクトップ/window-layout.cjs` の `windowBounds()`、最小サイズは `windowMinimumSize()` に集約します。`desktop.cjs` の `createWindow()` が生成時だけ適用します。単独起動はマウスポインター側、IDE連携は親IDEがあるディスプレイの `workArea` を使います。座標はタスクバー等を除く論理座標で、負の座標を持つサブ画面も扱います。

Codeは左上、Liveは右上へ、作業領域の端から8px空けて表示します。IDE連携でも親窓の内側へ寄せず、同じ画面の隅を基準にします。通常の幅480・高さ600と、小画面に収める上限は維持します。

IDE連携Codeの2枚目以降だけ、タイトルと共通の `record.slot` に従って右下へ24px単位でずらします。先頭は0px、後続は24〜120pxを循環し、画面内へ制限します。7枚目以降も先頭の0pxへ戻しません。閉じたslotは再利用されます。小画面で余白がない方向はずらさず、窓を画面外へ追い出さないことを優先します。単独CodeとLiveにはこのずらしを適用しません。ピン留めビューアは従来の親IDE基準の配置を維持します。

Termの高さは横長（作業領域の幅 > 高さ）で1/3、縦長・正方形で1/4を四捨五入します。幅2/3、下中央、複数窓の28px右上ずらしは維持します。最小高さ180は初期高さ以下に抑えるため、低い画面でも比率を上書きしません。

現行実装には終了時の座標保存・次回起動時の復元はありません。開いている通常窓の手動移動・リサイズは再フォーカスでは変更せず、新しく生成した窓だけ初期配置を使います。画面回転・ディスプレイ変更でも通常窓を勝手に再配置しません。例外は、利用者が明示的に選択する次のALL表示です。

## IDEの全ディスプレイ表示（ALL）

Electron版IDE本体の右上は `ALL / 最小化 / 最大化 / 閉じる` です。ALLで接続中の全ディスプレイにまたがる1枚の窓にします。ALL中はタイトル・接続バー・宇宙の操作バーを隠し、主ディスプレイの右上へマウスを寄せたときだけ復帰ボタンを表示します。キーボードフォーカスでも表示し、実行すると直前の位置・サイズ・最大化状態に戻します。Code / Live / Term・ピン留め窓にはALLを表示しません。

所有元は `frontend_ide/デスクトップ/全画面横断.cjs` です。`screen.getAllDisplays()` の `bounds` の外接矩形を使い、タスクバーを除く `workArea` や単一画面のfullscreenは使いません。ElectronのDIP座標に拡大率を重ねず、左・上にある負座標の画面も含めます。復帰ボタンの入口だけは主ディスプレイの `workArea` 内へ配置します。外接矩形の右上を基準にすると、不揃いな配置では画面が存在しない空間にボタンが出るためです。

切り替え時は `App.vue` が「ALL切り替え中…」を表示し、`開発スペース.vue` の `prepareAll()` が開いている閲覧セッション（比較表示も含む）と軌跡バー・エクスプローラーをピン留めします。閉じていたエクスプローラー・軌跡バーは元の窓サイズで開いてから移します。再生成せず同じDOMを使い、別窓の表示完了を全件待ってからALLのIPCを呼びます。手動ピン留め中なら同じ処理を待ちます。移行失敗やセッション変更では巨大化せず、完了済みのピン留め窓も破棄しません。

ALL中はIDE本体の移動・リサイズを止め、画面追加・取り外し・回転と最小化からの復帰時に範囲を更新します。解除時に元の操作ボタンの位置が画面外なら、接続中の画面内へ復帰位置を収めます。ピン留め済みの別窓の配置・内容は変更せず、ALL解除でも別窓を保ちます。宇宙表示はパネルの開閉による自動中心補正を停止して全体の中央を使います。画面の継ぎ目に合わせる手動中心調整は未実装です。

ALL中の新規ファイル選択も別パネルが原則です。`開発スペース.vue` は選択ごとの閲覧セッションを保持し、別窓の予約・表示を直列に処理します。表示待ちの本文を巨大なIDE内へ一瞬出さず、同じファイルの再選択は既存窓へフォーカスします。ソース比較はその閲覧セッション内で切り替えます。失敗した要求は保持して再試行でき、ALL解除後にも内容を失いません。エクスプローラー・軌跡の「本体へ戻す」はALL中に表示しません。

ALL中の新規窓の位置は `デスクトップ/panel-windows.cjs` がOSのマウス位置から実ディスプレイを選び、その `workArea` に収めます。新規ビューアーのサイズは通常の別窓用 `windowBounds('viewer', ...)` を共有し、巨大な仮想領域のプレビュー寸法を使いません。ALL切り替え前に開いていたパネルの移行位置は従来どおりです。

IDE起動のCode / Live / Term / Viewerは `BrowserWindow` の `parent`、DOMを移すピン留め窓は `setParentWindow()` でIDEをネイティブの親として指定します。既存の `setAlwaysOnTop(true)` と合わせ、IDE本体を操作しても子パネルを裏に隠しません。IDEフォーカス・ALL切り替え・軌跡リサイズ後には `isAlwaysOnTop()` を確認し、外れた場合だけ再設定します。Windowsの所有関係を持つ窓で同じtrueを再設定すると逆に最前面状態が外れるケースを実機で確認したため、無条件に繰り返さないでください。前後関係のためにフォーカスを奪ったり、再配置したりしないでください。単独起動窓は親を設定しません。

## 確認

`node --test frontend_ide/checks/window-layout.test.mjs frontend_ide/checks/code-window-title.test.mjs`

横長・縦長・正方形・小画面・負座標、親IDEを動かした場合、複数Code、slot再利用、単独起動と連携起動の画面選択、手動配置後の再フォーカスを確認します。Electron生成のテストは実 `createWindow()` と模擬OSを使うため、OS実画面・DPI・タスクバー・ウィンドウマネージャーの挙動の確認とは別です。実機では各向きの初期表示を撮影し、Code 1/2/3、閉じて再作成、Live、Termの上下端・読みやすさを確認してください。

ALLのロジック・中心補正は `node --test frontend_ide/checks/all-displays.test.mjs frontend_ide/checks/workflow-components.test.mjs` で確認します。4画面・負座標・拡大率混在・最大化からの往復・画面取り外し・IPCの呼び出し元制限を含みます。

実Electron確認は、画面の変更を反映した配布物を用意してから `node frontend_ide/scripts/check-all-displays.mjs` を実行します。一時プロジェクトと専用プロファイルを使い、利用者の画面にテスト窓を出さず、比較・軌跡・エクスプローラーの自動ピン留めと元位置保持、ALLの実寸・解除・最大化復帰、バーの非表示、復帰ボタンの位置・ホバー・フォーカスを確認します。画面と結果は `temp/all-displays-check/` に保存します。この確認は接続中の実画面構成だけを対象にするため、複数ディスプレイでの見え方はその実機でも確認してください。
