# 初期ウィンドウ配置の変更・確認

## 変更先と座標

初期サイズ・座標は `frontend_ide/デスクトップ/window-layout.cjs` の `windowBounds()`、最小サイズは `windowMinimumSize()` に集約します。`desktop.cjs` の `createWindow()` が生成時だけ適用します。単独起動はマウスポインター側、IDE連携は親IDEがあるディスプレイの `workArea` を使います。座標はタスクバー等を除く論理座標で、負の座標を持つサブ画面も扱います。

Codeは左上、Liveは右上へ、作業領域の端から8px空けて表示します。IDE連携でも親窓の内側へ寄せず、同じ画面の隅を基準にします。通常の幅480・高さ600と、小画面に収める上限は維持します。

IDE連携Codeの2枚目以降だけ、タイトルと共通の `record.slot` に従って右下へ24px単位でずらします。先頭は0px、後続は24〜120pxを循環し、画面内へ制限します。7枚目以降も先頭の0pxへ戻しません。閉じたslotは再利用されます。小画面で余白がない方向はずらさず、窓を画面外へ追い出さないことを優先します。単独CodeとLiveにはこのずらしを適用しません。ピン留めビューアは従来の親IDE基準の配置を維持します。

Termの高さは横長（作業領域の幅 > 高さ）で1/3、縦長・正方形で1/4を四捨五入します。幅2/3、下中央、複数窓の28px右上ずらしは維持します。最小高さ180は初期高さ以下に抑えるため、低い画面でも比率を上書きしません。

現行実装には終了時の座標保存・次回起動時の復元はありません。開いている窓の手動移動・リサイズは再フォーカスでは変更せず、新しく生成した窓だけ初期配置を使います。画面回転・ディスプレイ変更でも既存窓を勝手に再配置する処理を追加しないでください。

## 確認

`node --test frontend_ide/checks/window-layout.test.mjs frontend_ide/checks/code-window-title.test.mjs`

横長・縦長・正方形・小画面・負座標、親IDEを動かした場合、複数Code、slot再利用、単独起動と連携起動の画面選択、手動配置後の再フォーカスを確認します。Electron生成のテストは実 `createWindow()` と模擬OSを使うため、OS実画面・DPI・タスクバー・ウィンドウマネージャーの挙動の確認とは別です。実機では各向きの初期表示を撮影し、Code 1/2/3、閉じて再作成、Live、Termの上下端・読みやすさを確認してください。
