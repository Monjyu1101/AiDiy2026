# 環境診断の運用

`backend_diag` は、Node.js 標準モジュールだけで起動する任意起動の診断ツールです。起動・認証・Codespaces・検証の詳細は [backend_diag/README.md](../../backend_diag/README.md) を参照してください。

- セットアップとクリーンアップでは最初の選択項目に置き、既定 `[y]/n`、全体の a=auto でも対象にします。
- `aidiy_diag --browser` で起動します。Node.js 自体が無い場合はランチャーが理由と公式導入先を表示します。Python は診断アプリ起動には不要です。
- `_start.py` の IDE グループでは Diag を先頭に置きます。既定は n、選択した場合だけ起動します。全体起動から起動した Diag は全体の終了・クリーンアップ要求で停止し、自動再起動しません。
- Node.js、Python、その他の基盤・コア周辺、機能別の任意依存の順に確認します。任意機能の未検出をシステム全体の故障と判断しないでください。
- 固定 version 引数に副作用が無いことを確認できない項目は、存在確認のみにします。Ollama の `--version` はサーバーへ接続するため実行しません。
- Web 版でも全機能を使えます。Codespaces の転送ポートは Private にし、起動時の認証 URL を共有しないでください。確認対象はブラウザ端末ではなく診断サーバーです。
- カタログ追加ではソース参照と必要な機能を必ず記載します。設定ファイルのキー、ログイン情報、環境変数全体を返す診断は追加しません。

## ソース調査の基準

`backend_diag/coverage.json` の基準コミットに対し、対象ソース・設定 3,333 件を全件全文静的走査し、246 項目へ整理しています。通常の Markdown 本文や画像・音声・モデル等は除外です。各詳細の行番号、`reference/source-manifest.json` の blob SHA、README の調査範囲を照合してください。実行時の導入・認証・接続成功の保証とは別です。

## 拡張予定（未実装）

インストール状況の診断の次に、AI モデルのキー設定状況・API で利用可能なモデル一覧（キー不要も区別）を扱う予定です。その後、設定済みかつ MCP 稼働時に利用者が「試行」を押し、MCP 経由で LLM に「おはよう」を送る応答確認、CLI の応答確認へ進みます。キーの値は表示せず、外部送信・課金があり得る試行を自動実行しません。現在は構想のみで、これらの機能は未実装です。
