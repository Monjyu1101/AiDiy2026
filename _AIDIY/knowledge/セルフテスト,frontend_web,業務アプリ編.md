## 始める前に

試験用の利用者IDは `admin`、パスワードは `********`（アスタリスク `*` を8文字）です。この開発PCの総合テスト用アカウントです。

[説明資料の書き方](./セルテスト,_説明資料の書き方.md#試験の準備と終了)の準備後にログインします。試験データの名称には専用接頭辞を付け、実ID・元の値・参照先を本書の試験データ表に残します。試験日の既存データがある場合は試験IDで絞り込み、日付だけで試験データを判断しません。

この冊子は実データの登録を含みます。既存データを編集せず、試験用の関連マスタを先に作ります。登録・更新後は一覧の表示と再表示を確認し、必要な箇所はAPI／DBの値でも裏付けます。

## 2. マスタを用意する

`/Mマスタ/<機能名>/一覧` から新規登録し、保存後に検索・再表示・変更を行います。各対象で登録・読取・更新・削除を確認します。後続で参照するレコードの削除は7章で行います。

| ID | 対象と操作 | 期待結果 |
|---|---|---|
| WB-201 | M配車区分、M生産区分、M生産工程を試験名で登録します。 | 各選択欄に使え、更新・検索結果が一致します。 |
| WB-202 | M商品分類、M取引先分類、M取引先、M車両を登録します。 | 分類と関連先を正しく選択でき、未選択・取消で意図せず値が変わりません。 |
| WB-203 | 完成品Aと材料BをM商品へ登録します。 | 商品コード・分類・単位等が再表示でも保持されます。 |
| WB-204 | M商品構成で、完成品Aのヘッダーと「材料Bを2個」の明細を保存します。明細を追加・変更・削除します。 | ヘッダーと明細が一組で表示され、再表示でも数量と順序が一致します。明細だけを消してヘッダーが残る操作も確認します。 |

各マスタの主キー・必須項目は現行の編集画面に従います。表示名から型を推測せず、採番されたIDを本書の記録表へ記録します。重複IDの試験には試験用レコードだけを使います。

|---|---|---|
| WB-401 | `/Tトラン/T生産/一覧` で完成品Aを3個、試験工程・日付で登録します。 | ヘッダーと材料明細を確認できます。材料Bの必要量は構成2×生産3＝6です。 |

## 5. 入庫・出庫・棚卸と推移

ほかの試験の影響を避けるため、在庫用の新しい試験商品Cを作ります。初期在庫と対象期間を確認してから進めます。

| ID | 操作 | 期待結果 |
|---|---|---|
| WB-501 | T商品入庫で商品Cを10個登録します。 | 一覧と再表示で数量10を確認できます。推移上の増分も10です。 |
| WB-502 | T商品出庫で同じ商品を3個登録します。 | 増減の符号と残数が一致します。初期0なら残数7です。 |
| WB-503 | T商品棚卸で実棚数8を登録します。保存欄の意味を画面・実装で確認します。 | 棚卸後の残数が8です。差分方式なら調整量は＋1です。8を差分欄へ入れたと推測して合格にしません。 |
| WB-504 | `/Vビュー/V商品推移表` で商品Cと期間を選びます。 | 入庫・出庫・棚卸の順と最終残数を追えます。期間外の行が混ざりません。 |
| WB-505 | 入出庫と棚卸の試験行を1件ずつ変更・削除して再確認します。 | 一覧・明細・推移へ反映されます。各段階の期待残数を先に計算し、実値と照合します。 |

## 7. データの整理と整合性

試験データ本書の記録表を見て、参照する側から片づけます。DBファイル全体の置換は行いません。

| ID | 操作 | 期待結果 |
|---|---|---|
| WB-701 | 試験のT配車、T生産と明細、入庫・出庫・棚卸を削除します。 | 試験対象だけが消え、一覧・払出・集計・スケジュールに残りません。 |
| WB-702 | 商品構成の後、試験商品・車両・取引先・分類・区分・工程を参照順に削除します。 | 参照制約がある場合は案内が出ます。解除後に削除でき、既存データは保たれます。 |
| WB-703 | 本書の記録表の全IDを検索し、開始前の既存データ件数・代表値と比較します。 | 試験残骸と意図しない既存変更がありません。採番や監査記録の正常な増加はデータ破損と混同しません。 |
