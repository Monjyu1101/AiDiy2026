# セルフテスト解説・ナレーション方法

## 使う場面

セルフテスト操作ガイドを、実際のアプリ操作と日本語音声で紹介するときに使います。次の解説前に本書と対象ガイドを読み返し、前回の改善を準備へ反映します。冊子の体裁は [説明資料の書き方](../../_AIDIY/knowledge/セルフテスト,_説明資料の書き方.md) を参照します。

## 実施範囲を照合する基準

章 × 実行形態（Electron単独／単独--browser／VS Code／IDE連携／通常Web8090／Avatar Web8092）ごとに、過去の結果・今回の隔離自動テスト・今回の実機試験・音声解説を分けます。記録がない欄は未確認とし、長押し移動や起動紹介だけで章全体を完了にしません。全章を照合せず「残りは素材・許可待ちだけ」と判断しません。登録を伴わない閲覧機能も、対象ガイドと証拠で実施範囲を照合します。全体の根拠は[共通確認結果](../../docs/セルフテスト、操作ガイド/セルフテスト,共通,確認結果.md)にまとめます。

## 本編前の準備

- VRの独立ビューアは、検索一覧の選択先と同じ文書とは限りません。選択行・表示中のフォルダ・ビューアのファイル名と本文を別々に確認し、本文未切替の段階では選択結果だけを説明します。

- Browser・ConsoleなどIDE統合済みの機能は、現行のガイドと画面で入口を確認し、IDEから開く流れで解説します。プロジェクト名・入力位置が同時に見える大きさに整え、未接続時の利用範囲も実画面に合わせます。 IDEの解説はVRモードを中心にし、必要なパネルを独立表示して読みやすく配置します。銀河を眺める場面は自動探索ON、文字を読む操作説明は必要に応じOFFにし、F11等の通常表示への復帰も事前確認します。

- VS Code版Code/Liveはフォルダ未選択時に入力欄直上の赤字案内を表示し、利用操作を無効化します。通常機能の解説前は対象フォルダを開き、案内が消え、プロジェクト名が一致することを確認します。未選択ガードの紹介と認証・会話接続の確認を混同しません。

- ガイドを読み、機能名・到達点・操作順・成功の目印を短い台本にします。章立てやシナリオを変えません。
- 各解説前にDiagを「ランチャー表示」でミニランチャーへ整え、実画面を確認します。必要なアプリはそこから紹介します。サーバーの起動・停止には触れず、実演中の画面を途中で切り替えません。
- 安全な未実演ガイドから無作為に選びます。Diagの起動停止、破壊的操作、外部送信、秘密情報の表示は対象外です。
- 利用者が特定の送信を明示許可した場合は、その入力・宛先・回数に限定します。Liveの短い会話を紹介するときは、許可された挨拶から実回答までを見せます。送信前にナレーションを終え、応答中はTTSを重ねません。
- 連携先を先に開きます。Browserの下書き連携なら同じプロジェクトのCode／Liveを起動し、接続と入力欄を確認します。モデルへ送信しません。
- 起動前に既存窓を確認し、使える窓を再利用します。実演後は自分が開いた不要な窓を通常の閉じる操作で閉じ、一覧と画面で残りを確認します。録画・サーバー・Diag・利用者の窓と未保存作業を一括終了しません。
- 表示素材・文字サイズ・窓の配置を整えてから本編を始めます。PDFは録画に表示せず、説明文は裏で読みます。記録用の画像保存は不要です。
- 素材の安全確認だけで準備完了とせず、実際のUIで開く経路と初期表示まで確認します。対象形式が文字検索に出ると思い込まず、既知のフォルダ経路を用意します。
- 見せる対象を区別します。Browser機能の解説で、表示素材であるWebサイトやコードの内容説明へ脱線しません。

## 音声と操作


- 合成成功・再生APIの正常終了だけで、利用者の端末に音声が届いたと判断しません。音が聞こえない指摘があれば、既定出力・音量・ミュート・再生側セッションとRDP転送先を確認します。リモートオーディオは物理コンソールのスピーカーと区別し、セッション切断や録画設定変更で対処しません。声を変えず、到達先が未確認なら次の実演へ進まず経路を報告します。

- 利用者の指示により、音声の試聴確認や音質評価の依頼は挟みません。Edge / `ja-JP-NanamiNeural` / 速度比1.2を維持し、確認目的だけの再生は行いません。音声重複を防ぐため、各再生の終了待ちと設定値の内部確認は続けます。無断の音声代替は禁止です。

- 合成応答の `used_provider`・`voice`・`ratio` を照合し、Edge / ja-JP-NanamiNeural / 1.2 の指定と異なる場合は代替再生しません。

- 長押し後の移動は `aidiy_windows_control.mouse_long_press_drag` を使います。例は `hold_duration=0.8`（移動前の保持秒数）、`duration=0.6`（移動秒数）で、`x1,y1,x2,y2` は直前の実画面から決めます。通常の `mouse_drag` の時間を長くして長押しの代用にしません。Tools再起動とクライアント再接続後、専用メソッドの公開を確認してから実演します。詳細な結果と未確認範囲は各ガイド後半のテスト欄へ記載し、共通の操作解説はIDE操作編1か所にまとめます。

- ナレーターとして「何ができるか → 画面のどこを見るか → 操作 → 確認した変化 → 活用のポイント」をつなぎます。
- 本編は機能の目的・使い方・確認できた結果を、落ち着いた肯定的で正確な言葉で伝えます。不安をあおる表現、未確定の障害原因、内部の調査事情を混ぜません。不具合が出た箇所は成功とせず、「この部分は確認してから、あらためてご紹介します」と中立に区切ります。調査・修正は本編と分けて記録・報告し、その場で修正作業の実況へ広げません。重要な操作失敗やデータ・安全に関わる事実は隠さず、必要な相手へ具体的かつ冷静に報告します。利用者への作業進捗と、視聴者向けナレーションを区別します。
- 再開前に前回と同じTTSエンジン・音声名・速度を確認します。サーバー停止を理由にWindows標準音声へ無断で置き換えません。実装の既定値と前回の実使用記録は区別し、声が違うと指摘されたら新規再生を止めて照合します。いつもの音声が利用できない、または前回の設定を確認できない場合は、代替せず利用者に確認します。
- 日本語TTSをPCで実際に再生します。短い文、落ち着いたテンポ、画面上の名称に沿う読みを使います。ツール呼出し等の内部作業を実況しません。
- 本編前に、導入・操作前・結果確認後・終了・次回準備の音声をまとめて合成します。結果用音声は想定に合う実画面を確認できた場合だけ再生し、異なる結果を予定どおり読み上げません。 次の音声を用意してから操作し、長い無音を避けます。読込中は見るべき点や目的を説明し、同じ待機文や埋め草を連呼しません。音声を重ねず、読む間も確保します。
- マウス・キーボードで実演し、主要操作の結果を実画面で確認します。表示切替後は位置と座標系を再確認し、古い座標を使い回しません。
- 未確認の成功を先取りして話しません。TTSの再生成功と、視聴者の聞き取り・理解は別です。
- 準備不足や説明の脱線は短く認め、「ここから操作の流れをもう一度ご紹介します」とtake 2に切り替え、まとまった範囲を撮り直します。

## 保存先と実施方法

実演前に [docsの索引](../../docs/セルフテスト、操作ガイド/_index.md) から対象ガイドを開き、章と実行形態、実施済み証拠を確認します。操作説明・注意点・図解はdocs側の全文を使用します。結果、日時、残件、練習の実施記録はdocs側の使用ガイドと [解説記録](../../docs/セルフテスト、操作ガイド/共通,セルフテスト解説・ナレーション方法.md) へ保存し、ナレッジには再利用する方法だけを残します。

音声は Edge / ja-JP-NanamiNeural / 速度比1.2を使用し、別音声へ無断代替しません。試聴確認や音質評価を利用者へ求めません。締めまで事前合成し、各再生の終了を待ってから次を再生します。画面と素材を先に整え、目的と見る場所を案内し、操作結果を実画面で確認してから説明します。機能の使い方と確認した結果を落ち着いて伝え、未確定の障害調査を本編へ混ぜません。未確認の成功は断定せず、不具合は別に記録します。

1件ごとに自分の不要窓を通常終了し、利用者作業と必要な稼働を保持します。次の解説に向けた整理を音声で案内し、docs側の元ガイドを更新・読戻しします。長押し移動の共通解説はIDEの1か所にまとめ、専用 `mouse_long_press_drag` を使い、入力欄・ボタンを移動対象にしません。
