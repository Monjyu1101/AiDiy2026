## 始める前に

試験用の利用者IDは `admin`、パスワードは `********`（アスタリスク `*` を8文字）です。この開発PCの総合テスト用アカウントです。

[説明資料の書き方](./セルテスト,_説明資料の書き方.md#試験の準備と終了)の起動・アカウント・保存方法を使います。[AiDiy編](./セルフテスト,frontend_web,AiDiy編.md)のログイン後、`/AIタスク`、続いて `/AIチーム` を開きます。

AIが変更する範囲は試験専用フォルダだけです。既存の要求・チーム目標・自動作業の状態を記録し、試験用と混ぜません。自動ループは有限の1回で試し、99回／無制限にしません。

## 1. AIタスク画面と入力

画面は「要求一覧 → 明細 → フロー図」の順に確認します。フロー図は作業の前後関係を示す図です。

| ID | 操作 | 期待結果 |
|---|---|---|
| WT-101 | AIタスクを開き、既存要求を選択・切替します。 | 要求・明細・図が同じタスクを示します。横長／縦長でも選択先が一致します。 |
| WT-102 | 新規要求を開き、必須欄を空にして保存します。取消も試します。 | 入力案内が表示され、不完全な要求や取消した要求が登録されません。 |
| WT-103 | 試験名と専用作業フォルダを設定し、即時の短い要求を登録します。 | 払い出されたIDを確認でき、要求内容・開始条件が再表示でも一致します。 |

要求例：「指定作業フォルダ内だけで、挨拶.txtを読み、task-result.txtに『確認済み』と1行書いてください。他の場所は変更しないでください。」

## 2. 分解、実行、完了

要求の受付、AIによる分解、各明細の実行、生成物の確認を順に行います。

| ID | 操作 | 期待結果 |
|---|---|---|
| WT-201 | WT-103の進捗を観測します。要求と明細を開きます。 | 準備・実行・完了を追えます。表示された明細・ログと実行内容が対応します。 |
| WT-202 | 完了後、結果表示と実ファイルを確認します。再読み込みします。 | `task-result.txt`の内容が正しく、完了記録が残ります。受付だけでは合格にしません。 |
| WT-203 | 試験用の分岐・合流を持つタスクを表示します。先行SEQと図を照合します。 | 分岐と合流が一致します。固定データを使った場合は「図の表示試験」と明記します。 |
| WT-204 | 別の短い実要求で、独立した2ファイル作成と最後の統合を依頼します。 | AIが分岐を生成した場合、先行完了前に合流処理が走りません。直列分解なら実並行の合格にはせず、専用の分岐ケースを追加します。 |
| WT-205 | 専用フォルダ内の、存在しない入力ファイルを指定した要求を実行します。 | 失敗理由が見え、正常完了と混同しません。修正後の試験要求で復帰を確認します。 |
| WT-206 | 試験要求の実行中に中止を押します。 | 対象要求が中止となり、処理・ファイル更新が止まります。他の要求は巻き込みません。 |

観測の初期枠は15分とし、進捗が続く場合は[待ち時間の共通ルール](./セルテスト,_説明資料の書き方.md#操作と待ち時間)に記載した実装上限を踏まえて延長します。途中打ち切りは完了とせず、その時点の状態・ログ・待機時間を残します。

## 3. 実行開始条件

保存された条件と、実際に動き始める時刻を別に確認します。PCの時計は変更しません。

| ID | 操作 | 期待結果 |
|---|---|---|
| WT-301 | 時間指定、間隔、定時、曜日・日付、監視フォルダの入力欄を切り替えます。不正時刻・不正間隔も試します。 | 必要欄だけが有効になり、不正値を保存できません。正しい値は再表示で保持されます。対象ごとに枝番を付けます。 |
| WT-302 | 数分先の時間指定を、試験要求1件へ設定します。 | 分解後、指定時刻前は実行待ち、時刻到達後の毎分判定で実行されます。予定時刻・実開始時刻・完了を記録します。 |
| WT-303 | 短い間隔実行で2周期を確認し、すぐ実行有効をOFFにします。 | 初回は猶予2分を考慮し、その後は指定間隔で動きます。OFF後、次の予定時刻＋90秒まで新しい実行がありません。 |
| WT-304 | 試験専用の監視フォルダを指定します。初回の基準取得後、ファイルを1個追加します。 | 変化前には誤発火せず、毎分判定で変化を検出します。実行後に無変更でも繰り返し発火しません。 |
| WT-305 | 定時実行を当日の数分先に設定し、1周期を観測します。曜日・日付の将来条件は別の試験時計／隔離DBで計算を確認します。 | 当日条件では実発火します。月次などは実時間の長期運用と区別して記録し、計算試験だけを実発火済みとは書きません。 |

条件観測は予定時刻＋90秒までを最初の目安にし、実行完了は別に待ちます。間隔・定時ケースは観測後必ず無効化します。

現行実装では `tasks_watcher.py` に予約・間隔・条件実行の処理があります。要求編集Vueには「登録のみ・即時」とする古いコメントが残っています。コメントだけを根拠に予約試験を省略せず、実動作と照合してください。

## 4. AIチームの要員と依頼

`/AIチーム` を開きます。初期要員のadminは削除しません。

| ID | 操作 | 期待結果 |
|---|---|---|
| WT-401 | 要員・依頼・経験・作業・会話の各領域を開閉し、一覧を選択します。 | 選択と詳細が対応し、表示が更新されます。閉じた領域で不要な監視が続かないことはログ等で補助確認します。 |
| WT-402 | 試験用要員を登録・編集・召喚・解除します。 | 試験要員だけに反映されます。adminは残り、保護動作を確認できます。削除確定を使って既存要員を試しません。 |
| WT-403 | 試験プロジェクトで短い依頼を登録します。 | 受付から完了まで追え、生成物または正式な結果を確認できます。経験・作業の記録と関連が一致します。 |
| WT-404 | 要員名／空間上の要員をダブルクリックし、プロジェクト会話で「挨拶.txtの内容を一文で教えてください。」と送ります。 | 指定先を調査した返答が最大360秒の観測内で確認できます。別プロジェクトの内容が混ざりません。 |
| WT-405 | 試験依頼を中止し、その後に新しい短い依頼を行います。 | 対象だけが止まり、次の依頼を正常に実行できます。 |

## 5. 目標と自動作業

既存目標の元値を保存してから、試験用の目標へ切り替えます。試験が終わったら元へ戻します。

| ID | 操作 | 期待結果 |
|---|---|---|
| WT-501 | 自動作業OFFで、短い目標と作業を保存・再表示します。 | 内容が保持され、OFFのまま勝手に開始しません。 |
| WT-502 | 作業を1回に制限して自動作業とループをONにします。 | S相談→P計画→D実行→C評価→A改善を記録で追えます。完了後に無制限に継続しません。 |
| WT-503 | 自動作業をOFFにしてからONにします。ループのON／OFFも切り替えます。 | OFF→ON時の作業クリアと、ループ時の作業領域の表示が仕様と一致します。作業内容を先に証跡へ残します。 |
| WT-504 | 目標あり・自動作業ON・作業空の条件で会話領域を確認し、直後に自動作業をOFFへ戻します。 | 条件に対応した領域が表示されます。会話が発生した場合は実記録を確認します。表示だけで会話成功とはしません。 |
