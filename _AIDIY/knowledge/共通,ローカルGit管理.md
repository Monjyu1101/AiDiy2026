# ローカル Git 管理

> 文書: `共通,ローカルGit管理.md` | 実装: `_setup.py`, `scripts/local_git_setup.py`, `scripts/local_git_backup.py`, `backend_server/AIコア/AIバックアップ.py`

## このメモを使う場面

- ZIP 展開等で Git 管理情報のない AiDiy に、端末内の変更履歴を用意する場合。

## セットアップ時の動作

通常の `_setup.py` 実行では、Git 導入確認後、未管理フォルダに限って `.git_local` を初期化します。履歴の実体は `.git_local` にのみ置き、標準の `.git` ファイルは作成しません。AiDiy が `--git-dir` / `--work-tree` を明示して操作する独立環境です。通常の `git status`、AI CLI、エディターには自動認識させません。`core.worktree=..` によりフォルダ全体を移動しても参照を維持できます。Node.js 再ビルドだけのモードでは初期化しません。

- 対象または親フォルダに `.git` がある場合は、`.git_local` が同居していても Git 操作を一切行いません。ディレクトリ、worktree / submodule のポインタファイル、壊れたリンクや不正なファイルも保護します。bare リポジトリの管理情報がある場合も対象外です。
- `GIT_DIR` / `GIT_WORK_TREE` / `GIT_COMMON_DIR` が呼び出し元で設定されている場合も、別管理環境の指定を優先してスキップします。
- `.git_local` が既にあるのに `.git` がない場合は、復旧・削除・再初期化をせずスキップします。
- Git 未導入、管理状態を確認できない場合は初期化せず、理由を表示します。
- remote・GitHub 接続・認証情報・グローバル設定・ユーザー名/メールは設定しません。
- セットアップでは最初の `add` や `commit` は行いません。空の履歴を用意し、後述のバックアップ実行時に変更を記録します。
- `.git_local/info/exclude` に `.git_local` と `.gitignore` 自身を除外する規則を置きます。既存の `.gitignore` は書き換えず、その中の除外規則は通常どおり機能します。
- 設定・秘密情報・DB 等を初回コミットへ含めないよう、記録前に対象ファイルを確認してください。初期化だけでは全秘密情報の自動検出を保証しません。

## バックアップ時の変更記録

通常のファイルバックアップ処理に加えて、Git が導入済みで実際のプロジェクトフォルダが未管理の場合は、セットアップと共通の処理で `.git_local` を初期化し、その時点の変更をローカル commit します。既に専用環境がある場合は、`.git` がなく専用管理情報が正常な場合だけ記録します。通常の `.git` ディレクトリやファイルによる開発リポジトリ、親フォルダの Git 環境には作成・自動 commit しません。remote 設定や push も行いません。

- 新規・変更・削除を対象とし、差分がなければ commit しません。ファイルの更新時刻だけでなく内容で判定します。
- 対象は既存バックアップの除外条件と `.gitignore` に従います。`.gitignore` 自身、管理情報、設定、DB、秘密鍵等は記録対象から外します。ファイル内容からあらゆる秘密を検出する機能ではありません。
- `.git_local` のステージ済み変更、index.lock、異なる管理先、不正な管理情報は保護してスキップします。
- Git hooks・clean filters は実行しません。専用の一時 index を使い、通常の `.git` へは作用しません。
- commit の識別子は当該リポジトリの user.name / user.email を使用し、未設定なら実行中だけ `AiDiy Local Backup / aidiy-local@localhost` を使います。グローバル設定やリポジトリの identity 設定は書き換えません。
- Git 記録に失敗した場合も警告を残して既存のファイルバックアップを継続します。
- 過去に利用者が手動で記録した秘密情報を Git 履歴から削除する処理ではありません。

## 旧構成の扱い

旧版が作った `gitdir: .git_local` 形式の `.git` ファイルも既存 Git 管理として保護し、セットアップ・バックアップとも Git 操作をスキップします。`.git` の自動削除や履歴の移行は行いません。通常のファイルバックアップは継続します。

## 確認

新規フォルダでは `.git` がないことを確認します。プロジェクトルートで `git --git-dir=.git_local --work-tree=. status` が利用でき、同じ明示オプションでの `remote` は空、`ls-files` も空です。まだコミットがないため HEAD を必要とする比較は初回コミットまでできません。初期化済みの環境で再度セットアップしても履歴は変更しません。

Git の初期化仕様: https://git-scm.com/docs/git-init
