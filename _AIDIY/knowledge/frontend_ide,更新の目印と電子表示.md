# 更新の目印と銀河の電子表示

## 判定と表示

`frontend_ide/src/ファイル閲覧/更新の目印.js` が2Dと3Dの共通判定を持つ。入力は現在フォルダ直下の、フィルター適用後のファイルだけとする。子フォルダ内の日時や除外されたファイルを最新候補へ混ぜない。

- ブラウザのローカル暦日で今日・前日を判定する。日付の境界は `setHours` / `setDate` を使い、夏時間の日を24時間固定で計算しない。
- 今日のうち最も新しい更新日時を本日最新とする。同率はすべて最新扱い。今日のファイルがなければ今日・最新の強調は付けない。
- 2Dは今日を薄い縁、最新を少し強い縁で表示する。種類別アイコン、文字色、赤い「今日」、フォルダ色、選択・hoverの背景を上書きしない。
- 3Dの直下ファイルは前日1個、今日2個、本日最新4個の電子を表示する。個数は加算しない。それ以前は電子なし。
- 初回、フォルダ・フィルター・セッション切替は基準を取り直し、発光させない。同じ対象内の追加、mtimeまたはsize変更だけを1.2秒の弱い発光で示す。削除済み対象には発光を残さない。無差分更新で発光を再開しない。
- 深夜と非表示からの復帰時に再判定する。既存の2D監視は応答完了から30秒間隔を維持し、この表示処理は新たな走査要求を増やさない。

## CPUとGPUの担当

既存の銀河本体はCanvas 2Dで描画する。`開発スペース/電子の周回.js` は電子専用の小さなWebGL層であり、全画面のGPU化ではない。

CPUは日付判定、対象選定、対象変更時の頂点バッファ生成、カメラ行列と時刻uniformの受渡を担当する。電子ごとの周回座標は頂点シェーダー内で計算し、全電子を1回の `drawArrays(POINTS)` で描く。完成した透過キャンバスを既存Canvasへ1回合成する。電子用RAFを追加せず、2D・非表示では既存の3Dループと一緒に停止する。

OSの動作設定を理由に、規定の更新表示・発光を抑えない。WebGL不可・コンテキスト喪失時は、事前生成した静止スプライトへ切り替える。終了時はバッファ、プログラム、コンテキスト、購読、期限タイマーを解放する。

通常は最大2,048ファイル・8,192電子、静止フォールバックは最大256ファイル。上限を超えた時は最新→今日→前日、同じ区分はパス順で安定して選び、毎フレームの抽選や入替を避ける。上限は追加の電子装飾だけに適用し、ファイル本体・当たり判定・2Dの日時判定は省略しない。

WebGLを利用できても実機GPUでの実行はドライバーとブラウザ設定に依存する。CPU使用率低下や実機GPU加速を、draw回数だけから断定しない。

## 確認

`frontend_ide` で以下を実行する。ブラウザ確認前は明示的にビルドする（単独サーバーはdistを配信する）。

```powershell
node --test checks/update-marks.test.mjs checks/star-depth.test.mjs checks/folder-pages.test.mjs checks/file-dates.test.mjs checks/folder-monitor.test.mjs checks/navigation-parity.test.mjs
node scripts/build.mjs
node scripts/check-update-marks.mjs
```

ブラウザスクリプトは一時プロジェクトと隔離Chrome/Edgeを使う。AIや外部APIへ送信しない。今日/最新同率、変更行だけの発光、日跨ぎ、移動、WebGLの一括描画とバッファ再転送なし、2D・非表示停止、5,000対象の上限を検証し、`temp/update-marks-check/` に画面と結果を保存する。日時テストはUTC、東京、ニューヨークの年跨ぎ・夏時間境界を含む。
