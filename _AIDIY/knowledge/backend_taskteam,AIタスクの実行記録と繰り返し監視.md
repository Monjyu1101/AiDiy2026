# AIタスクの実行記録と繰り返し監視

> 文書: `backend_taskteam,AIタスクの実行記録と繰り返し監視.md` | 実装: `backend_taskteam/task_proc/tasks_api.py`, `backend_taskteam/task_proc/tasks_db.py`, `backend_taskteam/task_proc/tasks_watcher.py`, `backend_taskteam/task_proc/tasks_seed.py`, `backend_taskteam/task_sub/sub_do.py`, `backend_taskteam/task_sub/sub_end.py`, `backend_taskteam/task_sub/sub_context.py`

## このメモを使う場面

- 実行できていたはずの明細が「実行済み記録が空」「成果物が欠けている」で最終検証に落ちる
- 間隔実行・定時実行のタスクが 1 回エラーになったきり、次の周期が来なくなる
- 他のタスクを監視して自動復旧させるタスク（実行監視）を作る、または直す
- 操作検証ありの明細で、画面に応答内容が出ない

## 実行記録が残る経路

明細の `応答内容` が「実行済み記録」として後続明細と最終検証（`sub_end.py`）へ渡る。
記録が残る経路は操作検証の有無で変わる。

| 操作検証 | 記録の書き手 | 空になり得るか |
|---------|------------|--------------|
| なし | `sub_do.py` が code_agents の `result` を `/task/タスク明細/完了` へ渡す | ならない |
| あり | AI 自身が `task_check_okng` の `メッセージ` へ書く | **書き忘れると空になる** |

### 判断基準

- 読み取り専用の調査・検査ステップは操作検証を **false** にする。ファイル書き込みが無いのに true にすると、記録が AI の報告任せになり欠落経路を増やすだけになる。
- 操作検証 true は、実際にファイルを更新・追加する明細だけに付ける。

### 空記録に対する三重の防御（現行実装）

1. `tasks_api.task_check_okng` は 状態='完了' で `メッセージ` が空なら NG を返す。
2. `sub_do.py` は操作検証ありで完了になった後、DB の応答内容が空なら code_agents の `result` で埋め直す。
3. `sub_end.py` も同様に、検証結果で応答内容を補完する。

プロンプト側は `sub_context.py` の `do_verify_lines` / `check_request_lines` に
「メッセージは空にできない」「本文がそのまま実行済み記録になる」「報告先のタスクIDとSEQは指定値をそのまま使う」を明記してある。
`_config/AiDiy_task__context.json` が存在するとそちらが優先されるため、**プロンプトを直したら両方を同期する**。

### 確認方法

```
POST http://127.0.0.1:8093/task/タスク明細/一覧  {"タスクID": "<ID>"}
```

完了した明細の `応答内容` が 0 字なら記録が欠落している。
`backend_taskteam/temp/task/<タスクID>.step<SEQ>.log` に code_agents の `result` が残っているのに
DB が空なら、上の防御 2・3 が効いていない。

## 繰り返し実行が 1 回のエラーで止まる問題

`明細失敗` / `タスク失敗` はエラー時に要求の `実行有効` を 0 にする。
すると `tasks_watcher._保持可能状態()` を外れ、`次回実行日時` がクリアされて
間隔実行・定時実行の **2 周目が永久に来なくなる**。

### 現行の自動復旧

- `_繰り返し自動復旧対象()`: 実行区分が 間隔実行 / 定時実行、要求状態が エラー、かつ **次回実行日時が残っている** ものだけを対象にする。
- 次回実行日時が残っていることを「ループ運用の途中で落ちた」目印に使う。既に日時が空の古いエラータスクは対象外なので、この仕組みを足しても勝手に動き出さない。
- `tasks_db.発火対象外次回実行日時クリア()` も、繰り返し実行のエラー行だけ日時を残すようにしてある。ここを消すと再起動で目印が失われる。
- 発火時は `tasks_db.タスク発火(タスクID, エラー再開=True)` で、エラーの要求・明細を待機へ戻し `実行有効` を 1 に戻す。実行中・準備中の明細が残っているときは再開しない（生きているプロセスを横取りしないため）。
- 連続失敗は `繰り返し自動復旧上限`（既定 3 回）まで。超えたら次回実行日時を消してループを止める。1 周期でも成功すれば数え直す。

### 注意点

- `タスク発火()` で `実行有効 = 1` を書き戻すのは `エラー再開=True` のときだけ。通常の発火で書くと、利用者が個別に外した明細の実行有効まで 1 に戻してしまう。
- 自動復旧の連続回数はプロセス内の `_自動復旧連続回数` で持つ。再起動でリセットされる前提の値なので DB へ持たせない。

### 確認方法

ログに次が出れば自動復旧が働いている。

```
前回の周期がエラーで終わったため自動復旧して再開します: <利用者>/<タスクID> （連続 1/3 回目）
```

逆に次が出たら、そのタスクはループが切れている（修正前の症状）。

```
発火対象外のため次回実行日時をクリアしました: <利用者>/<タスクID> 状態=エラー 実行有効=0
```

## 実行監視タスクの作り方

他タスクを監視して自動復旧させるタスクのひな形は `task_proc/tasks_seed.py` にある。
`tasks_db.初期タスクを投入()` が、AIタスク要求が 0 件のとき（DB 再作成時）だけ 1 件目として書き込む。

### 監視対象の指定は 1 箇所に寄せる

- 監視対象タスクIDは**要求内容（処理目標）の代入行 1 つだけ**に書く。
- 各明細の要求内容にはタスクIDを書かない。`sub_start.py` が要求内容をそのまま開始明細の応答内容へコピーし、それが処理目標として全明細へ渡るので、明細側は「処理目標に書かれた監視対象タスクID」と参照すれば足りる。
- こうしておくと、別のタスクを監視したいときに直す箇所が 1 行で済む。

### 状態の置き方

| 項目 | 値 | 理由 |
|------|----|------|
| 要求の実行有効 | 0 | 置いただけで動き出さないようにする |
| 要求の状態 | 完了 | 明細も全件完了なら `タスク発火()` の条件を満たし、有効化するだけで回り始める |
| 明細の実行有効 | 1 | 要求側の 0 だけでブレーキが効く。明細まで 0 にすると有効化しても起動しない |

### 分岐で組む

判定は `if` 明細として独立させ、Y / N の枝を `or` で合流させる。2 段のネスト（例: エラー発生中か → ロジックの問題か）も
`tasks_db.明細パス伝播()` が変化の収束まで繰り返すので末端まで正しく `パス` が連鎖する。
`or` だけは「全先行が不成立」で初めてパスになる（`_先行不成立確定()`）。

### 復旧検証の合格条件

停止復旧の直後は監視ループがすぐ実行を開始するため、再検査時の要求状態は
待機 / 準備開始 / 準備中 / 実行中 のいずれにもなり得る。
**「要求状態 = 待機」を合格条件にしてはならない**（復旧が成功しているのにエラー報告になる）。

正しい合格条件:

1. 停止 = false
2. 要求実行有効 = 1
3. 進捗のエラーが 0 件
4. 要求状態が エラー でも 中止 でもない

### 注意点

- `tasks_db.タスク要求更新登録()` は `タイトル` を要求内容の 1 行目 40 文字から自動生成する。更新登録を通すとタイトルが変わるので、意図したタイトルを保ちたいときは要求内容の 1 行目を整える。
- 実行中の周期がある状態で `/task/タスク要求/更新登録` を呼ぶと、そのタスクの実行中プロセスを全て強制停止する。周期の完了を待つか、`/task/タスク要求/実行有効切替` で発火を止めてから更新する。
- `/task/タスク要求/本登録` は 状態='エラー' の要求には効かない。先に停止復旧か実行有効切替で状態を戻す。

### 確認方法

```
python -m unittest tests.test_task_seed
```

`backend_taskteam/.venv/Scripts/python.exe` で実行する（システム Python には `fastapi` が無い）。
DAG 整合、勝手に起動しないこと、有効化すれば発火することを検証している。

## 日本語パス API の呼び方

`/task/*` のパスは日本語を含むため、`curl` にそのまま渡すと 404 になる。
パスセグメントを percent-encode する。

```python
url = BASE + "/".join(urllib.parse.quote(p) for p in path.split("/"))
```

AI エージェントが直接呼ぶ用の ASCII 専用エンドポイントとして `POST /task_check_okng` だけが用意されている。

## 現行仕様の同期元

- 監視ループの間隔・タイムアウト・自動復旧上限: `task_proc/tasks_watcher.py` 冒頭の定数
- 1 ステップのタイムアウト計算: `task_sub/sub_do.py` の `CODE実行タイムアウト秒()`（`tasks_watcher` の倍率・最低分と同じ値を持つ二重管理なので、片方を変えたらもう片方も直す）
- 実行監視ひな形の本文と明細: `task_proc/tasks_seed.py`
