# 自動更新起動手順

> 文書: `共通,自動更新起動手順.md` | 実装: `_auto.bat`, `_setup.py`, `_start.py`

## このメモを使う場面

- Windowsでbat一本からclone・更新・通常setup・通常起動へ進む。
- デスクトップにコピーしたbat、またはcheckout内のbatへのショートカットを使う。

## 使い方と対象フォルダ

`_auto.bat` だけをコピーして実行する。外部の `_auto.py` は不要。
旧名から改名したため、ショートカットも `_auto.bat` を指定する。旧名の互換batは設置しない。退避用のフォルダ名は `_auto` とし、ログ用の `automatic` は維持する。
batの開始に必要なのは実行できるPythonとGit。実行ファイルがない、または実行できない場合は項目名とエラーを表示して停止する。退避コピーはPython標準ライブラリを使い、別のコピー用コマンドは要求しない。
プロジェクトのPython要件は3.13以上だが、batは旧版を警告するだけで続行する。Python 3.10.11でも版の判定だけで止めず、選ばれたPythonで通常setupへ進む。setupや依存ライブラリが旧版に対応しない場合は、その実際のエラーで停止し、失敗を成功扱いして起動しない。
Node.js・npm・uvはバージョン確認と警告のみで、未導入でも通常setupへ進む。Node導入やuv更新は `_setup.py` の既存の確認・選択に任せ、batから自動承認しない。

このbatは **CP932・CRLF・BOMなし** で保存し、先頭で `chcp 932` に揃える。日本語表示を維持し、ラベルや制御文はASCIIにする。リポジトリの通常のUTF-8方針に対し、このWindows配布batだけは利用者指定のCP932とする。UTF-8で保存し直さない。setup/start自体の日本語表示・確認内容は変更しない。
setup/startの子処理がコンソールのコードページを変えた場合に備え、終了コードを保存した直後、日本語行を読む前のASCII制御文で932へ戻す。復帰できない場合は日本語処理を続行せず、TEMPを保持して停止する。

更新対象は次の優先順で選ぶ。TEMPへ移った後も、起動前に保存した場所で判定する。

1. 元の実行フォルダ（cwd）に `backend_server` ディレクトリがあれば、そのフォルダ。
2. なければ元batの配置フォルダに `backend_server` があるか確認し、あればそこ。
3. 両方になければ `%USERPROFILE%\AiDiy2026`。存在すれば更新、なければclone。

デスクトップへコピーしたbatは通常3、checkout内のbatへのショートカットは「作業フォルダー」が空でも2になる。明示的に別AiDiyをcwdにした場合は1が優先する。スクリプト配置場所とcwdは別。

`backend_server` は選択の指標のみ。選択先がGitルート・正しいorigin（Monjyu1101/AiDiy2026）・mainであることを検証する。別repo・非Git・detached HEADは壊さず停止する。main上のmerge競合は退避後に復元できる。rebase・cherry-pick・revertの途中は自動abortせず停止するため、利用者がその操作を終了してから再実行する。
Gitの行出力はPythonで読み取り、LF・CRLFを区別せずに検証する。originは許可したHTTPS/SSHの完全一致のみ、branchは `main` のみを認める。行末以外の余計な文字・空白を勝手に除去して許可しない。パスは引き続きCP932へ無損失変換できるものだけを扱う。

## 処理順と確認入力

- 自分を一意なTEMPへコピーし、元batへ戻らずTEMP側で実行する。自己更新しても実行途中の内容が変わらない。
- 最初の「aidiyセットアップと実行しますか？ [y]/n:」は既定Yes・nで中止を維持する。実行ログのファイル名は実行を選んだ後だけ表示し、nで中止したときは表示しない（ログ自体の作成・中止記録は維持）。
- 環境チェック、リポジトリの新規取得・確認、設定・変更の退避、更新、セットアップ、アプリケーションの起動は、実際に進む段階で `_setup.py` / `_start.py` と同じ60文字の `=` と前後の空行を使った見出しを表示する。状態表示も `[INFO]` / `[WARN]` / `[NG]` に揃える（batではANSI色指定を追加しない）。
- ローカル変更・コミット履歴を退避してから `git fetch --no-tags origin refs/heads/main` を実行する。成功した今回の `FETCH_HEAD` をコミットSHAに固定し、追加の上書き対象退避が完了した場合だけ `git -c submodule.recurse=false reset --hard <取得SHA>` で復元する。リモートを優先し、mainのローカル変更・ステージ内容・独自コミット・merge競合は作業ツリーから置き換わる。
- 毎回、通常の `_setup.py` → `_start.py` を実行する。更新有無によるsetup省略は行わない。
- setup/startの確認入力はそのまま端末へ接続する。setupをNoでスキップして正常終了した場合は、元スクリプト同様にstartへ進む。失敗（非0）なら後続を実行しない。
- MCP設定の削除や選択の強制は行わない。
- 対象に `_auto.bat` がない場合だけ、このbatを配置する。同名ファイルは上書きしない。

## 保全・ログ・停止

- `clean`、自動stash、force-pushは使わない。未追跡・ignoredファイルはリモートの追跡パスと競合しない限り残す。競合するファイル、祖先の障害物、置換対象ディレクトリ内のファイルは、退避してからリモート内容へ置き換える。fetch・退避失敗時はresetへ進まない。
- 復元前に追跡ファイルの差分、未追跡ファイル、`_config`、ローカルコミット・merge相手・merge時のautostashを含む `history.bundle`（作成後にverify）を対象checkoutの `temp\_auto\<実行ID>\` へ退避する。worktreeでもそのcheckout内のtempを使い、Git管理領域へ独自ファイルは作らない。既存の `.git\aidiy-automatic` は移動・削除しない。退避失敗も停止する。
- `temp/` は既存の `.gitignore` で除外される。退避先自身は未追跡ファイルのコピー対象からも除外し、無視設定が変わっても自己再帰コピーしない。既存の `temp`・`temp/_auto` がファイル・symlink・junctionの場合は、原本を触らず停止する。
- `_config` はbat内の短いPython処理で、空フォルダ・ファイル内容・通常の更新日時を保持してコピーする。未作成ならスキップする。既存の退避先へ上書き・混合せず、symlink・junctionなどのreparse pointは追わずに停止する。読書きやコピーに失敗した場合もfetch・更新・setupへ進まず、原本と途中の退避を残す。外部の補助Pythonファイルは不要。
- `_data`や既存設定も、リモート追跡パスとの競合がなければ保持する。競合時は上記の退避後にリモートを優先する。setup/start自体の動作・確認選択は現行仕様に従う。
- fetch後の `force_restore_backup` では、indexの全stageとそのblob、現在の追跡ファイルとリモート書込先の実体、merge状態の参照用ファイルを退避する。リンク・junction・submoduleや `temp/_auto` 自身との衝突は、退避の安全性を保証できないためreset前に停止する。退避先の別名・大文字小文字の違いも拒否する。
- 退避に秘密情報が含まれる可能性があるため、共有・アップロードしない。
- 実行ログは `%LOCALAPPDATA%\AiDiy\automatic\logs\`。段階・終了コード・HEAD・退避先を記録する。setup/start出力はログへ複製せず画面に表示する。
- 前提確認は `prerequisite_git` / `prerequisite_python` のように項目別に記録し、実際のツール診断も残す。一括の終了コード2だけでは原因を判断しない。Node/npm/uvの警告は `check_node` / `check_npm` / `check_uv` で区別する。設定退避の失敗詳細も画面と実行ログへ残す。
- リポジトリ検証は `repository_directory` / `repository_files` / `repository_root` / `repository_origin` / `repository_branch` / `repository_gitdir` / `repository_operation` で区別し、失敗理由と実際の検証コマンド終了コードを画面・ログに残す。originの実値は認証情報を含む場合があるため表示・ログへ転載しない。Gitが所有者・権限を拒否した場合も、そのエラーを残して停止し、`safe.directory` 等を自動変更しない。管理フォルダ作成失敗は `repository_control_directory` となる。
- Windowsの `npm.cmd` は子CMDでバージョン確認し、親batの続きへ戻る。Python実行パスはCP932で一時ファイルへ出力する。GitがUTF-8で出力するGit管理領域・未追跡ファイルのパス一覧も、CMDで読む前にCP932へ変換する。CP932へ無損失で変換できない文字は、誤ったパスで処理せず停止する。差分patchや退避するファイル内容は変換しない。
- エラー時はpauseし、元の失敗コードを返す。前提不足2、安全検証3、Git/子プロセスはその終了コード。正常/利用者中止0。
- 二重実行の防止は利用者の責任とする。開始時の注意を確認し、同じcheckoutへの自動実行を重ねない。`run.lock` は作成・確認・削除せず、旧版の `aidiy-automatic\run.lock` が残っていても、それを理由に停止しない。既存ロックの削除作業は不要。履歴退避後にHEADが変わっていたら復元前に停止するが、同時編集を完全に排他する保証はしない。Gitのネイティブロックや各アプリ自身の排他処理は変更しない。同時編集・別Git操作を行わない。
- 終了時は自作した既知の補助TEMPファイルだけを削除し、元のcwdへ復帰する。実行中batの自己削除は行わない。CMDが終了直前に実行ファイルを読み直してパスエラーになる経路を避けるため、小さい実行用コピーはTEMPへ残し、その場所をログの `TEMP_COPY_RETAINED` に記録する。強制削除・遅延削除プロセスも作らない。
- エラー時のpauseは片付け・cwd復帰の後、exitの直前に行う。未知の追加ファイル、失敗したclone、退避は削除しない。

## 退避からの確認・復旧

退避先は実際の対象フォルダの `temp/_auto/<実行ID>/`。フォルダ名を変えた場合も、そのフォルダ内を使う。容量不足やコピー失敗では復元せず停止する。退避には秘密情報も含み得るので公開しない。

- `head.txt` と `history.bundle`: 復元前のHEADとローカルコミット履歴。必要なら **別の空きフォルダ** に `git clone <history.bundleのパス> <復旧用フォルダ>` して確認する。現在のcheckoutへ無条件に戻さない。
- `restore-files/` と `restore-manifest.json`: resetで変更され得た元ファイル・障害物のコピー、存在しなかったパス、復元前HEAD・今回のリモートSHA。必要なファイルだけ内容を比較して戻す。
- `index-stages.bin` と `index-blobs/`: `git ls-files --stage -z` と各blob。ステージ済みの内容やmerge競合のstage 1/2/3を復旧用repoで調べられる。`git-state/` は元index・merge情報の参照用コピーで、稼働repoの `.git` へ一括上書きしない。
- `working-tree.patch` / `staged.patch` / `untracked/` / `_config/`: 従来の差分・未追跡・設定退避も保持する。

reset後の権限・ディスク障害などでは一部だけ更新される可能性がある。失敗を成功としてsetupへ進めず、退避とログを残す。自動ロールバックは行わず、上記資料から別フォルダで確認して復旧する。
