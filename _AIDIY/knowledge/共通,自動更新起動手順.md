# 自動更新起動手順

> 文書: `共通,自動更新起動手順.md` | 実装: `_auto.bat`, `_setup.py`, `_start.py`

## このメモを使う場面

- Windowsでbat一本からclone・更新・通常setup・通常起動へ進む。
- デスクトップにコピーしたbat、またはcheckout内のbatへのショートカットを使う。

## 使い方と対象フォルダ

`_auto.bat` だけをコピーして実行する。外部の `_auto.py` は不要。
旧名から改名したため、ショートカットも `_auto.bat` を指定する。旧名の互換batは設置しない。保全用のフォルダ名は `_auto` とし、ログ用の `automatic` は維持する。
batの開始に必要なのは実行できるPythonとGit。実行ファイルがない、または実行できない場合は項目名とエラーを表示して停止する。必要な保全コピーはPython標準ライブラリを使い、別のコピー用コマンドは要求しない。
プロジェクトのPython要件は3.13以上だが、batは旧版を警告するだけで続行する。Python 3.10.11でも版の判定だけで止めず、選ばれたPythonで通常setupへ進む。setupや依存ライブラリが旧版に対応しない場合は、その実際のエラーで停止し、失敗を成功扱いして起動しない。
Node.js・npm・uvはバージョン確認と警告のみで、未導入でも通常setupへ進む。Node導入やuv更新は `_setup.py` の既存の確認・選択に任せ、batから自動承認しない。

このbatは **CP932・CRLF・BOMなし** で保存し、先頭で `chcp 932` に揃える。日本語表示を維持し、ラベルや制御文はASCIIにする。リポジトリの通常のUTF-8方針に対し、このWindows配布batだけは利用者指定のCP932とする。UTF-8で保存し直さない。setup/start自体の日本語表示・確認内容は変更しない。
setup/startの子処理がコンソールのコードページを変えた場合に備え、終了コードを保存した直後、日本語行を読む前のASCII制御文で932へ戻す。復帰できない場合は日本語処理を続行せず、TEMPを保持して停止する。

更新対象は次の優先順で選ぶ。TEMPへ移った後も、起動前に保存した場所で判定する。

1. 元の実行フォルダ（cwd）に `backend_server` ディレクトリがあれば、そのフォルダ。
2. なければ元batの配置フォルダに `backend_server` があるか確認し、あればそこ。
3. 両方になければ `%USERPROFILE%\AiDiy2026`。存在すれば更新、なければclone。

デスクトップへコピーしたbatは通常3、checkout内のbatへのショートカットは「作業フォルダー」が空でも2になる。明示的に別AiDiyをcwdにした場合は1が優先する。スクリプト配置場所とcwdは別。

`backend_server` は選択の指標のみ。選択先がGitルート・正しいorigin（Monjyu1101/AiDiy2026）・mainであることを検証する。別repo・非Git・detached HEADは壊さず停止する。main上のmerge競合もGitHub内容で書き換えられる。rebase・cherry-pick・revertの途中は自動abortせず停止するため、利用者がその操作を終了してから再実行する。
Gitの行出力はPythonで読み取り、LF・CRLFを区別せずに検証する。originは許可したHTTPS/SSHの完全一致のみ、branchは `main` のみを認める。行末以外の余計な文字・空白を勝手に除去して許可しない。パスは引き続きCP932へ無損失変換できるものだけを扱う。

## 処理順と確認入力

- 自分を一意なTEMPへコピーし、元batへ戻らずTEMP側で実行する。自己更新しても実行途中の内容が変わらない。
- 最初の「aidiyセットアップと実行しますか？ [y]/n:」は既定Yes・nで中止を維持する。実行ログのファイル名は実行を選んだ後だけ表示し、nで中止したときは表示しない（ログ自体の作成・中止記録は維持）。
- 環境チェック、リポジトリの新規取得・確認、書き換え準備、リポジトリの更新(github優先)、セットアップ、アプリケーションの起動は、実際に進む段階で `_setup.py` / `_start.py` と同じ60文字の `=` と前後の空行を使った見出しを表示する。状態表示も `[INFO]` / `[WARN]` / `[NG]` に揃える（batではANSI色指定を追加しない）。
- 確認前に、追跡ファイルのローカル変更を破棄する注意を表示する。`git fetch --no-tags origin refs/heads/main` に成功した今回の `FETCH_HEAD` をコミットSHAに固定し、必要なローカルファイル保全が完了した場合だけ `git -c submodule.recurse=false reset --hard <取得SHA>` で書き換える。mainのローカル変更・ステージ内容・独自コミット・merge競合はGitHub内容で置き換わる。
- 毎回、通常の `_setup.py` → `_start.py` を実行する。更新有無によるsetup省略は行わない。
- setup/startの確認入力はそのまま端末へ接続する。setupをNoでスキップして正常終了した場合は、元スクリプト同様にstartへ進む。失敗（非0）なら後続を実行しない。
- MCP設定の削除や選択の強制は行わない。
- 対象に `_auto.bat` がない場合だけ、このbatを配置する。同名ファイルは上書きしない。

## 保全・ログ・停止

- `clean`、自動stash、force-pushは使わない。通常の未追跡・ignoredファイル、`_config`・`_data`などはGitHubの追跡パスと競合しない限りそのまま残す。
- GitHubのファイルに置き換わる未追跡・ignoredファイル、祖先の障害物、置換対象ディレクトリの内容だけを `対象フォルダ/temp/_auto/<実行ID>/preserved-files/` へ保全する。保全失敗ではresetしない。競合する設定・データも、この保全後はGitHubの内容を優先する。
- **追跡ファイルの未保存・ステージ済み変更やローカルコミットを復旧するための全量退避は行わない。** `history.bundle`、index blob、全追跡ファイル、全未追跡ファイル、`_config`全体の毎回コピーを撤去した。必要な変更は実行前に利用者が保存・退避する。
- `head.txt`・`remote-head.txt`・`preserved-manifest.json` は対象SHAと保全対象を確認するための小さい記録。履歴復旧用のbundleではない。過去の `temp/_auto`・`.git/aidiy-automatic` の成果物は自動削除しない。
- `temp/` は既存の `.gitignore` で除外される。保全先自身に重なる追跡パスやその別名は拒否し、自己再帰コピーをしない。既存の `temp`・`temp/_auto` がファイル・symlink・junctionの場合は停止する。確認対象のリンク・reparse pointやsubmoduleも安全に扱えないため停止する。
- fetch失敗、保全失敗、HEAD変更では書き換えに進まない。保全先は実際の対象checkout内で、フォルダ名を `Xxxxx` に変えた場合は `Xxxxx/temp/_auto/`。Git管理領域へ独自ファイルは作らない。
- 置換対象ディレクトリに大量のローカルデータがある場合は、その保全には時間と空き容量が必要。通常の `.venv`・`node_modules`・過去の保全を全走査・コピーする処理は追加しない。ただしGitHub側がその場所をファイルで置換する場合は保全対象になる。
- 保全に秘密情報が含まれる可能性があるため、共有・アップロードしない。setup/start自体の動作・確認選択は現行仕様に従う。
- 実行ログは `%LOCALAPPDATA%\AiDiy\automatic\logs\`。段階・終了コード・HEAD・保全先を記録する。setup/start出力はログへ複製せず画面に表示する。
- 前提確認は `prerequisite_git` / `prerequisite_python` のように項目別に記録し、実際のツール診断も残す。一括の終了コード2だけでは原因を判断しない。Node/npm/uvの警告は `check_node` / `check_npm` / `check_uv` で区別する。保全の失敗詳細も画面と実行ログへ残す。
- リポジトリ検証は `repository_directory` / `repository_files` / `repository_root` / `repository_origin` / `repository_branch` / `repository_gitdir` / `repository_operation` で区別し、失敗理由と実際の検証コマンド終了コードを画面・ログに残す。originの実値は認証情報を含む場合があるため表示・ログへ転載しない。Gitが所有者・権限を拒否した場合も、そのエラーを残して停止し、`safe.directory` 等を自動変更しない。管理フォルダ作成失敗は `repository_control_directory` となる。
- Windowsの `npm.cmd` は子CMDでバージョン確認し、親batの続きへ戻る。Python実行パスはCP932で一時ファイルへ出力する。GitがUTF-8で出力するGit管理領域のパスも、CMDで読む前にCP932へ変換する。保全対象のパスはPython内で扱う。CP932へ無損失で変換できない文字は、誤ったパスで処理せず停止する。保全するファイル内容は変換しない。
- エラー時はpauseし、元の失敗コードを返す。前提不足2、安全検証3、Git/子プロセスはその終了コード。正常/利用者中止0。
- 二重実行の防止は利用者の責任とする。開始時の注意を確認し、同じcheckoutへの自動実行を重ねない。`run.lock` は作成・確認・削除せず、旧版の `aidiy-automatic\run.lock` が残っていても、それを理由に停止しない。既存ロックの削除作業は不要。実行開始時からHEADが変わっていたら書き換え前に停止するが、同時編集を完全に排他する保証はしない。Gitのネイティブロックや各アプリ自身の排他処理は変更しない。同時編集・別Git操作を行わない。
- 終了時は自作した既知の補助TEMPファイルだけを削除し、元のcwdへ復帰する。実行中batの自己削除は行わない。CMDが終了直前に実行ファイルを読み直してパスエラーになる経路を避けるため、小さい実行用コピーはTEMPへ残し、その場所をログの `TEMP_COPY_RETAINED` に記録する。強制削除・遅延削除プロセスも作らない。
- エラー時のpauseは片付け・cwd復帰の後、exitの直前に行う。未知の追加ファイル、失敗したclone、退避は削除しない。

## 保全ファイルの確認

GitHubと競合していた未追跡・ignoredファイルが必要なら、`preserved-manifest.json` と `preserved-files/` を確認し、内容を比較して必要なファイルだけ別の場所へ取り出す。追跡ファイルのローカル変更については、今回のランチャーは復旧用コピーを作らない。

書き換え開始後の権限・ディスク障害などでは一部だけ更新される可能性がある。失敗を成功としてsetupへ進めず、保全先とログを残す。自動ロールバックは行わない。

## 検証

```bash
python3 -m unittest scripts.checks.test_auto
```

静的構造、確認入力、対象フォルダ、固定したGitHub SHAへの書き換え、追跡変更の破棄、未追跡・ignored障害物だけの保全、取得・保全失敗時停止、危険なパス拒否を一時Gitで検証する。旧全量退避と新しい確認処理の一時fixture速度・Gitプロセス数も比較する。Windows CMD実行試験とは区別し、実Windowsの速度やGUI起動は未測定。外部通信・利用者PC操作・実setup/startは行わない。
