# X系小説解説ビデオ作成手順

> 文書: `frontend_web,X系小説解説ビデオ作成手順.md` | 実装: `backend_tools/aidiy_automations/ビデオページ生成/ビデオページ生成_小説小話.py`、`frontend_web/public/Xビデオ/本好き_貴族院13_ja/`（様式の基準）、`scripts/generate_novel_telop_timing.py`、`scripts/novel_update_durations.py`、`scripts/novel_check_endings.py`、`scripts/novel_stt_check.py`、`scripts/booklove_pause_pass.py`

## このメモを使う場面

- Web 小説の解説動画（女性一人語り・全22ページ）を新しく作る、または台本を見直す
- 作品フォルダ（例: `Xビデオ/本好き__貴族院/`）の `動画作り方.md` を作る・更新する
- 完成済みの回の音声や読みだけを直す

## 構成

| 置き場所 | 内容 |
|---|---|
| 本書 | 全作品共通の作り方・台本の書き方・注意点（正本） |
| `Xビデオ/<作品>__<範囲>/動画作り方.md` | その作品だけの内容。原作の確認方法、全回のページ割り（話数の割り当て）、作品固有の呼称・注意、制作中の状況 |
| `Xビデオ/<作品>__<範囲>/<作品>__<範囲>_NN.md` または `構成案_NN.md` | 各回の解説シナリオ・構成案 |
| `Xビデオ/<作品>_<範囲>NN_ja/` | 完成した動画ページ（1回分） |

作品フォルダには `_素材確認.md` を作らない。話数の対応表は `動画作り方.md` の「ページ割り」に置く。
作り方・注意点を作品側へ書き写さない。作品側に書くのは、本書と違う点と、その作品だけの事実に限る。

## 様式（女性ナレーター最新様式）

基準ページは `本好き_貴族院13_ja`。新しい回はこれと同じファイル構成・書式にそろえる。

- 全22ページ: `scene_000`（導入）、`scene_001`〜`scene_020`（本編）、`scene_999`（まとめ）。
- `scenario.json` のキー順: `project_name`, `version`(`mcp`), `title`, `source`, `target`, `assets_policy`, `language`, `visual_direction`, `timing_status`, `total_short_duration_sec`, `total_long_duration_sec`, `scenes`。`scenario.js` は同じ内容を `window.SCENARIO = ...;` で持つ。
- `assets_policy`: `left_avatar_38_right_content_62`、`../_vrm/VRM_female.vrm`、`edge:female`。
- 音声は short / long 各22本（計44 MP3）。指定場面の後に 1 秒の無音（`pause_after_*`、`scripts/booklove_pause_pass.py`）。
- `_gen_audio.py` は基準ページの版を使う（`PRONUNCIATION_OVERRIDES`、`--only-file`、`--force-long` 対応）。
- サムネイル: `_サムネイル.svg` は `_サムネイル背景.png` を参照し、`_サムネイル.png` を書き出す。
- 全ページの `expression` は `neutral`。`chips`、`metrics`、`cards`、`facts`、`evidence` は空配列。

## 原作の確認

- 台本を書く前に、対象回の原作を 1 話ずつ読む（Web 掲載版の URL は各作品の `動画作り方.md`）。本文ファイルは保存・転載しない。
- 確認するのは、人物と立場、場所と情景、誰が何を言い・したか、心の動き、話の境目と最後の引き。
- Web 版と書籍・漫画・アニメの展開を混ぜない。原作に書かれていない台詞・事件・心理は足さない。
- 要約だけで書かない。要約ツールの人名・続柄の取り違えがあるので、固有名詞と関係は本文で確かめる。
- 1 話ずつ WebFetch で「場面ごとの出来事、登場人物の立場、心の動き、情景、最後の引き」を要約させて読む（原文は引用させない）。要約が曖昧な点（誰がどこにいたか、誰が何をしたか）は、その点だけを聞き直して確かめる。
- 原作での呼び名をそのまま使う。原作が単に「マント」と呼ぶ神具に「夜空のマント」と名前を付けない。見た目の描写は、原作に書かれた範囲だけ。
- 人物の位置関係（誰が最初から戦場にいたか、誰が後から来たか）は、台本を書く前に本文で確かめる。

## 台本の書き方

目指す水準は「聞き手が感情移入できるほど鮮明な、第三者（女性語り手）の解説」。聞いて楽しむ小説解説であり、出来事の報告書ではない。

### 語り

1. 場面ごとに、原因 → 選択 → 結果 → 意味の流れで語る。出来事を時系列に並べるだけの羅列にしない。
2. 登場人物の心の動き（恐れ、悔しさ、喜び、戸惑い）と、情景（光、音、匂い、温度、手ざわり）を、原作に書かれた範囲で具体的に描く。
3. 場面が変わるたびに、場所と状況を短く言い直す（画面を見なくても分かるように）。
4. 人物は名前と立場を添える（例: 神官長フェルディナンド）。間が空いた再登場でも役割を言い直す。固有語は初出直後に平易な説明を置く。
5. 原文の台詞・地の文は転載しない。台詞は「〜と言います」の間接話法か、ごく短い要旨にして自分の言葉で言い換える。
6. `scene_000` は初見向けの全体説明、全編ネタバレを含むこと、原作の代わりではなく読書への入口であることを伝える。
7. `scene_999` は解決したことと未解決のことを分け、次回で新しく起きることを一つだけ予告する。本編で説明済みの内容を繰り返さない。
8. `scene_000`〜`scene_020` では AiDiy を宣伝しない。`scene_999` の最後にだけ短く触れる。

### 情景と感情移入

- 各場面では、原作で確認できる場所、目に入る物、人物の動きや反応から具体的な描写を選ぶ。聞き手が画面なしでも、その場に誰がいて何が起きているか思い浮かべられるように語る。
- 気持ちを「嬉しかった」「怖かった」と名付けるだけで済ませず、何を知り、何を望み・恐れ、どの言動に表れ、次に何を選んだかをつなぐ。転機では結論を急がず、人物が受け止める過程を追い、聞き手が感情移入できる厚みを持たせる。
- 光・音・匂い・温度や表情、しぐさは、原作にある場合だけ使う。書かれていない情景や心理を創作して雰囲気を足さない。描写が少ない場面は、確認できる行動や立場の変化を丁寧に語る。
- 推敲時は「聞き手に場所と人物の関係が見えるか」「その人がなぜ迷い、喜び、傷ついたかが伝わるか」を声に出して確かめる。抽象的な感想や同じ説明の繰り返しで長くしない。

### 文末（聞きやすさ）

- 「〜だった」「〜た。」「〜でした」「〜ました」の過去形が続くと、箇条書きを読み上げたように聞こえる。語りは現在形（〜ます）を中心にする。
- 「〜ています」「〜のです」「〜ません」、体言止め、問いかけを混ぜ、同じ文末を 3 文続けない。「でした」は 1 場面に 1 回程度。「のです」も 1 場面 2 回までを目安にする。
- 体言止めと常体（「〜る。」「〜ない。」）は、短く畳みかける効果に使ってよい。ただし連続は 3 文まで。
- short 版も同じ基準。全ページが過去形の一文、にしない。
- 機械的に過去形を現在形へ置換すると「〜ます」が長く連続する。置換で済ませず、文を組み直す。

### 長さ

- long の 1 場面 500〜700 字程度（約 75〜100 秒）は初稿の目安で、上限ではない。原作の出来事を聞いて理解できるように描くためなら、700 字・100 秒を超えてよい。
- 1 回のロング版は完成音声の実測で 27 分以上とする。合計尺に上限は設けず、27 分を超えたことを理由に必要な説明を削らない。
- 尺が足りないときに、感想文・挨拶文・抽象的なまとめ文を足して水増しすることは厳禁。原作を読み返し、まだ描いていない場面・会話・情景・心理を足す。
- 各場面の末尾に、その場面の出来事をもう一度たどる段落を足さない。加筆した事実が前段と重なっていないか、短い版だけでなくロング版の中でも確認する。別の場面で説明する出来事を繰り返す場合は、つながりに必要な一文に絞る。
- 重複を未説明の場面へ差し替えたら、短い原稿、見出し、挿絵、正本の台本も同じ内容にそろえる。再録後はMP3の実測尺から開始秒と字幕タイミングを再計算する。

### 見直しの確認

仕上げの前に `python scripts/novel_check_endings.py <動画ページのフォルダ>` で文末を数える。過去形の割合、同じ文末の連続、「でした」「のです」の回数が基準に収まっているか確認する。

## 読み（音声）

Edge TTS では、次のような語の誤読が確認されている。通常の漢字交じり文を基本とし、対象の文脈で誤読を確認した語と、読みが確定している作品語だけを `PRONUNCIATION_OVERRIDES`（`_gen_audio.py`）へ指定する。文面（字幕）は変えず、TTS に渡す文字だけが置き換わる。

**漢字を基本に、誤読しやすい箇所だけひらがな化する。** 正常に読める語の指定を増やさず、修正後の音声が良好と確認された場合は、その版を維持する。追加修正は具体的な誤読箇所を対象にする。

| 語 | 誤読の例 | 指定 |
|---|---|---|
| お父様 | ととさま | `おとうさま` |
| 人が（例: 人がそのまま乗り込める） | にんが | `ひとが` |
| 闇の神・闇のマント・闇の祝福 | あん〜 | `やみの神`・`やみのマント`・`やみの祝福` |
| 騎獣・神具・祝詞・養母・養父・汚泥・項垂れる・側仕え・東屋 | 誤読しやすい | `きじゅう`・`しんぐ`・`のりと`・`ようぼ`・`ようふ`・`おでい`・`うなだれる`・`そばづかえ`・`あずまや` |
| AiDiy | エーアイディー | `アイディ` |
| 城（建物を単独で指す） | じょう | `しろ`。城門・城壁・入城・固有名詞は別に判断する |
| 主（側近が仕える相手） | ぬし | `あるじ`。持ち主・主に・主な・領主などは別に判断する |
| 一行（同行する人たち・一団） | いちぎょう | `いっこう`。文章の一行・一行目は`いちぎょう`・`いちぎょうめ`なので、文脈で区別する |

一文字の漢字は文脈で読み分ける。過去の小説解説で確認した例:

この表は文脈判断の参考であり、掲載語をすべてかなへ置換する指示ではない。通常の漢字交じり文での発音を先に確認し、必要な箇所だけ指定する。

| 漢字 | 読み分け |
|---|---|
| 実 | 木の実・実を結ぶ=`み`、実は・実に・実の父母=`じつ` |
| 城 | 建物を単独で指す=`しろ`。「城へ戻る」「城で会う」は`しろ`。城門・城壁・入城や固有名詞は別に判断する |
| 主 | 仕える相手=`あるじ`。「主に仕える」「主を守る」は`あるじ`で、`ぬし`にしない。主に・主な=`おも`。領主・当主・主張・持ち主は別の語 |
| 間 | 待つ間・二人の間=`あいだ`、間もなく・最奥の間=`ま`、合間=`あいま` |
| 額 | 額に触れる=`ひたい`、支払う額=`がく` |
| 名 | 名を捧げる・名を預ける=`な` |
| 方 | 敬称=`かた`、比較・方向=`ほう`、使い方などの接尾辞=`かた` |
| 空 | 空を飛ぶ=`そら`、空の器・空の農村=`から`、上の空=`うわのそら` |
| 金 | お金・金の流れ=`かね`、金色・金の光=`きん` |
| 柄・地 | 模様の柄=`がら`、杖の柄=`え`。土地=`ち`、染める布の地=`じ` |
| 館・宴・杯・礎 | `やかた`・`うたげ`・`さかずき`・`いしずえ` |
| 階 | 建物の階=`かい`。かな変換が古語の`きざはし`を選ぶ場合がある |

誤読が多い回は `tts_narration.json` に各MP3のTTS専用原稿を保存してもよい。貴族院17〜20はこの方式で、通常の漢字交じり文を保ち、確認済みの誤読語だけ読みを指定する。全文を自動でかなに変換することを既定にしない。字幕用の `short_narration` / `long_narration` は変えない。

- 全文の自動かな変換は使わない。「二本→にぽん」「荷馬車→にうましゃ」「額を弾く→ひたいをひく」などの誤変換を音声入力に固定してしまう。通常の数詞・動詞・熟語は漢字を残し、実際に確認した誤読に対する指定だけを加える。かなで書いてあることだけで発音が正しいと判断しない。
- 読みを確認する際の参考: 「一日に二度」は`いちにちににど`（日付の`ついたち`ではない）、「一滴」は`いってき`、「町へ降りる」は`まちへおりる`、「鍛冶」は`かじ`。これらも通常は漢字を残す。「主に仕える」の主は`あるじ`で、頻度を表す`おもに`とは違う。
- 「数日間」は`すうじつかん`、「一区切り」は`ひとくぎり`、「気に入って」は`きにいって`、「有力者」は`ゆうりょくしゃ`。先に短い語をかなへ置換すると、残った「間」「者」などが誤解析される場合があるため、長い語と活用形も確認する。単独の城は`しろ`、城門など熟語の読みは別に確認する。
- 各トラックに字幕原稿とTTS原稿のSHA256を保存し、`_gen_audio.py` は一致を検査する。字幕を変えたら読み原稿も再確認する。ハッシュだけを更新して旧い読みを通さない。
- 「旧ヴェローニカ派」のような熟語は、原則として漢字を残す。かなで指定する必要がある場合は、名詞の「派」と助詞「は」を区別できるよう、文脈を含めて指定する。
- 貴族院17〜20の漢字を保った読み原稿は `scripts/novel_minimal_reading_20261003.py` の対象語と単語境界の確認を参考にする。`novel_prepare_tts_readings.py` の全文かな変換と、古い `novel_dedup*_audio*` のかな準備処理は再適用しない。読み指定を増やす場合も、一般語へ広げず、原稿中の語・文脈と音声で必要性を確認する。
- 単独の「主」は`あるじ`と指定できるが、「領主」「主に」「主な」は漢字を残す。「館」は`やかた`と指定しても、「図書館」には波及させない。部分一致での一文字置換を避け、単語境界または具体的な文脈を指定する。
- 城を建物として単独で指す箇所は、誤読が確認された回で`しろ`と指定する。「直接城へ」も`直接しろへ`。この「城」は辞書解析で接尾辞となる場合があるため、名詞判定だけに頼らず対象の文脈を確認する。「城門」「城壁」「入城」や固有名詞の末尾の「城」は別の読みなので、一括置換しない。貴族院18〜20の部分再録は `scripts/novel_castle_reading_20261003.py` を参照する。
- 音声認識、原稿、最終TTS入力、MP3のハッシュを `audio_review.json` に残す。ASRの固有名詞・同音語の別表記だけで誤読と判断せず、低一致の区間は時間窓を重ねて再確認する。全編を耳で確認していない場合は、その旨も記録する。
- ASRと読み原稿を音で比較するときは、形態素の補助記号・記号・空白を除いてから読みを連結する。空白を`キゴウ`と読む辞書出力を含めると、単語間に空白を含むASRの一致率を不当に下げる。

- 置き換えは文字列の部分一致。「暗闇」のように別の語に含まれる場合は、周りごと指定する（`闇` だけを `やみ` にしない）。
- 台本を直したら、指定の語がまだ文面に含まれるか確認する（含まれない指定は無害だが、意味のない指定になる）。
- 「一行」は人物の集団なら`いっこう`、文章の行なら`いちぎょう`。「一行は城へ向かう」「一行を迎える」は集団として読み、「文章を一行読む」「一行目」は行数として読む。TTSへ渡す対象の句だけを指定し、共通辞書で「一行」を一律に置き換えない。貴族院編・女神の化身編の両方で確認する。
- 読みの確認は `backend_tools/.venv/Scripts/python.exe scripts/novel_stt_check.py <mp3> --find 語` で行う。音声認識が別の語に聞き取るときは、誤読の疑いが強い。20 秒の区切りをまたぐ語は認識が欠けるので、`--window` を変えて重ねる。聞き分けにくい語は、耳で確かめる。

## 見直しの手順（第15回以降も同じ）

着手前に、公開・撮影済みの範囲と対象フォルダを確認する。生成・録画・再生確認が進行中の回には変更を反映せず、別の作業場所で原稿を見直す。資料の点検・手順の更新だけを依頼された場合は、以下の音声生成やステップ実行まで進めない。

1. **原作を読む**: 対象話を 1 話ずつ読み、場面・人物の位置・心の動き・情景・最後の引きを控える。
2. **台本を書く**: 「台本の書き方」に従い、22 場面の short / long を書く。既存の文面は土台にしてよい。大幅に書き直してよい。
3. **確認する**: `novel_check_endings.py` で文末を数え、長さの見込み（1 秒あたり約 6〜7 字）が 27 分以上か確認する。原作にない説明（見た目、呼び名、位置関係）を足していないか、書いた本人が読み返す。
4. **反映する**: 作品フォルダの各回の正本 md と `scenario.json` の short / long を場面ごとに一致させ、`scenario.js` に同じ内容を `window.SCENARIO = ...;` で書く。正本に旧稿と「差し替え原稿」が併存する場合は、採用する原稿を明示する。場面のタイトル・見出し・挿絵も照合し、前の説明が残っていないか確認する。
5. **音声を録る**: 読みを `PRONUNCIATION_OVERRIDES` に入れ、先に元の MP3 を退避してから `python _gen_audio.py --only-file <対象MP3名を空白区切りで列挙>` を実行する。全改稿なら44本、部分修正なら変更した short / long だけを指定する。TTS専用原稿を使う場合は、対象回の `_gen_audio.py` に `tts_narration.json` の読込・ハッシュ検査が実装されているか先に確認する。未対応の回へ JSON だけ置いても読みは反映されない。全 44 本で数分かかる。バックグラウンドで実行し、終了通知を待つ（打ち切ると一部だけ新しい音声になる）。
6. **尺と字幕を更新する**: `python scripts/novel_update_durations.py <フォルダ> "<timing_status の文面>"` で実測尺・開始秒・`assets.json` を更新し、`python scripts/generate_novel_telop_timing.py --write --page <フォルダ名>` で字幕タイミングを作り直す（全 44 本が一致すること）。
   - 区切り数が 1 か所だけ合わないときは、原稿を削る前にその MP3 の無音を短い閾値でも調べ、音声認識の時間窓と突き合わせる。文末の短い間合いが検出閾値より小さい場合は、その場面の `telop_timing.json` だけ実音に合わせて補正する。補正後に字幕の文数と順序を確認する。
7. **聞いて確認する**: ブラウザで再生し、読み間違い・つながり・事実の誤りを確かめる。直す点が出たら、該当場面だけ 2〜6 を繰り返す（音声は `--only-file` で対象だけ録り直す）。再生開始、最後の画面への到達、最後の音声の再生終了、全編を耳で確認したことを区別して記録する。スピーカー有効・消音なし・音量・実音声時刻の進行を確かめ、`scene_999` の音声終了まで確認する。音声を差し替えたら、古いキャッシュを再生していないか対象回の音声URLとシナリオの更新識別子も確認する。
8. **制作状況を更新する**: 作品フォルダの `動画作り方.md` の「制作状況」に、改稿日、尺、未実施の作業を書く。

`audio_review.json` が存在するだけでは現行44本の照合完了としない。原稿・TTS入力・MP3のハッシュと照合対象が現在のファイルに対応するかを確認する。記録がない、古い、抜粋だけの場合は未確認の範囲を残す。原作照合、機械的な素材検証、ASR照合、実音声の再生終了、耳での確認は別々の確認項目として扱う。

## 画像

- 横長 16:9 のオリジナル挿絵。公式イラスト、アニメ、漫画、書影、作品ロゴ、既存キャラクターデザインを模倣・複製しない。
- 画像内に読める文字、固有作品ロゴ、企業ロゴを入れない。左 38% はナレーター用に静かに空ける。

- 人物が不要な場面は、本、地図、祭壇、神具など象徴物を主役にする。流血・処刑・誘拐などは影、閉じた扉、残された物で間接的に示す。

## ステップ実行

作業ディレクトリは `backend_tools`。生成設定 `aidiy_automations/ビデオページ生成/_ビデオページ生成_小説小話_設定.json` の `topic`、`folder_name`、`template_dir` を対象回へ切り替えてから実行する。

```powershell
.venv\Scripts\python aidiy_automations\ビデオページ生成\ビデオページ生成_小説小話.py <ステップ番号>
```

| Step | 内容 | 主な確認対象 |
|---:|---|---|
| 0 | 初期確認 | 設定、テンプレート、各API、出力先 |
| 1 | フォルダ作成 | テンプレート構造、進捗Markdown |
| 2 | ルーティング追加 | Xビデオのメニュー登録、URL表示 |
| 3 | シナリオ作成 | `scenario.js`、22シーン、short/long原稿 |
| 4 | HTML修正 | タイトル、説明、プレイヤー構造 |
| 5 | 画像生成 | 全22枚、重複・欠落なし |
| 6 | 中間確認 | 内容、表現、画像、`scenario.json`同期 |
| 7 | 音声生成 | short/long各22本、合計44 MP3 |
| 8 | 音声照合 | 音声認識で誤読を検出し、読み指定を追加して再合成（`audio_review.json`） |
| 9 | 再生時間更新 | MP3実尺、開始秒、総再生時間 |
| 10 | 最終確認 | 画像・音声・HTML・manifest・メニュー |
| 99 | 完成案内 | `complete_steps=99` |

- 各ステップの後、`_ビデオページ生成_小説小話_状況.json` の `complete_steps` と成果物を確認する。失敗したら先へ進まず同じ番号を再実行する。
- 構成案を完成台本として Step 3 へ渡さない。台本を原作と照合してから進める。
- テンプレートは実在する完成回（基準ページか直前回）を使う。前回の題名・ナレーション・画像・音声・進捗が残っていないことを各ステップで確認する。
- Step 08 の仕様は `utils/steps.py` の `step_review_audio`。字幕（原稿）は変えず、TTS に渡す文字だけ `_gen_audio.py` の `PRONUNCIATION_OVERRIDES` で読みを指定する。

## 完成済みの回を直す

- 直す前に、対象の回が公開済み・撮影済みでないかを確認する（各作品の `動画作り方.md` の公開状況）。公開済みの回は台本・音声・タイトル・サムネイルを再修正しない。
- 手順は「見直しの手順」と同じ。変えた場面だけを直すときは、変わった MP3 だけを `--only-file` で録り直し（元の MP3 は先に退避）、尺・字幕を更新し直す。
- 自動化スクリプトで Step 09 を回す場合は、設定の `template_dir` と `folder_name` を同じフォルダにする（修正モード。Step 01 は自動スキップ）。
- 確認の再生は `aidiy_chrome_devtools`。MCP が繋がらないときは [`backend_server,backend_tools,MCP活用手順.md`](./backend_server,backend_tools,MCP活用手順.md) の HTTP 呼び出しを使う（`click` で `#modeBtn` を押すとショート／ロングが切り替わり、`#playBtn` で再生）。

## 注意点

- TTS の生成は 1 本数十秒かかる。44 本の再合成はバックグラウンドで実行し、途中で打ち切らない（打ち切ると一部だけ新しい音声になる）。
- 過去の失敗例: 「シュミルの姿をした騎獣」（原作にない説明）、「夜空のマント」（原作は「マント」）、「続いて駆けつけたヴィルフリート」（実際は最初から前線）。どれも聞き手に指摘されるまで気づけなかった。書いた説明は、原作の該当箇所で裏を取る。
- 公開済みの回を直す依頼が来たら、先に公開状況を確認する。
- 作品固有の呼称（例: 本好きでは養女先の家族を貴族の呼称で呼び、「実家」と言わない）は、作品側の `動画作り方.md` に書く。
