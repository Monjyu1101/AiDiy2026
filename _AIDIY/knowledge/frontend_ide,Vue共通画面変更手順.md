# Vue共通画面変更手順

> 文書: `frontend_ide,Vue共通画面変更手順.md` | 実装: `frontend_ide/src/App.vue`, `frontend_ide/src/ファイル閲覧/ファイル一覧.vue`, `frontend_ide/server.mjs`, `frontend_ide/host/src/vscode-html.ts`

## 機能フォルダと共通部品の所有者

`src/App.vue` は画面の組み合わせ、`src/main.js` は起動、`src/style.css` は共通レイアウトを担当します。Term・Code・Live・IDEはいずれも同じ Vue 3 基盤です。Code / Live の VS Code 版も同じ配布画面を読み込みます。

- `コード/`: コードパネル・通信・会話到着演出（Liveも共有）
- `ライブ/`: ライブパネル・通信
- `ターミナル/`: ターミナルパネル・コマンド補完・進捗表示・開始表示（Code / Liveも共有）
- `開発スペース/`: 開発スペース・宇宙キャンバス・描画・視点・経路記録
- `ファイル閲覧/`: 一覧・ビューア・フォルダページ・アイコン・ファイル操作・最新ファイル・走査警告
- `ファイル検索/`: AI検索・解析・履歴ダイアログ
- `下書き連携/`: 連携ダイアログ・受け渡し・連携先登録
- `共通表示/`: 状態バー・共通ダイアログ・接続状態・会話表示CSS

機能名・ファイル名は上記に揃え、`components` / `engines` / `transports` のような技術別の横断フォルダを再追加しません。既存の関数名・props・emit・保存キー・IPC/API・CSSクラスは互換契約として保ち、移動だけで変更しません。`host/src` のDiscord共有モジュール、公開起動入口、worker、配布URLも維持します。

移動時は通常のimportに加え、テストのreadFile・仮想require、型宣言の隣接、`viewer/server.mjs` の最新ファイル共有、`aidiy_term/terminal.mjs` のPowerShell補完情報を確認してください。日本語パスをファイルAPIへ渡すときはURLオブジェクトか `fileURLToPath()` を使い、URLの `.pathname` を直接ファイル名として使わないでください。`checks/component-paths.mjs` は実Vueマウントの論理名とファイルの対応を一か所にまとめます。

## このメモを使う場面

- Code / Live / IDEの共通画面やファイルエクスプローラーを変更するとき。
- 単独版とVS Code拡張の表示が一致しないとき。

## 変更先の選び方

Mac のアプリ名とメニューは `desktop.cjs` と `host/scripts/MacOS-Menu.cjs` で扱います。Term / Code / Live / IDE の単独起動・IDE子窓・ピン留め・ブラウザ窓は同じアプリメニューを使います。⌘Q / アプリメニューの「閉じる」は親窓の既存 close を通し、⌘W はフォーカス中の窓だけを閉じます。Mac のシステム Dock「終了」も IDE の利用中確認を通します。親との切断時の回収は `forcedQuit` で確認待ちにしません。編集キーは native role に任せ、Term の選択コピーやシェルへの Ctrl+C を main のキー処理で奪わないでください。`node --test checks/code-window-title.test.mjs host/checks/mac-menu.test.cjs` は各起動種別・終了確認と親子窓の寿命を確認します。

IDEのElectron版はプロジェクト表示行の名前のすぐ右側に並ぶ「＋ Term」「＋ Code」「＋ Live」から別ウィンドウを開き、Web版は画面内タブです。切り分けは `window.aidiyWindow` で行います。IPCにはアプリ種別だけを渡し、プロジェクト・モードはメインプロセスでIDEサーバーの状態から取得します。

画面は `frontend_ide/src/` の対応する日本語機能フォルダを変更します。Code / LiveをIDEへ配置するときも同じVue部品を使用します。ホストと通信プロトコルは `frontend_ide/host`、ファイルAPIとOffice表示資産は `frontend_ide/viewer` に統合しています。親ディレクトリ数を固定して共通設定やHermesを探さず、配置先から親方向へ探索してください。

IDEのオンライン利用では、`viewer/core-connection.mjs` がTermと同じ `PORT_TOOLS`（既定8095）の `GET /aidiy_code_agents/ping` を10秒ごとに確認し、`src/App.vue` も状態を10秒ごとに取得します。応答期限はTermと同じ1.5秒で、`status: "ok"` と `name: "aidiy_code_agents"` を確認します。Code / Live子パネルの接続先は `PORT_CORE` のままです。接続済みの定期確認中は `connected=true` / `connecting=false` を維持し、確認が失敗した時に接続表示を変えます。初回接続と切断後の再接続では `connecting=true` を表示します。tools停止でも利用開始時刻・作業・子窓を維持してください。単体検証は `node --test frontend_ide/viewer/checks/connection.test.mjs`、実画面検証はVue配布ファイル生成後の `node frontend_ide/scripts/check-connection.mjs`（Chromeを任意配置している場合は `CHROME_PATH` で指定）。模擬toolsを使い、10秒周期・定期確認中の表示維持・停止と復帰を確認し、日本時間の日時付き画像を `temp/connection-check/` へ保存します。

接続監視の負荷を確認する場合は `node --test frontend_ide/checks/monitoring.test.mjs frontend_ide/viewer/checks/connection.test.mjs` を使います。IDE・ピン留めビューアの状態取得、IDEのtools確認、Termのtools確認は10秒周期です。Codeは切断をWebSocketで検知し、再試行だけ10秒待ちます。初回確認・手動操作は即時のままです。Liveは既存のWebSocket通知を使い、定期HTTP確認を追加しません。Code / Liveの20秒ping、Termの15秒pingと端末ACK、音声処理の周期は変更しません。子窓の400ms監視とパネル寿命の250ms同期は終了連携用であり、接続疎通の周期と混同しないでください。

非表示のIDEはCanvas描画と毎フレームの配置取得を止め、再表示時は1つの描画ループだけを再開します。Web版のLiveを隠す時は、会話・下書き・接続を保持したまま `AudioCloud.setVisible(false)` で描画を停止し、StatusBarのclock-pulseも止めます。画面全体の非表示とパネルの非表示は別々に扱い、Canvasが0サイズの間も描かず、表示・サイズ復帰でRAFを1本だけ再開します。20秒の接続pingは変更しません。`checks/live-visibility.test.mjs` は実LivePanel・AudioCloud・StatusBarでこの寿命を検証します。接続バーは未接続の黒表示・画面非表示では50msの更新を止め、表示復帰時に現在時刻へ揃えます。Canvasのラベル幅は文字・フォントごとに保持し、階層再構築・サイズ変更・フォント読込時に破棄します。上記テストの呼出し回数は処理削減の確認用で、実機のCPU使用率を測定した値ではありません。画面の見た目・OSごとのCPU/GPU負荷は実画面検証で別途確認してください。

Codeのオフラインモデル候補は `same`（変更なし）を使い、選択時はHermesへ `--model` / `--provider` を付けずに呼び出します。オンラインの `auto`（AI判断）とは区別します。オフラインの選択値は `~/.aidiy/aidiy_code_model_offline.json` に保存します。

エクスプローラーは `ファイル一覧.vue` 一部品にまとめます。入力はtree/root/selected/current/startedAt/open、出力はupdate:open/select/clear/marksです。検索マークはイベントで宇宙へ伝え、エクスプローラーからCanvas内部を書き換えないでください。利用開始時刻が変わると起点検索を初期化します。

最終更新表示と自動追跡の候補は `src/ファイル閲覧/最新ファイル.js` の `latestFiles()` で選び、全階層の `_AIDIY`・`_data`・`_datas` 配下を除外します。`ファイル一覧.vue` の一覧計算と `viewer/server.mjs` の `/api/latest`（約1分周期）の両方で同じ関数を使ってください。`since` は前回の最新更新日時（ミリ秒）で、同じhh:mm:ssの秒頭まで含めて候補を返します。`createLatestUpdates()` は取得済みのパスと更新日時を覚え、前回の最後のファイル等の未変更分を取り除いて判定します。同じ秒の別ファイルを落とさず、同じパス自体がさらに更新された場合も拾います。

最終更新欄は初回に最新の1件を表示します。次回以降は新しい更新だけを古い順に並べ、更新なしなら前回の表示を維持します。3行程度の欄でスクロールでき、各行のクリックは通常の手動選択を使います。フィルター切替では基準を取り直し、切替直後の一覧だけで自動探索を開始しません。ツリー表示・バックアップ・Gitの対象条件へ最終更新の除外を転用しないでください。`node --test frontend_ide/viewer/checks/latest.test.mjs` でフィルターON / OFF、記録更新の無視、複数更新、秒境界の重複除外、同じパスの再更新、候補なしを確認します。

「閲覧軌跡」「AiDiy検索軌跡」と関連ファイルへの移動ボタンは、エクスプローラーの開閉に関係なく表示します。閉じている間はバーガーボタンの右隣へ横並びにし、狭い画面では折り返します。開閉だけでは選択した軌跡を変更しません。

軌跡ボタンは一覧の開閉も兼ね、直下にファイル一覧を表示します。AiDiy検索軌跡は検索結果の順、閲覧軌跡はengineのjournalからファイルだけを最近開いた順に表示します。journalはSpaceViewからpropsで渡し、一覧クリックも既存のselectExplorerを通します。閲覧一覧を開いている間は再訪による順序変更を止め、前・次で同じ2件を往復する状態を防ぎます。一覧外のクリックとEscで一覧だけを閉じます。`check-ai-search.mjs` はエクスプローラーを閉じたまま両一覧から移動し、再訪時の表示順も照合します。

ルート行も通常のフォルダと同じく、三角ボタンは開閉専用、フォルダ名ボタンは `select({type:'dir',path:''})`のルート移動に分けます。開閉ボタンを押しただけで宇宙を移動させないでください。ツリー行は `TransitionGroup` で高さと不透明度を240ms以内で変え、下の行も流れに沿って移動させます。手動開閉・ルート開閉・起点検索の展開変更を同じ演出にし、OSの設定によって規定の演出を省略しません。検証では途中の高さと連打後の最終状態も確認してください。

エクスプローラーからの移動は `SpaceView.selectExplorer()` を通し、航路全体の完了まで選んだ項目を一覧の `selected` / `current` に保持します。途中で通るフォルダは宇宙だけに反映します。`navigating` の間は一覧の自動 `reveal()`（カーソル変更・展開・スクロール）を止め、利用者の一覧操作は有効に保ちます。連続選択時は古い航路の完了で新しい選択を解除しないでください。`check-warp.mjs` で深いフォルダ・別枝ファイルへの移動中も一覧の状態とスクロールが変わらないことを確認します。

grepは検索ボタンでのみ実行し、入力中は前回の結果を保持します。検索開始時に一覧を先頭へ戻し、展開状態をリセットしてルートを閉じ、「検索中…」を表示します。完了時はルートと一致ファイルの全親フォルダだけを開き、0件ならルートだけ開きます。結果表示後もスクロール位置は先頭にします。再検索・解除・検索方式の切替後に古い応答が展開状態や検索マークを上書きしないことも確認してください。

縦表示（画面の高さが幅以上）では、上左にエクスプローラー、上右に軌跡ボタンとリスト、下半分にファイルビューアを配置します。エクスプローラーを閉じても軌跡は右側を維持します。両一覧の幅はそれぞれ画面幅の25%、高さは画面の中央までに制限します。ビューア表示中の宇宙の中心は、上半分で開いている一覧の間の中央です。ビューア非表示時は一覧の開閉に関係なく、画面全体の中央（横50%・縦50%）に固定します。

横表示では、左側にエクスプローラーと軌跡ボタン・リスト、右側に幅33vwのビューアを配置します。左の両一覧はそれぞれ画面幅の25%にし、宇宙の中心は開いている一覧の右端とビューアの左端の間に置きます。片側のパネルを閉じた分だけ空き領域を広げます。固定の33%・50%ではなく実際の一覧寸法から算出します。縦位置はヘッダーと下部操作ボタンを除いた作業領域の中央です。`SpaceView.layout()` がcenterX・centerYを返し、パンくずと `space.js` のmeasureCoverで共有します。ワープ到着後の配置もplannedPreviewで同じ中心を求め、移動中の投影中心固定を維持します。`check-warp.mjs` は横1280×800・縦768×1000・狭い縦390×844で各パネルの全8開閉パターンを確認し、中心がパネルに隠れないことと一覧の配置・高さを検証します。画面は `temp/space-layout-check/` に保存します。検証画像名の先頭には日本時間の撮影日時と連番を付け、名前順で新旧が分かるようにします。一覧・軌跡・ビューアの文字は共通の `--file-font-size:10px` で揃えます。MonacoもこのCSS変数を読み、コードと簡易テキスト表示のサイズを一致させます。HTML・SVG・Office文書の表示内容は元文書の書式を維持します。

自動視点は `src/開発スペース/自動周回.js`、操作との連携は `space.js` に置きます。軌道形状には遠点起算のケプラー方程式 `M = E + e sin(E)` を使います。遠点の速度は従来の1/3、近点は従来の1/6とし、速度差を圧縮して加速感を残します。接近中は実速度が増え続ける曲線を使い、近点直前で減速へ転じないようにします。物理公式どおりの一定面積速度にはせず、遠点では次の軌道への切替中だけ停止します。一周の軌道面は固定し、次の軌道面への変更は停止中に行います。船体の実座標から軌道を始め、1.1秒の位置固定旋回、軌道面へのロール合わせ、案内線の表示後、現在フォルダの中心を見続けて進みます。ファイル選択・ワープ・ドラッグでは彗星航行を中断し、画面非表示では描画ループも停止します。手動操作後は最後の操作から60秒経過して通常航行を再開し、それまでの待機中は低速回転を使います。ピンチとドラッグ終了時も停止期限を更新し、ファイル選択解除そのものでは期限を延長しません。`checks/auto-orbit.test.mjs` と `scripts/check-autodrive.mjs` で実座標・中心への視線・軌道の連続性と実画面での停止条件を確認します。

手動ドラッグの `orbitAround()` はワールド固定のY軸ではなく、現在のロールとパネルによる見回しを含む画面の上下・左右軸を使います。船体の実座標と視線を同じ角度だけ中心星の周囲で回し、中心の投影位置・周回距離を保ちます。`interpolateOrbit()` は最短回転で追従させ、真上・真下や上下反転の姿勢でもEuler角の個別補間による逆向きの動きを避けます。カメラのyawの符号だけを検査せず、手前側の星の投影位置がドラッグと同じ方向へ動くことを確認してください。`checks/warp-camera.test.mjs` は任意の姿勢・中心・パネルオフセットの投影を、`checks/manual-drag.test.mjs` は実エンジンのpointer入力からCanvas描画までと、クリック閾値・取消・ズーム・1分待機・2D中断を検証します。これらは実ブラウザーの画面撮影とは区別してください。

## 検証・配布

星・惑星・銀河の描画寸法はワールド寸法×透視倍率（焦点距離/奥行き）で決めます。最小表示サイズや選択時の上限で距離差を消さず、更新の強調も倍率だけで表現します。遠方は明るさを抑え、カメラ直前は滑らかに消します。銀河中心が背後でも手前に残る星は個別に描画・選択できます。`check-orbit.mjs` は実Canvasの描画呼出しで距離半分ならサイズ2倍となることと、銀河内の描画を確認します。

自動視点の最接近距離は遠点の18〜26%です。初回の軌道計算上の周期は48〜64秒で、実時間では全体の1/3速と近点の追加減速を適用します。星々の分布半径1500より内側まで入り込み、接近・通過・離脱が見える範囲を維持してください。全景の外から眺めるだけの距離に戻さず、`checks/auto-orbit.test.mjs` で `cameraPosition()` の原点からの距離を測り、分布の内側へ入ることを確認します。`dist` は描画上の注視点までの距離なので、実座標の代わりには使いません。

宇宙の中央にはルートを含む全階層でワームホールを表示し、ラベルは現在フォルダ名にします。子階層ではダブルクリックで1つ上へ戻り、ルートではワープしません。ラベルとツールチップに親フォルダ名を混ぜないでください。

宇宙表示の右下「視点移動」は利用開始ごとにONです。`開発スペース.vue` から `setAutoSpin()` を呼び、エンジンの通知でトグルとSpaceキー操作を同期します。OFFは自動移動を止め、手動操作は有効のままです。明示的なONは60秒の待機を解除します。ファイル選択中は通常航行を再開せず、低速回転を維持します。選択解除や階層移動で利用者のON/OFFを上書きしないでください。

起動時は現在の最終更新ファイルを一度表示します。自動表示中を示す `followedPath` と、最後に到着した `lastFollowedPath` は分け、手動操作やOFFからONへの切替で到着済みの記録を消さないでください。同じパスの通知や再開では再予約せず、移動先のフォルダで彗星軌道へ戻ります。別の最終更新ファイルは引き続き追跡し、手動待機・OFF中の未到着予約も保持します。追跡は直列に実行し、移動中の更新は最新の予約で上書きして、古い対象を開かないようにします。追跡開始時には一覧を再走査し、直前に新規作成されたファイルも取り込みます。進行中の走査が更新通知より前なら、両モードともfresh=1で1回だけ再検証します。通知後のfreshness走査は共有し、古い一覧に残る削除ファイルを開いたり、新規ファイル・同一ファイルの更新を捨てたりしないでください。モード切替中も受信済みの追跡先は保留へ戻し、古い航行を無効化して新モードで再検証します。未到着の更新と古いコールバックの寿命は分けます。プレビューは最後の操作から5分で閉じます。FileViewerのactivity通知（クリック・キー・ホイール・Monacoスクロール・文書内操作）と別ファイルの表示で5分を数え直します。自動消去からの彗星軌道再開では同じ対象を再予約せず、新しい更新を待ちます。`node frontend_ide/scripts/check-autodrive.mjs` で一時プロジェクトと実ブラウザの仮想時計を使ってこれらの遷移を検証し、`temp/autodrive-check/<日時>_<連番>_autodrive-*.png` を撮影します。

複数更新は `requestFollow()` に更新順のパス配列で渡します。自動探索が動ける状態になったら再走査し、先行ファイルはカメラ移動やプレビューを行わず、親フォルダの経路とファイルの閲覧軌跡だけを保存します。最後のファイルだけへ実際に移動します。待機中にさらに更新が来た場合も先行分の経路を保持し、移動先は最後の新しい対象にします。`check-autodrive.mjs` は同じ秒の3件から前回最後のファイルを除外すること、先の2件が表示されないこと、別フォルダの経路保存、更新なしでの一覧保持、6件の小さいスクロール、縦横画面も確認します。任意配置のChrome / Edgeは `CHROME_PATH` で指定できます。

ワープの旋回計算は `src/開発スペース/ワープ視点.js` にあります。`cameraPosition()` で船体の実座標を復元し、位置を固定して1.1秒で目的地へ旋回した後、正面へ直進します。通常のカメラ補間も `interpolateCamera()` で実座標を補間し、注視点と角度の同時補間による横滑りを防ぎます。ドラッグだけは例外で、`orbitAround()` により中心星を軸に回り込みます。星までの距離を保って船体と視線を一緒に回し、ドラッグ後の実位置・向きを次の航行の出発地点にします。彗星飛行は楕円上の位置と速度を維持し、視線だけは常に現在フォルダの中心へ向けます。再開直後は位置を固定して約1.1秒で中心へ向き直します。計算した軌道線は `auto-orbit.js` の航行と同じ位置計算から385点を採り、新しい軌道の確定時だけ生成します。船は基準軌道点から軌道面の上向き法線へ、基準半径×tan(5度)だけ上げた実座標を飛びます。基準半径をcos(5度)倍して中心からの船体距離を従来どおり保ちます。初回と次軌道の計算では、この高さを含む船体位置が切替前と一致するよう軌道の基底を回転します。`space.js` の `drawOrbitPath()` は基準軌道の座標を原点中心に0.90倍して船の内側へ寄せ、天体と同じ投影で淡い青の線だけを描き、背後の点や軌道の末尾と先頭を結びません。手動操作・ワープ・プレビュー・OFFで航行用の軌道を破棄します。表示用の線は約1.2秒のsmoothstepと軽いぼかしで消し、新しい線も約1.2秒で浮かび上がらせます。遠点では `hiding`（1.2秒の消去）→ `planning`（暗い状態で再計算）→ `aligning`（3.6秒のロール回転）→ `revealing`（1.2秒の表示）→ `flying` の順で進めます。自動探索ボタン上の状態表示は、軌道切替の全段階で「軌道計算と姿勢制御中」、航行開始後は「探索軌道航行中」に切り替えます。回転は2.7秒で目標角度を回転量の15%だけ越え、残り0.9秒で一度だけ戻して水平に整えます。切替中は船体を遠点に固定し、視線も中心に保ちます。`orbitLevelRoll()` は軌道面の法線から水平になる最短ロール角を求めます。`cam.roll` を天体・遠景の投影へ同じように反映し、軌道面の上側が機体の上になるようロールを合わせます。案内線だけの見かけの回転は行いません。`orbitVisibility` とフェーズを使い、機体回転中には新しい線を出しません。星系が変わった場合は旧線を持ち越しません。進行方向の接線を向くと星系を背にして黒い画面になるため、接近・通過・離脱と次の軌道への切替でも中心注視を保ってください。手動回転の軸は彗星飛行中は現在フォルダの中心、接近後は目的の星です。全体表示は外側の観測位置へ向いて前進し、そこで中心へ向き直ります。フォルダ到着時も船首方向を引き継ぎます。

親へ戻るワープでは、現在フォルダ名を付けた中央の星（`world.gate`）だけ接近距離を画面幅から求めます。中心球だけでなく外周リングの線幅込み直径（`2.07 × R`）が接近時に約25%へ収まる距離を `framingDistance()` で計算し、`cockpitLook()` による視線の偏りも補正します。既に近い時は滑らかに離れて同じ距離へ合わせます。この帰還だけCanvasの拡大を2倍にし、外周の最大幅を約50%にします。淡い背景光の透明な外縁はリングより広いため、中心球・明るいリング・背景光の寸法を区別してください。子フォルダ銀河への接近距離・2.6倍のワープ、同階層ファイルの接近、通常描画のファイル星のサイズは変えません。`checks/warp-framing.test.mjs` は横1280×800・縦768×1000・狭幅390×844・超横長2560×720と視線偏り、実Canvasのarc外周と中心球、至近距離からの調整、接近中の取消・モード変更・選び直し・破棄、他天体の互換性を確認します。テストの描画呼出し計測は実ブラウザ撮影の代わりにはなりません。

手動選択・閲覧軌跡・AiDiy検索軌跡・最終更新の自動追跡は `goTo()` を共有します。別フォルダへは共通の親を経由し、1階層ずつ旋回・前進・ワープします。目的フォルダ内のファイル接近には常に `transition:false` を使い、Canvasの拡縮・暗転・ぼかし・放射状のワープ光跡を再生しません。接近済みの同一ファイルの手動再選択は移動を省略します。ビューアの閉じる操作・5分での自動消去は、現在の階層・船体位置・船首方向を保ちます。閉じる操作で移動中なら、その場で航行を取り消します。連続選択でも古い航路が後からプレビューを開かないよう世代番号で無効化します。未選択状態の再走査を「閉じる」操作として扱わないでください。自動追跡が自分の再走査で取り消されてしまいます。

パネル開閉では船体を動かさず、`cockpitLook()` で操縦席から見回す回転を加えます。透視投影面の中心は画面中央に固定し、空き領域へ移すのは船首の見える位置です。平行移動による全景の横滑りや、ビューアが開いた瞬間の中心ジャンプを避けます。`SpaceView.layout({preview})` が返す空き領域の中央とパンくず配置は維持します。航行中は `warpProjection` に視線配置を固定し、フォルダ間のワープでは不可視の間だけ到着時の配置へ切り替えます。

`checks/warp-camera.test.mjs` は実座標・正面への直進・航行の位置固定旋回・手動周回・視線回転の距離/角度保存を確認します。`check-warp.mjs` は実際のエクスプローラー行クリック、同階層の演出なしの接近、深いフォルダ・別枝・選び直し・閉じた時の現在地保持・左右ドラッグ・縦横の配置を検証します。`check-autodrive.mjs` は同階層の自動追跡にもワープ演出がないこと、5分消去、更新追従、予約変更を確認します。ワープ光跡の長さは従来比1.8倍を維持します。

右下の「高速ワープ」は利用開始時OFFです。ONでは `goTo()` による別フォルダのファイル選択（エクスプローラー・閲覧軌跡・AiDiy検索軌跡）を、目的フォルダまで1回の `travelTo()` にまとめます。中間階層を表示せず、到着後に `destinationFile` を新しいworldから引いてプレビューを開きます。到着後のファイル追尾や追加接近を行わず、フォルダ全景を維持してください。同階層の一覧選択は高速ワープのON/OFFに関係なく旋回・接近します。最終更新の自動追跡も高速ワープ設定に従い、フォルダ自体の選択は通常の階層順ワープです。OFFへ戻すと通常の階層順ワープになります。`check-warp.mjs` で既定OFF、深い階層・別枝・親フォルダへの1回の移動、同階層の旋回・直進と接近済みファイルの再選択、選び直しによる取消と到着後の視点固定を確認します。

## AiDiy検索の変更・検証

AiDiy検索を選んでいる間はファイルツリー・ルート行・最終更新行を隠し、検索入力・履歴・結果にパネル全体を使います。起点検索・grep検索へ戻すとツリーを再表示し、検索結果や軌跡は保持します。

`frontend_ide/ファイル機能/ai-search.mjs` が `/api/ai-search` のPOST（依頼）とGET（結果確認）を受け持ちます。共通設定の `PORT_TOOLS` を使って `aidiy_code_agents/config` と `/run` を呼び、Codeの既存セッションは再利用しません。IDEの利用状態とHost / Origin検証を通し、ブラウザから接続先・任意の結果パスを指定できない構造に保ってください。

依頼ごとにID・秒形式の保存先・5分の期限を発行します。保存先はプロジェクト内のtempを実パスで確認し、`.request` の排他作成で重複を避けます。結果のrequestId・query一致、相対パス、実ファイル、リンク先の境界、件数・サイズ、routeとfilesの一致を検証してから返します。タイムアウト後も同じ依頼のGETで再確認できます。新しい依頼を始めても古い出力が新しい結果へ混入しないことを維持してください。

`AI検索パネル.vue` が2秒間隔の確認と世代管理を行い、完了した結果だけを `ファイル一覧.vue` へ渡します。`FileExplorer` は検索理由・親フォルダの関連件数・成功結果の保存・軌跡切替を担当し、`SpaceView` を通じて `space.js` のmarksとrouteへ通知します。`ai-route.js` が各階層の中央から直下の関連フォルダ・ファイルへの描画順を作ります。閲覧航路のvoyages/journalは変更しません。AI結果の到着でファイル選択やgoToを実行しないでください。

結果JSONの `title` はユーザーの要求からAIに生成してもらう検索タイトルです。目安30文字以内、最大80文字で依頼し、空白・型・長さを検証して履歴へ保存します。履歴一覧・削除確認・選択結果・AiDiy検索軌跡リスト上部はこのタイトルを表示し、元の `query` も保持して再検索とツールチップに使います。旧結果のtitle欠落はqueryを1行80文字以内にした表示へ補完し、過去の履歴を読み込むためだけにAIを実行しません。`checks/ai-search.test.mjs` で保存・再起動・不正タイトル・旧形式を、`check-ai-search.mjs` でタイトルによる履歴選択と軌跡の復元を確認します。検証画像は日時と連番付きで `temp/ai-search-check/` に保存します。サーバー側を変更した時はIDEサーバーを再起動して新しい依頼形式を反映します。

`checks/ai-search.test.mjs` で期限・遅れた結果・不正結果・リンク・セッション・API・航路を検証し、`scripts/check-ai-search.mjs` で結果到着時にワープしないこと、マーク、切替、順番に閲覧、再検索時の古い結果抑制を撮影します。`scripts/check-ai-search-live.mjs` は実エージェントを使うため明示実行専用です。

検索履歴は `ファイル機能/ai-search-history.mjs` がプロジェクト内 `_AIDIY/aidiy_ide/file_searches/<依頼ID>.json` に保存します。保存先の作成・境界確認・旧版 `.aidiy/ai-search/` からの移行は `ファイル機能/ide-data.mjs` の `ideDataFolder` に共通化しています。`/api/ai-search/history` のGETで一覧、`?id=`付きGETで理由と軌跡、DELETEで確認済みの1件を削除します。既存のHost / Origin・利用開始チェックを共用します。保存先の各段階で実パス境界を検証し、原子的な一時ファイル→renameで保存します。削除はIDだけの削除済み記録に置換し、元のtempから復活させません。初回一覧時に旧版の依頼付き結果を取り込みます。履歴読込ではパス形式・理由・routeの整合を検証し、現在は存在しない対象も検索当時の情報として残します。

`AISearchPanel` は履歴の取得・選択・削除確認を担当します。初期復元は現在の検索方式・閲覧軌跡を変更せず、明示選択だけがAiDiy検索軌跡に切り替えます。`FileExplorer.acceptAI` は結果を受け取り、位置移動なしでmarksとrouteを更新します。新規検索開始・部品破棄では古い履歴応答を無効化してください。履歴の取得失敗と空一覧を区別し、既存のマークを消さず再読込を案内します。テストでは別プロジェクト分離、再起動、旧結果の移行、削除後の再取込防止、異なるマークへの切替、削除取消・確定、履歴切替で視点が動かないことを確認します。

## 更新履歴の比較を変更するとき

`ファイル機能/file-history.mjs` は `/api/file-history?path=...` で保存版一覧、`version=...` 付きで旧版・現在の全文を返します。プロジェクトとファイルの祖先にある `backup/YYYYMMDD/HHMMSS[.all][.コメント]` のみを調べ、各保存版の同じ相対パスを照合します。全体のバックアップ内容を再帰走査せず、最大5000保存版で打ち切りを明示します。IDはバックアップ相対パスのSHA-256ですが、取得時にも候補一覧との一致と実パス境界を再検証してください。外部リンク・保存版外のリンクを拒否し、利用状態と既存のHost / Origin検証を通します。比較は各1MBまで、UTF-8 / Shift_JISを読み、切り詰めません。

`ファイルビューア.vue` はテキスト表示時に履歴を確認し、存在する場合だけボタンを出します。`App.vue` が `ファイル履歴ダイアログ.vue` の対象を保持するため、ビューアの5分消去や別ファイルの選択でも比較対象が変わりません。MonacoのDiffEditorを読み取り専用・左右固定・空白差分を無視しない設定で使い、未変更行の位置合わせとスクロール同期を任せます。切り替え時の古い通信を中断し、閉じる際はエディターと両モデルを破棄します。更新履歴は最後の操作から5分で自動消去します。再読み込み・履歴選択・クリック・キー操作・ホイール・ドラッグ・左右Monacoのスクロールで時間を数え直し、単なるマウス移動では延長しません。閉じる際はタイマーとスクロール購読も解除します。

Monacoの共通読込は `src/ファイル閲覧/コード表示.js` に集約します。並行読込と成功結果だけを共有し、読込失敗を永続的にキャッシュしないでください。失敗後の再試行ではAMDローダーの失敗状態をresetし、配信URLにも読込時の識別子を付け、セットアップ前の古いモジュールを使わないようにします。`/monaco/` の資産は再検証を要求するキャッシュ設定で配信します。比較画面の「再試行」は画面の再読み込みなしで再取得し、依存不足が続く時はセットアップ確認を案内します。通常ビューアは読込失敗時も簡易コード表示を維持します。

APIとパス境界は `checks/file-history.test.mjs`、共通読込の失敗と復旧は `checks/monaco.test.mjs`、実画面は `node frontend_ide/scripts/check-file-history.mjs` で確認します。ブラウザー検証は専用の一時プロジェクト・ブラウザーを使い、ローダー・比較モジュールの読込を意図的に止めて「再試行」で復旧することも確認します。任意配置のChrome / Edgeは `CHROME_PATH` で指定してください。エラー・横・縦の画像を `temp/file-history-check/` に日時・連番付きで保存します。実利用中のブラウザーのビューポート寸法を固定しないでください。API変更後は対象IDEサーバーを再起動します。

## ファイル解析の保存・表示を変更するとき

`ファイルビューア.vue` の「AiDiy分析」ボタンから、`App.vue` が保持する `ファイル解析ダイアログ.vue` を開きます。対象のプロジェクトとファイルを固定し、ビューアの5分消去でもダイアログを消さない構成です。初回指示は画像類とソース類を分け、保存済み指示があれば必ず優先します。Markdown本文はHTMLを無効化し、外部画像を読み込みません。

`ファイル機能/file-analysis.mjs` は `/api/file-analysis` のGET（復元・結果確認）、PUT（指示保存）、POST（解析依頼）を担当します。既存の `runSearchAgent` を使い、対象と指示を含む依頼ID付きJSONをtempへ出力させます。ブラウザを閉じてもサーバー側が最大5分間確認し、最新の成功結果を `_AIDIY/aidiy_ide/file_analyses/<相対パスのSHA256>.json` に保存します（`ideDataFolder` を共用し、旧版 `.aidiy/file-analysis/` は初回に移します）。前回指示・本文・日時・対象の更新日時とサイズを保持し、失敗時に成功結果を消さないでください。保存先の実パス境界を確認し、ファイル別の書込キューと一時ファイルからのrenameで指示保存・結果到着の競合を防ぎます。

`checks/file-analysis.test.mjs` は再起動・プロジェクト分離・更新判定・失敗時保持・遅延結果・保存競合・パス境界・APIを確認します。`scripts/check-file-analysis.mjs` は模擬エージェントによる実画面の指示復元・結果表示・ソース/画像の指示切替・縦横配置を確認します。配信更新時はVue bundleの再生成とIDEサーバーの再起動が必要です。

## Code / Live の演出を変更するとき

表示寸法・配色・キーフレームは `frontend_ide/src/共通表示/会話表示.css`、Vueへの送受信連携は `src/コード/会話到着演出.js`、文字送りと枠飛行は `host/src/arrival-effect.ts` にあります。旧画面を参考にするときも `frontend_vscode` を実行時依存にしないでください。

入力は送信時の入力欄位置を予約し、同じ本文が戻ったユーザー発言へ560msで飛ばして白い光とぼかしから表示します。Codeの入力履歴は右側70%以内、回答は左側90%以内です。回答は中央の高さ30vhの黒地・白枠へ文字送りし、全文表示後3秒保持して履歴へ移します。Code / Liveとも後続回答は順番待ちにし、入力通知や後続回答で3秒待機を打ち切りません。Codeで同じ状態を再受信しても再演出せず、同じ発言の本文が更新された場合だけ最新の全文表示から数え直します。保存済み会話の読込では再演出しません。会話切替・切断・破棄・画面非表示では順番待ちを含む飛行、文字送り、タイマーを解除します。`check-chat-effects.mjs` は連続する回答それぞれの文字送り完了から飛行開始までを実ブラウザの時計で計測します。

初期画面は3行を12秒周期で順に表示し、入力を始めたら全行表示で止めます。入力欄を空にしても再開せず、新しい会話で再開します。Codeの処理中は入力欄上下の1px線を、シアンと白が4.2秒周期で逆方向に通過します。進捗はSTX/ETX/CANで文字送りを開始・終了し、状態通知で同じ文字を二重追加しないようにします。

画像は `host/media` と `host/aidiy_live/media` の元画像を `scripts/build.mjs` から共通・両拡張の配布先へコピーします。画像追加時は `server.mjs` の配信許可一覧も更新してください。検証はREADMEの `check-chat-effects.mjs` と `check-electron.mjs` を使用します。

## 起動・終了

Code / Live / IDEの接続バーは `状態バー.vue` のclockPulseを有効にし、Webの `_TopBar.vue` と同じ `round(255 * abs(sin(2πt / 9)))` を実時刻から50msごとに計算します。明滅は4.10秒周期で、接続時はシアン、Codeの自動接続OFF・IDEのオフライン時は赤、未接続時は黒です。CSSのopacityアニメーションを重ねず、背景色だけを変えます。

ポートは自動割り当てです。aidiy_code / aidiy_live / aidiy_ideからVue版を起動します。旧aidiy_devの互換起動はありません。cleanupのプロセス照合は起動スクリプトの完全一致とアプリ種別で行い、IDE群の解除が成功してから共通Vue生成物を削除します。

Electronの初期配置は `デスクトップ/window-layout.cjs` で画面のworkAreaから計算します。IDEは余白付きの大きな画面、Code / Liveは左右に配置し、IDE連携時は親の境界を基準にずらし、Code / Liveの上端と高さは揃えます。連携窓のタイトルは「AiDiy IDE / Code」「AiDiy IDE / Live」で、単独版のタイトルと区別します。既存窓の再表示では最小化を解除して前面に出すだけにします。単独Code / Liveは種別ごとのsingle-instance lock、IDEは同じプロジェクトごとのlockを使い、Termは複数起動を許可します。IDEのCode子窓は複数起動でき、それぞれ独立したサーバー・会話を持ちます。Live子窓だけ親セッションと初期化中のPromiseで重複を防ぎ、起動中は＋Liveを隠します。子窓の状態はメインプロセスから取得し、閉じたときにボタンを戻します。`checks/window-layout.test.mjs` と `scripts/check-windows.mjs` で画面外にはみ出さない配置・連打・前面復帰・終了連携を確認します。

IDEのプロジェクト識別は `デスクトップ/project-profile.cjs` に集約します。`launch.mjs` が `--project` / 位置引数 / 起動フォルダを先に解決し、実パスを `AIDIY_DEVELOPMENT_PROJECT` でElectronへ渡します。`desktop.cjs` はロック取得前に実パスのSHA-256を使って `userData` と `sessionData` をプロジェクト別に分けます。同名の別フォルダは共有せず、相対表記・リンクは同じ実体に揃えます。Windowsでは大小文字・区切り・長いパス表記を統一し、ファイルIDも加えて大小文字を区別する別実体を混同しません。ファイルAPIへ渡す実パスの大小文字は変えません。サーバーは従来どおり自動ポート・個別所有を維持し、他プロジェクトの終了・再起動に巻き込まないでください。旧プロファイルから認証・保存情報をコピーしません。`node --test frontend_ide/checks/project-instance.test.mjs` は模擬Electronと実ローカルHTTPで、重複時の前面化、別プロジェクトの子窓・キャッシュ・接続・ポート・終了の分離、起動引数、同時起動を確認します。実ElectronでのOSロックと前面化は別途確認が必要です。

WindowsでElectronのGUI本体をspawnするときは `windowsHide: false` にします。`true` では初回の画面表示が隠され、URLだけ出て再実行するまで窓が見えない場合があります。バックグラウンドの補助プロセスとは区別し、初回起動時の可視状態を `scripts/check-single-instance.mjs` でも確認します。

最前面ピンは全Electron共通の `デスクトップ/最前面ピン.cjs` で管理します。単独起動はOFF、IDEから作る子窓だけONです。操作は「ー □ 📌 Ｘ」で、VR中は本体と所属子窓をON固定し、解除後は各窓の直前の選択へ戻します。OFFでも親より手前に残るOS親子関係は作らず、寿命は `record.owner` で管理します。全アプリを同じ `floating` 層に揃え、選択されたON窓だけを手前にします。詳細とWindows実機でのZ順確認手順は [共通の基本方針](./共通,Electronウィンドウ基本方針.md#タイトル操作と最前面ピン) を参照してください。以前の所有関係・上位レベルによる回避策を戻さず、Windowsで異常が出る場合はOFF/ON・別アプリ間の選択順を実窓で再検証してください。

## BrowserパネルとMCP接続

Electronで選択HTMLをBrowserへ渡すときの例外は `viewer/登録HTMLルート.mjs` に集約します。作業ルートの `frontend_web/public/` 配下だけを対象に、`src/router/*.ts` の `createStaticAliasRoute` と、登録Vue画面の `frameSrc`（`baseUrl` にHTMLの相対パスを足す形式） を使うiframeを照合します。登録に一致したHTMLだけ、`vite.config.ts` の `PORT_WEB`（既定8090）の対応ルートを開きます。ソースを実行して判定しません。未登録HTML・他フォルダ・コメントアウトされた登録は通常のfile URLです。Webサーバー停止中は理由を表示し、file表示へ暗黙に戻しません。ルート側の認証は通常どおり適用します。判定の検証は `node --test frontend_ide/checks/registered-html.test.mjs`、Electronでの通常HTMLとの切り替えは `node frontend_ide/scripts/check-browser.mjs` で確認します。

Browserの画面は `src/ブラウザ/ブラウザパネル.vue`、WebContentsViewは `デスクトップ/ブラウザ.cjs`、CDP中継は `デスクトップ/ブラウザCDP.cjs` が所有します。通常画面・VRの「＋ Browser」とHTML/HTMの「ブラウザ」ボタンから起動します。既存のコード・表示プレビューは維持します。Web起動では新しいタブを開くため、クリック内で空タブを予約してからtools接続とプレビューURLを確認します。

BrowserはIDEの `active && mode==='online' && connected` を起動前・非同期準備後に照合します。tools切断時は既存ページを保持したまま非表示にして操作を停止し、再接続時に戻します。接続判定の取得元は既存のIDE接続状態です。Electronのファイル選択では `previewFile()` で実パスとプロジェクト境界を確認し、`pathToFileURL()` による絶対パスのfile URLをBrowserへ渡します。アドレス欄・履歴・MCPのURLもfile URLです。日本語・空白・`#`・`%`を含む名前を手動連結せず、相対画像・CSS・リンクはファイル位置を基準に読み込みます。Browserのfile要求とMCPの遷移先はプロジェクト内の実ファイルに限定します。通常Web起動と既存の「表示」プレビューは `/api/preview` の専用配信URLを引き続き使います。外部ページはpreloadなし・Nodeなし・sandbox有効の別WebContentsで、IDEのAPIオリジンへの要求は拒否します。

MCPは `session="aidiy_ide"`、複数IDEでは `aidiy_ide-2` 以降です。`backend_tools/temp/_ide_browser_sessions/` にIDEがloopbackポート・ランダムトークン・PIDの登録を置き、`tools_proc/ide_browser_session.py` が既存のChromeレジストリへ接続専用セッションとして組み込みます。トークンやポートを画面へ公開せず、パネルにセッション名だけを表示します。IDE終了で登録と中継を解除します。MCPの `close_session` / `delete_session` はBrowserだけを閉じ、IDEプロセスをkillしません。未起動のセッションへ別Chromeを自動起動しません。

Electron全体のremote-debugging-portは使わず、専用ページのCDPだけを中継します。HTTP・WebSocketはloopbackとトークンで限定し、WebページからのOrigin付き要求を拒否します。IDE本体やCode/TermのTargetへアクセスするBrowser/Targetドメインは転送しません。`new_tab` だけは専用アダプターから所有IDEへ新しいBrowserパネルを要求します。Web起動の通常タブは登録しません。

確認は `node --test frontend_ide/checks/browser*.test.mjs` と `backend_tools/.venv/Scripts/python.exe -m unittest discover -s backend_tools/tests -p test_ide_browser_session.py`。実画面確認は共通Vueの配布物生成と変更済みtoolsの起動後、`node frontend_ide/scripts/check-browser.mjs` を実行します。Googleへの実接続、HTML/HTMと相対CSS・リンク、履歴、MCPからの一覧・クリック・入力・移動・撮影・新規パネル・終了、各ディスプレイのVR起動配置、利用終了連携を確認し、`temp/browser-check/` に画像と結果を保存します。テスト用プロジェクトとElectronプロファイルを使い、有料AIや音声は起動しません。

## VRボタンの表示と切り替え

Windowsのフレームレス窓には細いOS外枠が残るため、`全画面横断.cjs` はVR中だけディスプレイ全体の外接矩形より各辺2 DIP外側まで窓を広げます。上端の灰色ラインを画面外へ出し、DPIの丸めも吸収します。メニュー位置は拡張後の実際の窓座標から計算し、VR解除では保存した位置・寸法へ復帰します。通常窓の端ドラッグによるリサイズを維持するため、`thickFrame:false` は設定しません。表示設定変更のたびに画面配置から計算し直し、余白を累積させません。

拡大率の違う画面への復帰では、最初の座標設定が旧DPIで換算されることがあります。大きな寸法差は端数補正へ加算せず、移動先で保存寸法を再適用します。125%などの端数DPIでは、1 DIP小さく指定しても実寸が変わらない場合があります。端数の補正は元の目標値から毎回作り直さず、直前の指定値へ残差を加えて実寸を再確認します。最大4回で制限し、同じ指定値への再訪は打ち切り、一致不能なら最も近かった指定値へ戻します。

環境変数 `AIDIY_ALL_EDGE_ONLY=1` を設定して `node frontend_ide/scripts/check-all-displays.mjs` を実行すると、実Electronの画面外への枠配置・VRの5往復・通常窓の復帰位置と寸法の完全一致を検証し、上端画像と `temp/all-displays-check/edge-result.json` を保存します。Electronが`host/node_modules`にある環境では、`ELECTRON_PATH`に`frontend_ide/host/node_modules/electron/dist/electron.exe`の絶対パスを指定します。検証窓はGPU負荷を避けるためソフトウェア描画、窓座標とDPIは実OSです。確認後は環境変数を解除してください。手動相当の再確認ではIDEを再起動してから復帰ボタンとF11の両方を試し、移行前後のキャプチャ寸法・原点も比較します。実施記録は[IDE操作編](./セルフテスト,aidiy_ide,操作編.md)を参照してください。

`App.vue` の `canEnterAll` は、Electron版・利用開始済み・3D表示の3条件で判定します。起動画面、2D表示、`--browser` のWeb版ではVRボタンを表示しません。切り替え処理の入口と準備完了後でも同じ条件を確認し、VRから戻す操作は許可します。

表示条件だけを確認する場合は、環境変数 `AIDIY_ALL_BUTTONS_ONLY=1` を設定して `node frontend_ide/scripts/check-all-displays.mjs` を実行し、実行後に変数を解除します。この確認は隔離Electronをソフトウェア描画で動かし、起動画面・3D・2Dの撮影と、Electronのpreloadを持たないWeb画面の非表示を確認します。VRの画面横断・復帰サイズの検証は、変数を設定しない通常の同スクリプトで別途行います。

VRへの移行ではExplorerと軌跡を順に自動ピン留めします。ファイルビューアーとソース比較は自動で別窓にせず、中心星の右128pxから、最大幅640px・高さ720pxのIDE内パネルに表示します。表示領域より大きい場合は縮めます。ファイル選択のたびにIDE内の閲覧を差し替え、選択やパネル開閉で宇宙の中心を補正しません。明示的な📌でだけ別窓化し、既にピン留めした同じファイルはその窓へフォーカスします。

Explorerと軌跡のVR位置は `デスクトップ/VRパネル配置.cjs` がIDE本体ごとにメモリー内で保持します。VR終了時、親窓を通常サイズへ戻す前に両別窓のDIP座標を記憶します。次回はピン留め・VR展開後、Web側の元表示の消去描画を待ってから、Explorer→軌跡の順に各650msで前回位置へ移動し、その間は共通の四方向マーカーと「VR空間へ移行中…」を表示します。初回・同位置では移動演出を省略します。移動先を示す操作のため、装飾のアニメーション抑制とは独立して移動とマーカーを表示します。サイズは保存せず現在の寸法を保ち、画面構成変更時は作業領域へ収めます。移行中断時は通過点を保存せず、タイマーとマーカーを解除します。永続設定には書き込まず、IDE終了で忘れます。検証は `node --test frontend_ide/checks/vr-panel-placement.test.mjs frontend_ide/checks/all-displays.test.mjs frontend_ide/checks/code-drag.test.mjs`、実窓は `AIDIY_ALL_PANEL_POSITION_ONLY=1` を指定して `node frontend_ide/scripts/check-all-displays.mjs` を実行します。実窓を移動してVRを3回往復し、位置復元・移動中のマーカー・寸法維持を確認、`temp/all-displays-check/panel-position-result.json` と画像へ保存します。

VR中は再オープン用の入口が隠れるため、Explorerの別窓タイトルの×と内部の閉じる☰、軌跡バーの×を非表示にします。VR解除では両方の別窓を閉じ、本体でも非表示にします。DOM・閲覧履歴・検索状態は保持し、通常画面の「☰」「軌跡」から再表示できます。`ファイル一覧.vue` でVR状態の解除を監視し、既存のdismiss処理でDOMを回収してから閉じます。ビューアーなど他の別窓はそのまま維持します。

VR中の復帰・起動メニューは全ディスプレイの作業領域の右上に置き、マウスオーバーまたはキーボードフォーカスで表示します。復帰マークの下のTermはその画面の下部、Codeは右上、Liveは左上へ開きます。Liveは接続利用中かつ未起動の場合だけ表示し、終了後はメニューへ入る時の状態取得でも再表示します。`全画面横断.cjs` の `toolbars` は画面IDとIDE内の割合座標を返し、`openApp` は任意座標ではなく画面IDだけを渡します。main側でVR状態・実在画面・所有元を照合し、起動準備中の切断やVR解除も窓生成時に再確認します。通常起動の配置と窓番号は維持し、VRの重ね位置だけ画面別に数えます。

環境変数 `AIDIY_ALL_LAUNCHERS_ONLY=1` で同スクリプトを実行すると、接続中の各実ディスプレイでホバー表示・3種の起動位置・Liveボタンの非表示/復帰・各画面からのVR解除を検証し、メニュー画像を保存します。IDE画面・IPC・別窓・表示演出は実Electronで、接続状態と子窓の本文サーバーをfixtureに替えます。Code CLI・PTY・マイク・有料APIの検証は含みません。

この閲覧動作は環境変数 `AIDIY_ALL_VIEWER_ONLY=1` を設定して同じスクリプトで確認できます。実ElectronのVR中で、移行前の比較DOM保持・中心右の配置・連続選択で窓が増えないこと・手動ピン留め・VR解除後の閲覧保持と、Explorer・軌跡の閉じる操作の非表示、解除時の別窓終了・通常画面からの再表示・VR再移行後の再終了を検証し、`temp/all-displays-check/` に画像を保存します。窓の復帰寸法は通常の全体検証で確認し、この限定検証の合格で代替しません。

## Code / Live の操作・遅延応答を確認するとき

`node frontend_ide/scripts/check-host.mjs` は模擬ホストを実ブラウザから操作し、`nn-audit-*.png` を保存します。履歴の新しい順・更新日時・削除の取消と確定、モデルの自動／既定／直接指定、オフライン固定候補、検証回数の送信・オンライン復帰を確認します。自動接続ONで未接続のバーは黒、接続済みはシアン、手動OFFは赤です。実行モードのHermesフォールバックと、自動接続スイッチの表示判定を混同しないでください。

Liveは接続時のスピーカーON、モデル変更時の音声設定引継ぎ、接続途中のフォルダ変更、モデル保存待ちの停止を確認します。遅れて届いたAPI・保存結果は、開始時のgenerationと一致するときだけ適用してください。モデル変更の再接続では履歴とスピーカーを保持してマイクをOFF、新しい会話ではモデル・音声・スピーカー・マイク設定を引き継ぎます。

`host` 側の既存画面テストだけではVue部品の操作漏れを検出できません。通信基盤のテストに加え、上記Vue画面検証と `check-chat-effects.mjs` を使い分けてください。

Liveの詳細比較では `host/aidiy_live/src/audio.ts`・`protocol.ts`・`visualizer.ts` の共有だけで同等と判断せず、Vue側の制御も確認します。初回接続では開始画面を消し、新しい会話では開始画面へ戻します。モデル再接続中は「再接続中」、マイクON中は「会話中」を表示します。再送時は前の送信エラーを消し、入力・音声認識の再編集でも会話末尾へ追従させます。

`check-host.mjs` は実際の共通AudioWorkletと疑似ホスト入力を使い、PCM送信、マイクONの新規会話への引継ぎ、準備待ちの中断、ホストからのマイク一時停止、音声だけの変更、保存・接続失敗も確認します。実マイクや外部AIには送信しません。`check-chat-effects.mjs` は旧Live CSSとのボタン・入力欄の描画値比較も行います。

Code / Live / IDEの単独起動時は `host/scripts/window-opening.cjs` の750ms拡大演出を使います。その間は `desktop-opening` クラスでVue画面を隠して開始文字送りを止め、演出後にフェード表示します。Electron検証ではこの一時的な演出専用ウィンドウをアプリ本体として数えず、利用者の起動済み画面と分離した一時プロファイルを使ってください。

Code / Live / IDEの単独Electron起動では `launch.mjs` がサーバーを所有するNodeプロセスを分離し、IPCで画面表示完了を受け取ってから呼出元を終了します。Electron自身のIPCはサーバー所有プロセスとの接続を維持し、画面終了でサーバーも閉じます。`--foreground` / `--wait`、ブラウザ版、`--no-open` / `--serve` は分離しません。`scripts/check-launcher.mjs code` / `scripts/check-launcher.mjs live` / `scripts/check-launcher.mjs ide` で、呼出元終了後の継続、再実行での既存窓再利用、×でのプロセス・ポート解放、起動失敗の通知を確認できます。

Electron本体の起動は `デスクトップ/desktop-process.mjs` に集約します。stdinを無効にし、stdout / stderrはpipeで読み取ります。背景起動時にはその出力を起動元へ転送せず、`--foreground` / `--wait` の待機起動時だけログを表示します。WindowsではElectronもdetachedでコンソールから切り離します。GUIの初回表示まで隠す `windowsHide:true` は使わず、IPC接続を維持して表示完了・終了を管理してください。起動元端末に空行や制御文字が出る場合の検証は `node --test frontend_ide/checks/desktop-process.test.mjs` です。実子プロセスが継続出力していても背景起動では漏れず、待機起動では出力でき、IPC終了も維持することを確認します。Windowsの実端末では放置中のカーソル位置と、IDE終了後に現象が止まるかも確認してください。

## HTML / SVG の相対参照を確認するとき

`ファイルビューア.vue` のHTML/SVG表示は `/api/preview` が返す別ポートのURLをiframeで開きます。`viewer/preview.mjs` はプロジェクト内のフォルダ構造をURLに保持し、同じフォルダ・親フォルダの画像、CSS、モジュールを通常のブラウザと同じ相対URL解決で配信します。SVGを `/api/raw` のimgタグへ戻すとSVG内部の外部画像が読めなくなるため、文書として表示してください。SVGは表示を既定とし、コードへの切替も提供します。

プレビューのiframeと文書CSPには `allow-same-origin` を付け、外部SVGのuse参照などを可能にします。IDE自身とは別ポートで隔離し、元のプロジェクト外や設定・鍵ファイルの配信拒否を維持します。ディレクトリのindex.htmlは末尾スラッシュ付きURLへ誘導し、画像の基準位置をずらさないでください。ファイル切替・破棄では古いプレビューAPIの応答を無効化します。

文書と資産の `Referrer-Policy` は `same-origin` とし、外部画像などへtokenとプロジェクト内パスを送らないでください。同一プレビュー内ではRefererを維持し、`/…` 始まりの資産をページの `public` 基準で解決します。参照元の公開元も、このプレビューのローカルまたは確認済み転送先に限定します。

Codespacesの転送先からAPIを開いた場合は、既存の `forwardedOrigin()` でプレビュー用ポートのHTTPS URLを返します。IDEとプレビューは別の転送公開元を維持し、IDEと同一公開元へHTMLを中継しないでください。Hostを書き換える転送では既知のOrigin / Refererも判定に使います。ローカルから開いた場合はループバックURLを返します。初回起動でtokenを含まないローカルURLを出力し、Codespacesのポート検出へ通知します。自動転送されない場合はPortsからそのプレビューポートをPrivateのまま転送し、必要なら転送先を別タブで一度開いて認証してから再読込します。ポートをPublicへ変更する必要はありません。

`node --test frontend_ide/viewer/checks/preview.test.mjs` と `node frontend_ide/scripts/check-preview.mjs` で配信・ブラウザ表示を確認します。前者は転送HostとプロキシがHostを書き換えた場合、ローカル利用、token・パス・別サイトの拒否も確認します。後者は別ポートの模擬外部画像にRefererが送られず、ルート相対画像は読めることも確認します。実Codespacesのポート転送・認証確認はローカルのHost模擬テストとは別に実施してください。実ファイルは `check-preview.mjs --project <ルート> --html <相対パス> --svg <相対パス>` で読み取り専用に検証し、`nn-preview-*.png` に撮影します。配信側を変更した際は、画面再読み込みだけでなくIDEを終了して再起動してください。

## Term（ターミナル）の変更・検証

Termの最小高さは `デスクトップ/window-layout.cjs` の `windowMinimumSize()` で180pxにし、単独窓とIDE子窓で共用します。最小幅360px、初期の幅2/3・高さ1/2、Code / Live / IDE / ビューアの最小寸法は変えません。作業領域がさらに小さい時は初期配置の寸法を上限にします。`ターミナルパネル.vue` はパネル自身をsize containerにし、高さ240px以下では入力前・表示クリア後の起動案内を畳んで端末へ高さを渡します。通常の14px文字なら180pxの窓で約4行が目安です。FitAddonとResizeObserverの対象は余白のない内側の `term-viewport` にし、外側のpaddingを行数へ数えて最下行が欠けることを防ぎます。ステータスは1行、短い画面のエラーは1行分のスクロールに収めます。Web版にも同じパネル内判定を使い、ブラウザー自体の最小サイズは変更しません。

`checks/window-layout.test.mjs` は小さい作業領域・単独/IDE子窓の最小寸法と従来の初期配置、`checks/term-size.test.mjs` は実Vue処理と実FitAddonによる1〜5行への縮小・復元・入力・表示クリア・タブ往復・再起動、`checks/terminal.test.mjs` は小さい行数のサーバー検証と実PTYのリサイズを確認します。これらは実描画の検証ではありません。Electronの `checks/term-desktop-probe.cjs` では360×180への縮小・入力・クリア・操作ボタン・最下行・元の大きさへの復元も撮影して確認してください。

TermのElectron窓は作業領域の幅2/3・高さ1/2で画面下中央に開き、次の窓を28pxずつ右上へ配置します。親IDEの矩形には合わせず、親と同じディスプレイの作業領域を使います。画面端まで進んだら基点へ戻します。単独Termはsingle-instance lockを使わず、起動ごとの一時Chromiumプロファイルを終了時に片付けます。`デスクトップ/term-window-slot.cjs` は127.0.0.1の18440〜18567を操作受付のない排他用ポートとして使い、単独プロセスとIDE子窓で配置番号を共有します。番号は窓終了で解放し、プロセス異常終了でもOSが解放します。Code / Live / IDEの既存窓再利用は維持します。

プロジェクトバーの「tools接続確認」はCodeの `auto-connect` トグルを共用します。既定ON、WebSocketの `tools-check` で切り替え、`tools` 応答の `enabled` / `online` で画面を同期します。OFFは疎通の定期実行を止め、シアン表示を解除して赤いバーにします。ONへ戻すと即時に疎通確認を再開します。シェルの再起動は行わず、端末の再起動でも同じサーバー内の選択を維持します。確認中にOFFへ変わった場合の古い応答は世代番号で無視してください。

Termの入力前はCodeと同じ `開始表示.vue` とアイコンを使い、実PTYの入力欄を下部へ小さく配置します。xtermの `onKey` とDOMの `input` / `paste` で初回操作を検出し、同じ端末要素を拡張・再fitします。シェルや端末を作り直さず、初回の文字・日本語IME・貼り付けを失わないようにしてください。シェルが自動送信する制御応答を入力開始と誤認しないよう、`onData` だけで判定しません。再起動時は初期表示へ戻し、タブ切替では表示状態を保持します。

CLI補完候補は `ターミナルパネル.vue` でカーソル直後へ薄いグレーの文字として重ねます。xtermのセル寸法・表示中の行位置から配置し、右端で折り返します。端末バッファには候補を書き込まず、Tab確定時だけPSReadLineが入力へ追加します。描画・スクロール・サイズ変更時に位置を更新し、別画面や終了時には表示しません。候補を常設の下部パネルへ戻さず、下部はキー操作の案内だけにします。

タイトルバーはCodeと同じ `状態バー.vue`、プロジェクトバーは共通の `component-toolbar` を使い、フォルダ名と完全パスのツールチップを表示します。シェルの状態は下部に分け、シアンバーはtoolsの疎通だけで決めます。`aidiy_term/terminal.mjs` は `ファイル機能/ai-search.mjs` の接続先解決（`PORT_TOOLS`、既定8095）を共用し、`aidiy_code_agents/ping` を10秒ごと・タイムアウト1.5秒で確認します。tools停止でシェルを終了させず、シェルの自然終了後もtoolsの状態通知は維持します。

Windowsの `aidiy_term/powershell-init.ps1` は、その端末セッションだけにPSReadLineのTabハンドラーを設定します。入力が対象CLI名だけでカーソルが末尾なら、`scripts/cli_bat` と同じ権限省略オプションを追加し、実行はEnterに任せます。対象は `codex` / `claude` / `copilot` / `agy` / `grok` / `aidiy_hermes` で、Claudeは既存バッチに合わせて `--chrome` も追加します。モデルは変更しません。それ以外は元のTab処理へ戻します。`src/ターミナル/コマンド補完.js` の `cliCompletions` を候補表示とシェル補完で共用し、履歴予測の斜体表示と確定済み引数を区別します。ユーザーのプロファイルは変更しません。検証では同名の模擬関数で引数を確認し、実CLIを起動しないでください。

`aidiy_term` は `aidiy_term/launch.mjs` → 共通 `launch.mjs` の `--app term` で起動します。IDEのElectron版は「＋ Term」で独立した子窓を複数開き、Web版は `ターミナルパネル.vue` をTermタブに保持します。利用モードはオンライン・オフライン両方で有効です。setup / start / cleanup の表示と処理は Term → Code → Live → IDE の順に揃えます。`aidiy_term/_setup.py` はランチャー、`_start.py` は環境確認・独立起動・プロセス照合、`_cleanup.py` は停止とランチャー解除を担当し、依存物は共通UIにまとめます。

`aidiy_term/terminal.mjs` はランダムパス付きのローカルサーバー、`viewer/panels.mjs` は同一公開元への中継です。Host / Origin・IDE利用状態を検証し、シェル・開始フォルダはサーバー側で決めます。入力サイズと端末寸法を制限し、描画完了のACKで出力を制御します。パネル初期化中・終了中のセッション切替では、破棄中のサーバーも完了まで待ちます。

`aidiy_term/terminal-process.mjs` は `aidiy_term/terminal-worker.mjs` を端末ごとに起動します。ネイティブのPTYと補助スレッドをそのプロセスに閉じ込め、ElectronからもNodeモードで動かします。Windowsの終了はそのworkerのプロセスツリーを停止します。WebSocket切断・ページ再読込・窓終了・IDE終了で停止し、タブ非表示だけでは切断しません。自然終了では末尾のIPC出力を送り終えてからworkerを終了します。ConPTYをIDEメインプロセスで直接保持すると補助スレッドの寿命がIDEに影響するため、この境界を維持してください。

- `node --test frontend_ide/checks/terminal.test.mjs`: 不正接続・寸法・フロー制御、実PTYの日本語、開始フォルダ、リサイズ、Ctrl+C、シェル配下の子プロセスの終了。
- `node frontend_ide/scripts/check-term.mjs`: 専用ブラウザで日本語入力、タブ保持、狭い画面、exit後の再起動、利用終了。WindowsのChrome / Edgeで実行します。
- `node frontend_ide/scripts/check-term-desktop.mjs`: 専用Electronプロファイルで日本語入力、複数窓、個別終了、IDEとの終了連携。
- `node frontend_ide/scripts/check-launcher.mjs term`: プロンプト復帰、同一プロジェクトの複数起動、幅2/3・高さ1/2、右上への配置、個別終了、待機指定、サーバー終了。

画面確認画像は `temp/term-check/` に日本時間の日時付きで保存します。画面の変更を実行中の配信へ反映する場合は共通Vueの配布ファイルを再生成し、サーバー側を変えた場合は対象アプリを再起動します。PTYの依存は `node-pty`、画面は `@xterm/xterm` / `@xterm/addon-fit`。第三者ライセンスを `scripts/build.mjs` の通知生成へ含めます。新規環境の `npm ci` でPTYのビルドが必要になるOSでは、そのOSのC++ビルド環境も用意してください。


## 状態確認・最終更新・下書き連携の境界

- `App.vue` と `閲覧ウィンドウ.vue` は `src/共通表示/接続状態.js` で利用状態の応答を検証します。HTTP失敗・タイムアウト・不完全なJSONを `active:false` に置き換えないでください。Appの状態取得と下書き連携の確認には開始時のrevision・セッションを照合し、終了や再開後の遅延応答を捨てます。Electron側の `デスクトップ/desktop-session.cjs` も同じ方針で、子窓監視失敗では破棄せず、終了確認時の不明は確認が必要な作業中として扱います。
- `ファイル一覧.vue` の最終更新通知は、一覧の鮮度更新と自動追跡を分けます。`space.js` の手動latest/未知パス移動は `fresh=1` で再走査し、新しい手動選択・clear・フィルター切替・破棄があれば中断します。進行中の走査を共有した結果が古い場合だけもう一度確認します。自動探索のON/OFFで手動クリックを無効にしないでください。
- `ファイルビューア.vue` は `file-reference.js` でgrepの行・列・検索語を現在の内容と照合します。Monacoと簡易表示の双方に位置を伝え、CRLF/CR/LFとUTF-16列を扱います。本文変更や削除で不一致なら再検索の案内にします。
- `下書き連携ダイアログ.vue` は初回表示時に候補を取得し、有効な `frontmostTargetId` を初期選択します。閉じて再表示した時も、その時点の最前面を取り直します。連携先行の「最前面を再選択」は候補を取り直し、`frontmostTargetId` を選び直します。通常の候補更新では有効な手動選択を保持し、再選択だけで下書きを追加しません。有効な候補が1件なら最前面情報の有無によらず名前を表示して選択します。最小化・非表示などで最前面情報がない場合は「最前面は未確認」と明示し、最前面と断定しません。初回表示・再選択時に複数候補の最前面を特定できなければ未選択として案内し、一覧での明示選択を残します。ゼロ件で自動起動・自動送信はしません。`コードパネル.vue` / `ライブパネル.vue` の `draftTarget()` / `insertDraft()` は `src/下書き連携/下書き受け渡し.js` を共有し、今の下書きに追記します。Codeは合計200,000文字、Liveは20,000文字、選択本文は80,000文字までで、超過は切り詰めず拒否します。Codeの新規・履歴切替など会話変更操作では、要求を送る前に連携先を同期的に無効化します。途中の旧会話stateやHTTP成功だけで復帰させず、要求先の会話stateまたは変更前の確定拒否を待ちます。VS CodeはrequestId付きのconversationChangeResultと会話stateを照合し、実行中・モデル変更中・消えた履歴の拒否でも安全に復帰します。マルチルートの新規だけは、ホストが成功応答で確認した別の作業フォルダへ移れます。履歴選択は要求した会話ID・元のプロジェクトを維持します。応答喪失や500は適用済みか判断できないので、旧下書きのまま連携を停止し再読み込みを案内します。`checks/code-transition-handoff.test.mjs` は実テンプレートのクリックとHTTP/SSE・VS Code経路を検証します。
- Webは `draft-target-registry.js` のマウント固有IDと会話contextIdを再照合します。ピン留めはAppが実際に開いたWindow参照だけを登録し、同じ公開元・IDEセッション・プロジェクトと送信元の生存を確認します。BroadcastChannelやlocalStorageに本文を流さないでください。
- Electronは `デスクトップ/draft-router.cjs` が所有IDE、セッション、窓ID、会話contextId、プロジェクトを検証し、限定したpreloadのIPCへ渡します。受信結果のACKまで待ち、期限切れ・閉じた窓・再配送を扱います。表示名やCodeの配置番号だけで相手を決めないでください。最前面候補はホストのウィンドウfocus順を記録し、現在の所有IDE・セッション・登録に一致する表示中のCode / Liveだけから選びます。IDE・ビューア・ダイアログへのフォーカスや登録情報の更新では順番を変えず、閉鎖・最小化・非表示の窓は最前面候補から除外します。Webは最後に表示したCode / Live種別をマウント固有IDへ変換し、Term・ダイアログを候補にせず、利用再開時に記録を消します。
- LiveのWebパネルは隠してもマウントを保持し、`visible` でマイク取得待ちを無効化し音声入出力を止めます。会話・下書き・スピーカーの選択を残し、再表示でマイクを自動再開しません。

`viewer/file-scan.mjs` の走査は同じサーバー内でフィルターと走査範囲（通常/grep）ごとに1秒だけ共有し、同時実行は1本です。grepのbackup除外は走査前に行い、対象外の保存版で候補・フォルダ・深さ・時間上限を消費しないようにします。通常のgalaxy/latestとは進行中の要求・キャッシュを分離し、通常一覧のbackup表示条件は維持します。明示操作の `fresh=1` は完了済みキャッシュを使わず、進行中の同じ走査は共有します。既定上限は30,000ファイル（backupフィルターは100,000）、10,000フォルダ、200,000項目、128階層、10秒。待機者の個別中断、全待機者の中断、利用終了・切替、サーバー終了を伝播し、中断した走査はキャッシュに残しません。常時watcherは使いません。

`/api/galaxy` は従来のtreeに走査件数・時間・打切り理由を加え、`/api/latest` は同じ情報をscanにも持ちます。`/api/grep` はpathsを維持し、matchesにpath/line/column/length/snippet/mtime/sizeを追加します。grepは1ファイル1MB、合計256MB、候補30,000ファイル、一致1,000件、30秒、最大8並列読み取りです。読み取り中にファイルが変わったらスキップします。UIはtruncatedとtruncationReasonを捨てないでください。

検証では `frontend_ide/checks/monitoring.test.mjs`、`desktop-session.test.mjs`、`draft-handoff.test.mjs`、`draft-target-registry.test.mjs`、`workflow-components.test.mjs`、`explorer-navigation.test.mjs`、`viewer/checks/file-scan.test.mjs`、`grep.test.mjs` を実行します。実画面ではCode複数/Live1つ、対象窓の終了、連携確認中の利用終了、下書きが入力済みの場合、ピン留めとタブ切替、Monaco読込失敗時の簡易表示を確認してください。配布への反映は共通VueとCode/Live bundleの再生成が必要です。

## 3D / 2D の表示部品を変更するとき

- `App.vue` は利用セッションごとの `viewMode` を持ち、開始時は3Dにします。プロジェクト名の直後に3D / 2D、右側にTerm / Code / Liveを配置します。表示モードを `SpaceView` やCode / Live / Termのkeyに含めないでください。
- `開発スペース.vue` は共通の走査結果・選択・エクスプローラー・読み取り専用ビューアを結びます。`宇宙キャンバス.vue` は既存の `createSpace()` を包む薄いライフサイクル部品です。3Dエンジン内の既存の走査・選択・移動管理を共用し、二重取得や別セッションを作りません。
- 3Dは現在フォルダの直下ファイルを惑星、直下サブフォルダを銀河にし、各銀河の全子孫ファイルを1ファイル＝1星で描きます。深いフォルダによる集約・間引きは行いません。空フォルダは個別のファイル星を持たず、直下に来た時は空の銀河として移動できます。星の座標は銀河内の相対パスで区別し、色・容量によるサイズ・更新や検索の強調もファイル単位で保ちます。クリック・検索・履歴・最終更新は実ファイルの親へ移動します。銀河の更新件数は走査・マーク変更時に集計し、毎フレームの描画やhoverで元ツリーを再走査しないでください。新規星の誕生時刻と描画時刻はどちらも実時刻を使い、通常サイズの4倍から6秒で元へ戻します。`checks/star-depth.test.mjs` で集約前の座標・色・サイズ・瞬き、同名ファイルの区別、12,000件の深いファイルの個別描画・当たり判定、検索・航路・追加削除・6秒の新規強調を確認します。非表示時の描画停止・ラベル幅キャッシュ・通信周期の負荷改善は維持してください。
- `setViewMode('2d')` はRAFとワープの待機・アニメーションを中断し、3Dのキー・ポインター操作を止めます。2Dの最終更新追跡は、共有の自動探索ON/OFF・手動操作後の猶予・手動プレビュー保護を守るイベント駆動です。探索枠の回転条件も3Dと共通にし、更新候補がない待機中も自動探索が可能なら回します。手動猶予の終了時だけ1回起きて枠を復帰し、更新予約があれば追跡します。OFF・モード変更・フィルター・セッション・非表示・破棄で古い処理を無効にし、常時のRAF・追加ポーリングは作りません。`goTo` / `ascend` / ブラウザ履歴は2D中だけ直接階層を切り替えます。3Dへ戻す時は同じworldと現在の選択を保ち、描画予約を必ず1本だけ再開してください。ページ非表示からの復帰でも2DのRAFを再開しません。
- `フォルダページ.vue` は初めて2Dを選んだ時に生成し、その後は部品の記憶を保持します。非表示中は全ツリーの集計や項目DOMを作りません。`folder-pages.js` が直下項目と更新・検索一致数を集計し、ページごとのスクロール・選択行を記憶します。本文や認証情報は保存しません。新しい走査・検索マークで、ユーザーが矢印キーで移したカーソルを開いているファイルへ巻き戻さないでください。
- 2Dページだけは本文18px・行高1.5、補足16px（行内のサイズ・日時・件数は行高1.125）を使い、共通の `--file-font-size` やCode / Liveの文字設定は変えません。固定insetの `.folder-pages` をsize containerにし、幅520px以下では補足を次行へ、高さ360px以下では見出しと補足欄をコンパクトにします。一覧の最小高さ96pxとページ外側のスクロールを残し、縦表示のプレビュー中に一覧が潰れないようにします。日時・長い名前は省略せず、動作確認では狭幅・長いパンくず・一覧外参照の案内を組み合わせてください。
- 2Dページ切替は旧ページを上に残し、下の移動先を右に傾いた斜線（上端が右の `/`）に合わせて露出させる方式です。進む時は斜線が右→左、戻る時は同じ傾きのまま左→右へ動き、同じ時間・ease-in曲線でゆっくり始めて徐々に加速します。旧ページの `clip-path: polygon()` とSVG線の上下端を `--page-turn-slant`（幅20%・上限160px）で揃え、傾き分だけ画面外まで動かして開始・終了時の四隅に旧ページや移動先の欠片を残さないでください。SVG線は `preserveAspectRatio="none"` と `vector-effect="non-scaling-stroke"` で高さに追従し、線幅2pxを保ちます。`folderPageTurnPlan()` で共通の親への戻りと目的の枝への進行を求め、各経由ページの実データを順に重ねます。1階層でも複数階層でも移動全体を約800msに揃え、実際に表示する枚数で総時間を等分します（1枚800ms、2枚400ms、3枚約267ms、4枚200ms、5枚160ms）。深い経路は共通の親と最終目的地を落とさず最大5枚へまとめ、省略した階層数も表示します。共有の現在地・選択はすぐに最終目的地へ反映し、途中の枚数は視覚効果として扱います。初回表示・モード復帰では再生せず、OSの設定を理由にページ繰りを止めません。同じ階層の更新は下方向の更新演出を使います。実操作する移動先のスクロール領域は階層パス、旧ページ・経由ページ・斜線はめくりごとの一意なIDでkey付けします。表示専用ページはスクロール位置・選択行を保持し、`inert` / `aria-hidden` を付け、optionのIDを複製しません。旧ページのanimationend/cancelが新しいページを止めないよう、イベントの対象・アニメーション名・一意IDを照合してください。完了時は表示用シートだけを外し、操作側のDOMを維持します。途中の一覧クリックや決定キーはまず演出だけを終え、下に隠れた別の項目へ誤操作しないようにします。ホイール・タッチ移動・スクロールバー操作や一覧更新でも演出を解除し、親ボタン・パンくず・外部からの新しい移動は最後の目的地を優先します。ページ演出にタイマーや描画ループは追加せず、CSSのend/cancelと入力・更新通知で後片付けします。背景は `frontend_web/src/assets/menu-common.css` の既存クリーム色（#faf7f2 / #f5f1e8 / #f0ebe0、文字#5a4a3a）を2D専用CSS変数で使い、3Dと共通ビューアの色は変えません。軌跡バーの高さはResizeObserverとresize時だけ測り、狭い画面でパンくずへ重なることを防ぎます。フォルダ移動後は項目リストへフォーカスを戻し、共有ビューアのEscも維持します。矢印/Home/End/PageUp/PageDown、ホイール、タッチ移動、スクロールバー等のポインター入力はactivityから共通エンジンへ手動操作を通知します。scroll自体は位置の保存だけとし、復元・scrollIntoView・検索更新によるプログラムスクロールで手動待機を延長しないでください。

`checks/folder-pages.test.mjs` はページ集計、親・子・ルート、スクロール・カーソル、キー操作、更新・削除、部品再生成の抑止、共通パネル維持、配置構造を検証します。Vueの実マウントでは移動先・旧ページの重なり、スクロール保持、表示専用シートの操作抑止、同方向の古い完了通知、最大5枚の経由内容、演出終了後のDOM維持も確認します。CSSの切り抜きと斜線の上下端・方向・同期条件、狭幅/横長/低いページでの四隅、加速曲線はソースの数値計算で検証し、実際の中間フレーム・描画は実ブラウザーで別途確認してください。`checks/space-mode.test.mjs` は実エンジンの3D→2D→3D、カメラ・選択・検索位置、履歴、フィルター、遅延応答、連打、非表示時RAF、ワープ中断、破棄を検証します。既存のworkflow / explorer / orbitテストも併せて実行してください。実画面の横長・縦長・狭幅、Code / Live下書き保持、grep位置とピン留めは、自動テストとは別に確認します。

`checks/navigation-parity.test.mjs` はVue部品を実際にマウントし、FileExplorerのイベントからSpaceView・SpaceCanvas・実エンジンを通って、FolderPagesとFileViewerへ選択が届くことを確認します。エクスプローラー、AI結果/軌跡、閲覧軌跡、grep位置、最終更新の手動/自動、新しい深いフォルダ、古い応答、フィルター切替、削除、戻る/進むを確認します。Canvas・API応答・Monacoは試験用で、実ブラウザーや実AIは使いません。更新時系列では同じ60秒のファイル監視、通知後の2D即時開始/3D次フレーム開始、自動プレビューの次の更新、モード切替、手動保護と探索枠を比較します。接続監視の10秒周期と混同しないでください。

フィルター対象外のgrep参照は、親フォルダが一覧にあれば2Dではそのページへ移動してからプレビューを開きます。親まで一覧にない場合はページを捏造せず、元のページとプレビューを保ち、`unlistedParent` でフィルターOFF・一覧更新・再選択を案内します。AI/履歴の欠落パスもフィルターを自動で変更せず案内してください。一覧を取得済みならエラーを画面全体のspace-loadingで覆わず、閉じられる非遮断のspace-noticeにし、現在ページ・プレビュー・更新操作を維持します。3Dの既存の一覧外参照動作は維持します。

3Dのパネル境界は `.space-view:not(.mode-2d)` 内のエクスプローラー・ファイルビューア・軌跡バー・閲覧/検索軌跡一覧にだけ、静かな白い外側の影を付けます。2Dのクリーム色と他画面のパネルへは適用せず、影にアニメーションを付けないでください。

3Dの自動航行のランダム軌道は、90度の制限を設けず視線軸の全周から選び、最短方向（左右0〜180度）へ姿勢を合わせます。初回は現在位置から自然に開始し、以後はフォルダがあれば通過指定とランダムを交互に選びます。`step()` に現在の `world.galaxies` を渡し、通過指定では銀河内部の点・進入側を選び、実船体がその点を通る近点距離と軌道面を計算します。面内ドリフトは通過指定の周だけ止めます。遠点の実位置と中心注視は固定し、必要な場合だけ見下ろし角を5度より下げて反対側の小さな銀河にも届くようにします。細長い楕円もケプラー方程式の有界反復で解きます。2.7秒で目標を変化量の15%だけ越え、残り0.9秒で一度戻します。各区間は角速度を線形に加速・減速する二次補間を使い、3度未満の区間は一定速度です。案内線の0.90倍表示、消去・再計算・回転・再表示、手動中断、2D中の停止を維持します。`checks/auto-orbit.test.mjs` は全方向の回転・速度変化・一つのフォルダの交互通過を実座標で確認し、`AIDIY_ORBIT_ROUTES_ONLY=1` を指定した `scripts/check-autodrive.mjs` は実描画で4周の交互選択と銀河内通過を撮影します（既存のプレビュー待機時間の検証とは独立）。


3Dの待機中は、自動探索ONなら現在の中心星の周りを180秒で1周します。ファイル選択中だけでなく、起動時の最終更新への到着後や、手動操作で通常航行を中断した後も同じ低速回転を使います。閲覧を閉じても直前の中心星を引き継ぎ、フォルダ表示ではその星系の中心を使います。通常巡回の60秒の手動待機には従わず、ドラッグ・ワープ・導入飛行・姿勢合わせ・軌道航行中は重ねません。2D・非表示・自動探索OFFでは止めます。既存の `orbitAround()` でカメラと目標を同じ角度だけ回し、中心星との距離と投影位置を維持します。回転だけで閲覧の待機時間を延長しません。

`checks/space-mode.test.mjs` と `checks/manual-drag.test.mjs` で未選択時の一周、閲覧終了時の中心維持、操作・表示停止、60秒後の航行再開を確認します。実描画は `scripts/check-autodrive.mjs` に `AIDIY_SELECTED_ORBIT_ONLY=1` または `AIDIY_IDLE_ORBIT_ONLY=1` を指定します。前者は起動後の閲覧と一周、後者は閲覧終了後の待機回転と通常航行への復帰を仮想時計で検証・撮影します。軌道計算・ロール合わせ中は既存の航行処理が視点を管理し、待機回転で上書きしません。

### 自動探索ボタン上の航行状態

自動探索ONの間だけ、ボタンのすぐ上へ現在の状態を表示します。航行状況は枠・背景・影を付けない文字だけにします。2Dでは文字色だけを変えます。`space-flight-controls` は `z-index:5` とし、航行状況・自動探索・高速ワープをビューア（30）とエクスプローラー（40）の背面へ置きます。パネルが重なった部分は隠れ、航行状況は `pointer-events:none` で操作を妨げません。`宇宙描画.js` が実際の処理から `explorationStatus` を通知し、`開発スペース.vue` が表示します。追加のタイマーやポーリングは使わず、状態が変わった時だけ通知します。

| 表示 | その時の動き |
|---|---|
| 出航準備中 | 起動時の読み込み・導入飛行を進めます。 |
| 航路確認中 | 更新先のファイルと経路を確認します。 |
| 目的地へワープ中 | 別の星系へワープします。 |
| 目的地へ接近中 | 同じ星系の目的地へ旋回・前進します。 |
| 手動操縦中 | ドラッグ・ピンチなどの操作を優先します。 |

## 閲覧・検索軌跡の明細と分岐

閲覧の `voyages[階層パス]` は `route-records.js` の `{ from, to }` 明細を追加順に保存します。点は従来と同じ `g:フォルダパス` / `f:ファイルパス` で識別し、現在点は `voyageCurrent[階層パス]` に分けます。最初の明細の `from: null` は、出発点のない始点レコードを明示したものです。閲覧では従来どおり最初の点だけを描き、中心からの線は追加しません。検索は従来の各階層の入口（中心）を最初の `from` にして一本道を描きます。

既存点へ戻ったら現在点だけを更新し、明細の追加・並べ替え・既存の出発点の書き換えはしません。A→B の後に A を再訪して C へ進む場合は、末尾に A→C を追加します。経路の同一性は向きを区別しません。A→BとB→Aは同じ経路として1明細にまとめ、最初に記録した明細のfrom/toの向きと追加順を保持します。`sameRoute()` / `uniqueRouteRecords()` を閲覧の追加・旧データ復元・検索の明細生成で共有します。旧明細に始点行がなくてもfrom側を既存点として認識し、逆向きの再訪は現在点だけを更新します。点マーカーはfrom/toの両端を対象に重複除外し、逆辺の整理後にfrom側にだけ残る現在点も強調します。各線は明細自身の両端から描き、配列の前後を結び直しません。途中のファイルが削除・非表示になった場合も、その点を飛び越す線を捏造しません。古い点への再訪も判定できるよう、従来の40点での航路切り捨ては行いません。閲覧日時一覧 `journal` は航路とは別用途なので、従来の最近順・最大80件を維持します。

保存はバージョン2の `{ version, voyages, voyageCurrent, journal }` です。旧文字列配列は読み込み時に初訪問の明細へ変換し、再訪は現在点の更新として処理します。旧形式では最後の参照点を現在点にし、新形式では保存された現在点を優先します。壊れた明細だけを除外し、使える他の明細は残します。AI検索結果は従来の `route` パス配列APIを互換維持し、同時に `routeRecords` の `from` / `to` 明細を共通の `searchRouteRecords()` で生成して返却・履歴保存します。点IDは閲覧と同じ `f:ルート相対ファイルパス` で、最初の `from` は `null`、後続は直前の `to` です。入力結果の1MiB上限は維持し、派生明細のパス重複を含む保存履歴だけは読み書き共通の3MiB上限にします。入力で受理した長い500件の結果が保存後に読込不可にならないことと、上限超過の書込が既存履歴を壊さないことを確認してください。検索結果の `files.path` / `route` 自体へ `f:` を付けないでください。旧履歴の読み込み時も検証済みの `route` から明細を補完します。外部結果内の明細は信用せず、順序と全ファイルの一意性を検証した `route` を正として生成します。

FileExplorerは検索明細をrouteイベントの `records` として送り、SpaceView経由でengineが複製して保持します。旧UIの `paths` だけの通知は同じ生成関数で補完し、検索順と矛盾する明細を採用しません。描画境界の `aiRouteRecords()` は保持した論理明細のファイルIDを各表示階層へ投影し、深いファイルをその階層の親フォルダ位置へ写します。この描画座標・親フォルダの点と、保存する `f:パス` の論理明細を混同しないでください。検索の互換用`route`配列とファイル巡回順は維持しますが、投影後の軌跡明細にも向きを区別しない同一路判定を適用し、逆向きの線を重ねて描きません。例えばsrc→other→srcはsrcとotherを結ぶ線1本とし、最後の点の強調は重複除外後の最後の明細ではなく元の検索順のsrcに残します。検索の順序を閲覧の重複除外規則で変更しないでください。

フォルダは親階層の点です。2D / 3Dの `goTo({type:'dir', ...})` は共に `parentOf(path)` の航路へ記録し、そのフォルダ自身の子階層へ混ぜません。ルート移動では空パスの点を追加しません。

確認コマンドは `node --test frontend_ide/checks/route-records.test.mjs frontend_ide/checks/search-route-records.test.mjs frontend_ide/checks/star-depth.test.mjs frontend_ide/checks/space-mode.test.mjs` です。同一点・往復・分岐・旧データ・保存再開・40件超・途中点削除・2D/3Dのフォルダ記録・検索結果の返却/保存/再読込・旧検索履歴の補完・Explorer通知からengineへの明細受渡を確認します。Explorer通知の検証は実ソースの通知コールバックを実行しますが、Vue全体のマウント検証ではありません。これらはCanvas/APIを置き換えた実エンジン検証で、実ブラウザーの描画品質やElectron保存容量は別途確認が必要です。

## 2Dのフォルダ状態監視・更新表示

2Dの「自動探索」がONで表示中の間、`ファイル閲覧/フォルダ監視.js` が `/api/folder-state?path=<プロジェクト相対フォルダ>&filter=backup` を確認します。画面のフィルターOFFでは `filter=` を渡します。表示は直下だけですが、子フォルダカードの件数が再帰集計なので監視範囲も現在フォルダ以下の再帰です。親や兄弟のフォルダへは広げません。

- 応答は `files`（ファイル数）、`latest`（対象ファイルの最新mtime・Unixミリ秒、空ならnull）、`revision`、`fileList`（プロジェクト相対のpath/name/size/mtime）、`tree`（既存形式）です。一覧・件数・日時・指紋は同じ1回の走査から作ります。`since=revision` が一致すれば `unchanged:true` となり、一覧とツリーを省きます。表示更新は返されたツリーを直接利用し、再取得の全体走査を追加しません。ファイル名の表示順は既存の日本語・数値自然順です。
- 除外規則は従来の `viewer/file-scan.mjs` の値を `backend_server/core_router/フォルダ除外規則.json` に移し共有しています。backupの意味を変更せず、変更が必要なら元の `AIバックアップ.py` と照合してください。指紋は対象パス・サイズ・mtime・ctime・inodeと表示対象ディレクトリ名から作り、ディレクトリmtimeは使いません。対象外ファイルの変更で親mtimeが動いても、再描画しません。本文は読みません。OSのメタデータをすべて維持した特殊な書換えは検知対象外です。
- 通常は応答完了から30秒後に次回を確認します。開始・再開・対象切替時の初回確認と手動更新は即時です。大規模走査・不完全結果・HTTP失敗後も30秒待ちます（フォルダが見つからない場合の既存の10秒再試行は維持）。OFF・3D・非表示・利用終了・フォルダ/フィルター切替で要求をabortし、世代番号でも古い応答を捨てます。サーバーの同時走査は1本で、フィルター・対象フォルダを分けた短期キャッシュを共有します。
- 上限は通常3万/backup10万ファイル、1万フォルダ、20万列挙、深さ128、走査10秒です。`truncated` と `truncationReason` を必ず確認してください。不完全な結果は表示を置き換えず、案内を出して30秒後に再確認します。一覧を返す場合の件数は返した部分一覧と一致します。
- 自動更新は差分がある時だけ、右上の手動更新は成功したら差分がなくても、上から下へ線と旧ページの切り抜きを650msで動かします。移動・連続更新・ユーザー操作では旧演出を取り消し、OSの設定によって演出を省略しません。スクロールと残存する選択を維持します。
- 今日の日付は閲覧端末の年/月/日で判定し「今日 HH:mm」を赤字表示します。それ以外の従来表記と元日時tooltipを維持し、ローカル深夜と再表示時に判定を更新します。無効な日時は「—」です。
- フォルダカードは角丸なし、四辺に沿ったinset shadowで外周を濃くします。名前とメタ情報の列では右側に固定42%を予約せず、メタ情報の内容幅以外を名前に使います。
- 閲覧軌跡の見出し右端の「クリア」はjournalのファイル閲覧記録だけを消し、既存の保存処理を再利用します。階層別の経路・現在点・重複判定・AI検索軌跡・ファイル本体は保持します。空なら無効、閉じた時やAI検索軌跡には出しません。

バックエンド共用APIは認証付き `POST /core/files/フォルダ状態` です。bodyは `{"フォルダ":"src","フィルター":"backup"}`（OFFは空文字）です。サーバー設定のCODE_BASE_PATH内だけを許可し、絶対パス・親脱出・リンク・除外フォルダへの直接指定を拒否します。`data` に `ファイル数`、`最終更新日時`、`ファイル一覧`（パス/名前/サイズ/更新日時）、`変更識別子`、`不完全`、`制限理由` を返します。IDE独立サーバーでは既存のHost/Origin/利用開始とプロジェクトルート境界を使う同等APIを使い、オフライン利用を保ちます。Python側も同じ上限と2秒キャッシュ、同時走査1本を使い、混雑時は429を返します。

## 3分類の軌跡ツリーとフォルダ境界

軌跡バーは「閲覧軌跡」「検索軌跡」「AiDiy検索軌跡」です。起点日時の指定・プリセット操作・grep実行で検索軌跡へ、AI検索開始・再確認・履歴選択でAiDiy検索軌跡へ切り替えます。結果到着だけに依存しません。検索失敗では前回確定した同分類の結果を維持し、空の成功結果は空状態にします。3分類の選択は対応する実際のツリーと描画へ渡し、閲覧記録を追加しません。現行エクスプローラーの非AI検索は起点検索とgrep検索です。将来別の検索方法を追加する場合も `beginSearch` / `acceptSearch` を同じ経路で使います。

ツリーは `開発スペース/軌跡ツリー.js` の表示用変換です。閲覧は保存済みvoyagesのfrom/to、AIは検証済みrouteRecords（旧結果はrouteから補完）を使います。grep・起点の結果は関係性を持たない並列候補として表示し、ファイルの名前順・フォルダ階層を経路の親子に置き換えません。同一路・逆辺は既存規則でまとめ、循環や合流は参照行で展開を止めます。反復処理なので長い経路にも再帰上限はありません。

フォルダの親階層にある `g:パス` は到着点、そのフォルダ内のnull始点は内部の出発元です。表示だけに `o:パス` を使い「到着 → 出発元」の対として示します。保存形式v2・保存済み明細・現在点・再訪時の重複判定は変更しません。ルートの表示用出発元は `o:` ですが保存する空パスの点は追加しません。＜ ＞はツリーの表示順に辿り、同じフォルダの到着／出発元を1操作へまとめます。通常ファイルは1件ずつ進み、終端で無効になります。各点を直接選ぶ操作も同じgoToへ渡します。

閲覧のクリアはファイル閲覧journalだけを消します。フォルダの記録が残る場合はその部分を表示し、消したファイルを保存済みの辺から復活させません。検索・AI分類と保存済みvoyagesは保持します。表示用変換からlocalStorageを直接書き換えないでください。

## ExplorerとViewerのピン留め・表示開始

Electronのピン留めは、DOM移動前に元パネルの表示範囲を `capturePage` で撮影し、本体の同じ位置に操作不可の画像として残します。比較・Monaco・iframeの実体は従来どおり1つだけ移動します。別窓の表示演出と描画が完了したら元画像を除去し、失敗・終了・親破棄でも必ず片付けます。撮影範囲にはCSS座標へ窓のzoomだけを掛け、OSのDPI倍率は重ねません。展開中の軌跡は窓の初期サイズ用のバー範囲とは別に、元パネル全体を保持します。

Explorerは `ファイル閲覧/パネル別窓.js` で同じVueインスタンスのaside DOMを別Documentへ移します。検索やAIジョブを再発行せず、入力・展開・選択・結果・スクロールを保持し、既存のselect/marks/routeイベントでIDEと連携します。軌跡バーは本体に残します。別窓のCSSが準備できてから移し、ポップアップ失敗時は本体を残します。Electron別窓はタイトル右端の×で閉じ、Explorerを本体内に開いたまま戻します。本文の↙は重複するため表示しません。OSの閉じる操作や本文バーガーで折り畳んだ場合も、再表示時に検索・展開・入力を保持します。Web popupの「本体へ戻す」は維持します。子の再読み込みでは旧Documentを離れる前にDOMを退避して、新Documentへ戻します。Vueがaside自体を条件付きで作り直す変更は避けてください。

Electronは親IDEからの限定IPCで、一度だけ使えるwindow名とabout:blankを予約します。子窓を既存のセッション監視に登録し、利用終了・親終了で閉じます。Webは親のpagehideとコンポーネント破棄時に子窓を閉じます。再pinでリスナーやポーリングを積み重ねません。Viewerとソース比較の別窓Xは、その閲覧セッションを終了します。IDE内への自動復元やファイル削除は行わず、Monacoモデル・要求・タイマー・窓参照を解放します。ファイルを選び直せば新しい閲覧を開始できます。子reloadと起動失敗はXとは区別し、既存セッションを保持します。

両別窓の初期位置は元パネルの矩形を使います。ElectronではgetContentBoundsとworkAreaのDIPへwebContentsのzoomだけを掛け、パネルに対応するディスプレイ内へ収めます。OSのDPI倍率を二重に掛けません。Windowsでは外枠が1～2px丸められる場合があります。ブラウザーでは外枠と表示領域の差から位置を見積もり、screenの利用可能領域へ制限します。配置・寸法の要求はブラウザーやOSに制限されるため完全一致は保証できず、複数画面やブラウザーズームでも厳密に配置する必要がある場合はElectronを使います。追加の画面アクセス権限は要求しません。

Web別窓、画面内Explorer/Viewer、軌跡一覧の開始は260msのopacityフェードです。通常の再描画や内容更新では繰り返さず、閉→開・明示的な本体への復帰でだけ開始します。別Documentへ移す際は元Documentのフェードを解除します。Electron別窓は既存 `host/scripts/window-opening.cjs` の750ms・.55倍からのズーム演出を使います。reduced-motionでは両方式とも開始演出を省略します。フォルダ更新線の演出は独立しています。別窓は不透明背景、本体へ戻すと既存すりガラスの適用範囲へ戻ります。

IDE / Code / Live / Term / Viewer と Explorer・軌跡・比較・Web 別窓には、開いた後に光や影が走る演出を付けません。`aidiy-window-shown` やパネルのフェード完了から光沢を呼び出さず、光沢用の DOM・CSS・タイマーも生成しません。ネイティブの拡大表示と通常のフェードは維持します。`scripts/check-code-drag.mjs` は登場完了後の光沢が生成されないことと寸法・入力・ヒット判定を撮影して確認します。`AIDIY_OPENING_ONLY=1` を指定した `scripts/check-all-displays.mjs` は IDE 内のパネルとピン留め Explorer に絞って実 Electron で撮影し、指定なしの試験は Explorer / 軌跡 / 比較を含む全画面横断の確認も行います。`checks/panel-lifecycle.test.mjs` と `checks/panel-windows.test.mjs` は共有パネルの移動・復元・フェードを確認します。

## 各モジュールの長押し窓移動

全Electronアプリの必須方針と表示開始ズームは [共通,Electronウィンドウ基本方針.md](./共通,Electronウィンドウ基本方針.md) を参照します。ズームは最終寸法の透明パネルで領域を確保し、内側だけを拡大します。軌跡の別窓も `panel-windows.cjs` の共通ズームへ進み、実ウィンドウの外枠を連続拡大しません。

Diagの通常・ミニ表示、Avatarの全Electronパネル、Discordも同じ処理を使います。他アプリは `デスクトップ/長押し窓移動.cjs` の `attachNativeWindowMove(window,screen,kind)` をmainの窓生成時に一度取り付けます。許可した種別は `diag` / `avatar` / `discord`。mainが所有する窓のrecordを内部で作り、`code-drag.cjs` のDIP差分・サイズ補正・解除処理を共用します。rendererへ窓ID・任意座標・新しいIPCを公開しません。詳細な適用箇所・検証は各アプリの運用ナレッジを参照してください。

Electron の Code / Live / Term / Browser / Viewer と、IDEからピン留めした Explorer / ファイルビューア・ソース比較 / 軌跡バーは、左ボタンを同じ位置で0.5秒静止して押すと窓を移動できます。本文・入力欄・ボタン・リンクを同じルールで扱います。押下は保留し、短押しなら解放時に元の押下と解放を渡すため、押した瞬間のファイル選択・ワープを起こしません。0.5秒の判定中に少しでも位置を動かした場合は元の押下を渡し、通常の文字選択・dragを続けます。最大化・全画面の窓では開始しません。

成立後は標準の移動カーソルと静止した四方向マーカーでドラッグ状態を示します。`デスクトップ/窓移動表示.cjs` が透明なpopoverを最前面に置き、iframe・Monaco・比較の左右どちらでも表示します。回転・拡縮の演出は行いません。単にhtml要素のcursorだけを検査せず、押した位置のヒット要素と移動中の画像を確認してください。解放・Esc・blur・ページ遷移・画面破棄で解除し、移動後の解放をページへ渡さないことでクリック・リンク遷移を防ぎます。

`デスクトップ/長押し窓移動.cjs` が Electron の `before-mouse-event` で入力を調停します。IDE本体・通常の窓・ピン留め窓に加え、BrowserのWebContentsView本文にも取り付けます。Monaco、同一・別オリジンのHTML iframeを共通処理でき、外部ページへIPC権限を渡しません。`preload.cjs` の `nativeWindowMove` がある場合、`src/共通表示/長押し窓移動.js` の旧renderer方式を停止して二重処理を防ぎます。Web / VS Codeには導入しません。

IDE本体は通常モードでは窓移動、VR中では中心点移動に分岐します。VR状態はmainで判定し、窓の位置・寸法を変更せず、`development:space-center-move` で開始・開始時からの差分・終了を通知します。差分はDIPから開始時のzoomFactorでCSS座標へ変換し、同じ四方向マーカーをマウスに追従させます。`開発スペース.vue` が手動補正を保持し、`宇宙描画.js` はVR中だけ自動補正・ワープ中の固定中心・補間より手動中心を優先します。短押しと0.5秒前の通常旋回は維持し、長押し後の解放・Escを宇宙の選択や戻る操作へ流しません。VR終了で通常の配置に戻り、同じ開発スペースでVRへ再移行すると補正値を再利用します。別パネルはVR中も窓移動です。

IDE本体の確認は `$env:AIDIY_ALL_CENTER_ONLY='1'; node scripts/check-all-displays.mjs`。実OS窓のVR固定、通常時の位置移動、倍率1.5での差分、複数回の長押し、マーカー追従、解放・Esc・blur、短い旋回を検査し、`temp/all-displays-check/center-result.json` とマーカー画像へ保存します。カーソル位置・フォーカス判定だけを模擬し、Electron入力とVue・宇宙描画・窓座標は実物を使います。

ネイティブ側 `デスクトップ/code-drag.cjs` は窓の種別・信頼した主frame・tokenを検証します。`development:window-move-*` は各モジュール自身の窓、またはIDE本人から名前で指定した所有パネルだけを対象にします。ピン留めパネルは表示済み・同じ所有元・同じ起動世代を `panel-windows.cjs` で照合します。rendererから座標や任意の窓IDを受け取らず、Electronのカーソル・窓位置を同じDIP座標で差分計算します。lease・navigation・終了時にtokenと購読を破棄します。旧 `development:code-move-*` は互換入口として残します。

検証は `node --test checks/native-window-move.test.mjs checks/code-drag.test.mjs checks/code-window-title.test.mjs`。実Electronでは `node scripts/check-module-move.mjs` がCode / Live / Termの単独・IDE起動と独立Viewer、`node scripts/check-panel-desktop.mjs` がExplorer項目・Viewer・比較・同一/別オリジンHTML・軌跡ボタン、`node scripts/check-browser.mjs` がGoogle入力欄・HTMLリンク・VR中の各画面を確認します。入力はElectronのsendInputEvent、窓の座標・寸法は実OSを使い、カーソル位置とフォーカス判定だけを模擬します。長押し後の誤クリック防止、短押しの入力・遷移、サイズ維持を検査します。`node scripts/check-code-drag.mjs` は旧renderer方式の隔離Chromeテストとして残します。

Windowsの端数倍率では、`setPosition` が内部で窓サイズを再設定するとDIPの丸め誤差が累積します。静止中のheartbeatはlease更新だけにし、移動時は長押し開始時の寸法を明示した `setBounds` と1回の実測補正を使います。整数DIPでは一致できない座標の残差を次の長押しの基準寸法へ加算しないよう、最後の実測サイズと基準寸法を保持します。手動でサイズが変更された場合は新しい寸法を採用します。

`node scripts/check-code-drag-desktop.mjs` は実Electronで接続中の各ディスプレイに透明・非アクティブの検証窓を作り、7種類の窓種別で静止140回・移動280回・長押し7回の反復でサイズ誤差が累積しないことを確認します。入力とフォーカス判定は模擬しますが、座標設定とサイズ取得は実OS窓を使います。倍率が混在する画面間をマウスで横断する操作は別途実機確認が必要です。


## 小さな軌跡パネル

折り畳み時の操作は分類・ルート・前後・ピン・閉じるを1行に収めます。`route-controls` は折り返さない横並びとし、本体内も別窓も幅360pxを基準にします。本体の `--route-width` を画面幅の割合に戻すと広い画面で間延びするため、固定幅を維持し、狭い画面では画面内へ制限します。通常幅360pxでは横スクロールも出しません。Electronの移動ハンドルも同じ行に置き、タイトル専用の行を増やさないでください。画面下端の検証は固定の本文高ではなく、バーを含めた下端が画面内に収まることを確認します。

本体内・別窓の軌跡バーは幅360px・高さ40pxを基本とし、ボタン間隔0px、左右余白3px、バーガー幅26px、分類文字10pxに揃えます。分類のボタンは余白へ引き伸ばさず、同じ文字幅・パディングを使います。別窓側だけを小さくするCSSを追加しないでください。狭いWeb画面では従来の画面幅制限と横スクロールを維持します。`checks/panel-desktop-probe.cjs` はバーを開いてからピン留めし、透明領域内のズーム完了後に1行・横スクロールなしを確認します。高さが異なるバーガーボタンとの整列は縦中心で比較し、Chromiumの矩形計算には0.01pxの誤差を許容します。軌跡だけを調べる場合は `AIDIY_PANEL_ROUTES_ONLY=1` で同じ実Electron検証を実行できます。

ExplorerとViewer／比較のElectron別窓は、既存の `閲覧ウィンドウ.vue` と同じ `共通表示/状態バー.vue` を `ファイル閲覧/別窓タイトル.js` から表示します。OS標準枠を重ねず、接続状態は親IDEの状態バーへ追従します。窓操作は `development:panel-action` を使い、所有元・窓名・起動世代・許可操作を検証して子窓だけに適用します。親の `window.aidiyWindow.close()` を直接呼ばないでください。reload／復帰時はタイトル用Vueと監視を破棄し、検索・閲覧のDOMは従来どおり保持します。

軌跡バーの📌は閲覧・検索・AiDiy検索の3分類とツリーを同じDOMのまま別窓へ移します。閉じた状態では幅360px・バーの実測高だけの小さなパネルとして開きます。分類を開くと上端を保ったまま下へ最大300px伸ばし、260msの展開が終わってから本文を表示・操作可能にします。閉じる時は本文をすぐ隠し、縮む演出の後に窓の領域をバーの高さへ戻します。

別窓の最前面ピン・×は `別窓タイトル.js` でバーの末尾にこの順で追加します。×は独立窓を閉じ、本体内に同じ軌跡バーを開いたまま戻します。分類の前へ挿入しないでください。Explorer・軌跡を別起動している間、本体側に開き直すバーガーを残しません。×で本体へ復帰した後は通常の表示に戻します。閲覧軌跡の左の二重縦線は削除し、左端のバーガーだけを `-webkit-app-region:drag` の即時移動面にします。独立窓ではクリックで閉じず、タイトルバーの代わりに使います。分類・ピンは静止0.5秒の長押し移動に対応し、短押しは従来の操作、移動成立後の解放はクリックを抑止します。本体内のバーガーは折り畳み操作を維持します。入力欄・開いたポップアップの保護も維持します。実窓で左端から即時移動できることと、分類ボタン・ピンの長押し移動後に分類・ピン状態が変わらないことを確認します。

エクスプローラーの見出し用のflex・最小幅は `header>span` の直接の子だけに適用します。`header span` ではバーガー内部のspanにも最小幅が付き、26pxのボタンから三本線がはみ出して見出し文字へ重なります。本体の起点・grep・AiDiy検索と別窓で、三本線がボタン内に収まり、見出しと交差しないことを `checks/panel-desktop-probe.cjs` で確認します。

`src/ファイル閲覧/軌跡パネル展開.js` がWeb埋込・別窓共通の開閉状態を持ちます。世代番号とタイマー解除で途中反転、連打、遅れて届く領域確保応答を処理し、分類だけの変更では再展開しません。Document移動・reloadでタイマーとresize/reduced-motion購読を付け直し、破棄時に解除します。画面下端では表示可能な高さに収め、reduced-motionでは高さ演出を省略します。

Electronは枠なし・透明の軌跡専用窓を作り、`development:resize-routes` で透明な領域を先に確保してから共通の高さ演出を開始します。IPCは信頼済みIDEとその所有する軌跡子窓、同じ起動世代に限定します。手動リサイズを無効にするのは[Electronの透明窓の制約](https://www.electronjs.org/docs/latest/tutorial/custom-window-styles)によるものです。実OSでの透明表示・プログラムによるサイズ変更は、モック検証とは別に確認してください。

Web別窓はOS背景の透明化を保証できず、ブラウザーが最小窓サイズやresize要求を制限する場合があります。先にresizeを要求し、取得できた内側の高さに表示を収めます。Web埋込でも同じ下方向の演出を使います。Electronの透明な余白はクリック透過にはしません。

右端の×で独立窓を閉じると、本体内に軌跡バーを開いたまま戻します。独立窓のバーガーは即時移動専用です。OSの閉じる操作では、本体でバーを折り畳んで「軌跡」ボタンを残します。記録・分類を保持し、再表示後も選択ジャンプ・閲覧軌跡のクリアができます。reloadは閉じる操作と区別して同じDOMを再接続します。表示に失敗した場合は本体側を保持します。

検証は `node --test checks/route-expansion.test.mjs checks/navigation-parity.test.mjs checks/panel-windows.test.mjs checks/panel-lifecycle.test.mjs`、ビルド後に `node scripts/check-route-expansion.mjs`。後者は隔離Chromeと一時プロジェクトで開閉中の高さ・本文の表示時刻、途中反転、画面下端、reduced-motion、3分類・実ツリー・ジャンプ・X復帰・クリア・親終了を確認します。AiDiy検索は固定結果に置き換え、外部AIの実行を禁止します。Electron実窓の検証とは区別してください。

## 2Dモーションの実画面検証

`node frontend_ide/scripts/check-2d-motion.mjs` は、初期表示、ページ内の進む／戻る、エクスプローラーと最終更新欄からのファイル選択を実ブラウザーで確認します。自動探索はOFFにし、3Dの周回・探索航行とは分けます。複数階層の切替、スクロールによる中断、一覧更新、OS設定による演出省略がないこと、3D復帰時の選択維持も確認します。

一時プロジェクトと隔離Chromeを使い、最終更新の通知データだけを試験用に指定します。CSSアニメーションを25%／75%などの途中時刻で固定し、斜線の座標・旧ページの切り抜き・設定時間を比較して撮影します。設定時間800ms／650msは実機のフレームレート測定とは区別してください。経由ページにも `folder-page-sheet` が付くため、旧ページの検査には `[data-page-layer="outgoing"]` を使います。

画像・結果・ハッシュは `images/セルフテスト,aidiy_ide,操作編/` に `<実施ID>-ide-2d-motion__ide-操作_6nn_…画面.png` として保存します。記録先は `セルフテスト,aidiy_ide,操作編.md` の6-3です。関連確認は `node --test frontend_ide/checks/folder-pages.test.mjs frontend_ide/checks/navigation-parity.test.mjs frontend_ide/checks/space-mode.test.mjs` です。

## 横画面のビューアとVR操作領域の余白

`src/style.css` の通常の横表示では、`space-view` 内のビューアと比較パネルを `top:var(--workspace-top)`・`bottom:60px` にし、エクスプローラーの上端・下端にそろえます。比較の固定高さも解除します。通常表示へ余分な上下16pxを足さず、右上の操作領域を避ける制限はVR側で扱います。別窓のViewer／比較にはこの配置を適用しません。

VR中は `--vr-viewer-top:192px`・`--vr-viewer-bottom:48px` を確保し、最大720pxの高さを画面内へ収めます。右上の復帰・部品起動メニューの縦並びを避け、ビューアと比較に同じ制限を使います。横位置は中心星の128px右を基本に、画面右端の16px余白へ収めます。

`AIDIY_ALL_VIEWER_ONLY=1` を指定した `scripts/check-all-displays.mjs` は、実Electronで通常横画面の3サイズ・比較・VR移行と復帰を確認します。通常表示でのExplorerとの上下端の一致、上部操作との矩形交差、VRの上下の余白、単一ビューア、ピン留め・子窓の寿命を検証し、画像と `viewer-result.json` を保存します。設定方法は上のVR閲覧の項、正式な実施記録は `セルフテスト,aidiy_ide,操作編.md` の2-1を参照してください。

## 閉じる印の大きさと太さ

閉じる・添付解除の×は、`<span class="close-icon" aria-hidden="true"></span>` をボタン内で使います。`src/style.css` が14pxの領域に2pxの斜線2本を描きます。ビューアの本文用 `--file-font-size` やOSのフォントで印が細くならないための共通指定です。ボタンには機能に合う `aria-label` を残してください。文字サイズの一括指定を直すために、本文や他の操作ボタンの文字を拡大しないでください。

変更時は3D／2Dでファイルを開き、×の表示・クリックによる閉じる操作を確認します。タイトルバー、履歴、分析、Liveのモデル選択、Webのパネル、案内、Codeの添付解除にも同じ印を使います。ブラウザの読込停止は別の操作です。
