# Vue共通画面変更手順

> 文書: `frontend_ide,Vue共通画面変更手順.md` | 実装: `frontend_ide/src/App.vue`, `frontend_ide/src/components/FileExplorer.vue`, `frontend_ide/server.mjs`, `frontend_ide/vscode-html.ts`

## このメモを使う場面

- Code / Live / IDEの共通画面やファイルエクスプローラーを変更するとき。
- 単独版とVS Code拡張の表示が一致しないとき。

## 変更先の選び方

IDEのElectron版はプロジェクト表示行の名前のすぐ右側に並ぶ「＋ Term」「＋ Code」「＋ Live」から別ウィンドウを開き、Web版は画面内タブです。切り分けは `window.aidiyWindow` で行います。IPCにはアプリ種別だけを渡し、プロジェクト・モードはメインプロセスでIDEサーバーの状態から取得します。

画面は `frontend_ide/src/components/` を変更します。Code / LiveをIDEへ配置するときも同じVue部品を使用します。ホストと通信プロトコルは `frontend_ide/host`、ファイルAPIとOffice表示資産は `frontend_ide/viewer` に統合しています。親ディレクトリ数を固定して共通設定やHermesを探さず、配置先から親方向へ探索してください。

IDEのオンライン利用では、`viewer/core-connection.mjs` がコアの疎通を5秒ごとに確認し、`src/App.vue` も状態を5秒ごとに取得します。接続済みの定期確認中は `connected=true` / `connecting=false` を維持し、確認が失敗した時に接続表示を変えます。初回接続と切断後の再接続では `connecting=true` を表示します。コア停止でも利用開始時刻・作業・子窓を維持してください。単体検証は `node --test frontend_ide/viewer/checks/connection.test.mjs`、実画面検証はVue配布ファイル生成後の `node frontend_ide/scripts/check-connection.mjs`（Chromeを任意配置している場合は `CHROME_PATH` で指定）。模擬コアを使い、5秒周期・定期確認中の表示維持・停止と復帰を確認し、日本時間の日時付き画像を `temp/connection-check/` へ保存します。

Codeのオフラインモデル候補は `same`（変更なし）を使い、選択時はHermesへ `--model` / `--provider` を付けずに呼び出します。オンラインの `auto`（AI判断）とは区別します。オフラインの選択値は `~/.aidiy/aidiy_code_model_offline.json` に保存します。

エクスプローラーは `FileExplorer.vue` 一部品にまとめます。入力はtree/root/selected/current/startedAt/open、出力はupdate:open/select/clear/marksです。検索マークはイベントで宇宙へ伝え、エクスプローラーからCanvas内部を書き換えないでください。利用開始時刻が変わると起点検索を初期化します。

「閲覧軌跡」「AiDiy検索軌跡」と関連ファイルへの移動ボタンは、エクスプローラーの開閉に関係なく表示します。閉じている間はバーガーボタンの右隣へ横並びにし、狭い画面では折り返します。開閉だけでは選択した軌跡を変更しません。

軌跡ボタンは一覧の開閉も兼ね、直下にファイル一覧を表示します。AiDiy検索軌跡は検索結果の順、閲覧軌跡はengineのjournalからファイルだけを最近開いた順に表示します。journalはSpaceViewからpropsで渡し、一覧クリックも既存のselectExplorerを通します。閲覧一覧を開いている間は再訪による順序変更を止め、前・次で同じ2件を往復する状態を防ぎます。一覧外のクリックとEscで一覧だけを閉じます。`check-ai-search.mjs` はエクスプローラーを閉じたまま両一覧から移動し、再訪時の表示順も照合します。

ルート行も通常のフォルダと同じく、三角ボタンは開閉専用、フォルダ名ボタンは `select({type:'dir',path:''})`のルート移動に分けます。開閉ボタンを押しただけで宇宙を移動させないでください。ツリー行は `TransitionGroup` で高さと不透明度を240ms以内で変え、下の行も流れに沿って移動させます。手動開閉・ルート開閉・起点検索の展開変更を同じ演出にし、動きを減らす設定では即時切替にします。検証では途中の高さと連打後の最終状態も確認してください。

エクスプローラーからの移動は `SpaceView.selectExplorer()` を通し、航路全体の完了まで選んだ項目を一覧の `selected` / `current` に保持します。途中で通るフォルダは宇宙だけに反映します。`navigating` の間は一覧の自動 `reveal()`（カーソル変更・展開・スクロール）を止め、利用者の一覧操作は有効に保ちます。連続選択時は古い航路の完了で新しい選択を解除しないでください。`check-warp.mjs` で深いフォルダ・別枝ファイルへの移動中も一覧の状態とスクロールが変わらないことを確認します。

grepは検索ボタンでのみ実行し、入力中は前回の結果を保持します。検索開始時に一覧を先頭へ戻し、展開状態をリセットしてルートを閉じ、「検索中…」を表示します。完了時はルートと一致ファイルの全親フォルダだけを開き、0件ならルートだけ開きます。結果表示後もスクロール位置は先頭にします。再検索・解除・検索方式の切替後に古い応答が展開状態や検索マークを上書きしないことも確認してください。

縦表示（画面の高さが幅以上）では、上左にエクスプローラー、上右に軌跡ボタンとリスト、下半分にファイルビューアを配置します。エクスプローラーを閉じても軌跡は右側を維持します。両一覧の幅はそれぞれ画面幅の25%、高さは画面の中央までに制限します。ビューア表示中の宇宙の中心は、上半分で開いている一覧の間の中央です。ビューア非表示時は一覧の開閉に関係なく、画面全体の中央（横50%・縦50%）に固定します。

横表示では、左側にエクスプローラーと軌跡ボタン・リスト、右側に幅33vwのビューアを配置します。左の両一覧はそれぞれ画面幅の25%にし、宇宙の中心は開いている一覧の右端とビューアの左端の間に置きます。片側のパネルを閉じた分だけ空き領域を広げます。固定の33%・50%ではなく実際の一覧寸法から算出します。縦位置はヘッダーと下部操作ボタンを除いた作業領域の中央です。`SpaceView.layout()` がcenterX・centerYを返し、パンくずと `space.js` のmeasureCoverで共有します。ワープ到着後の配置もplannedPreviewで同じ中心を求め、移動中の投影中心固定を維持します。`check-warp.mjs` は横1280×800・縦768×1000・狭い縦390×844で各パネルの全8開閉パターンを確認し、中心がパネルに隠れないことと一覧の配置・高さを検証します。画面は `temp/space-layout-check/` に保存します。検証画像名の先頭には日本時間の撮影日時と連番を付け、名前順で新旧が分かるようにします。一覧・軌跡・ビューアの文字は共通の `--file-font-size:10px` で揃えます。MonacoもこのCSS変数を読み、コードと簡易テキスト表示のサイズを一致させます。HTML・SVG・Office文書の表示内容は元文書の書式を維持します。

自動視点は `src/engines/auto-orbit.js`、操作との連携は `space.js` に置きます。軌道形状には遠点起算のケプラー方程式 `M = E + e sin(E)` を使います。遠点の速度は従来の1/3、近点は従来の1/6とし、速度差を圧縮して加速感を残します。接近中は実速度が増え続ける曲線を使い、近点直前で減速へ転じないようにします。物理公式どおりの一定面積速度にはせず、遠点では次の軌道への切替中だけ停止します。一周の軌道面は固定し、次の軌道面への変更は停止中に行います。船体の実座標から軌道を始め、1.1秒の位置固定旋回、軌道面へのロール合わせ、案内線の表示後、現在フォルダの中心を見続けて進みます。ファイル選択・ワープ・ドラッグ・画面非表示では進めず、手動操作の最終時刻から60秒経過してから再開します。ピンチとドラッグ終了時も停止期限を更新し、ファイル選択解除そのものでは期限を延長しません。`checks/auto-orbit.test.mjs` と `scripts/check-autodrive.mjs` で実座標・中心への視線・軌道の連続性と実画面での停止条件を確認します。

## 検証・配布

星・惑星・銀河の描画寸法はワールド寸法×透視倍率（焦点距離/奥行き）で決めます。最小表示サイズや選択時の上限で距離差を消さず、更新の強調も倍率だけで表現します。遠方は明るさを抑え、カメラ直前は滑らかに消します。銀河中心が背後でも手前に残る星は個別に描画・選択できます。`check-orbit.mjs` は実Canvasの描画呼出しで距離半分ならサイズ2倍となることと、銀河内の描画を確認します。

自動視点の最接近距離は遠点の18〜26%です。初回の軌道計算上の周期は48〜64秒で、実時間では全体の1/3速と近点の追加減速を適用します。星々の分布半径1500より内側まで入り込み、接近・通過・離脱が見える範囲を維持してください。全景の外から眺めるだけの距離に戻さず、`checks/auto-orbit.test.mjs` で `cameraPosition()` の原点からの距離を測り、分布の内側へ入ることを確認します。`dist` は描画上の注視点までの距離なので、実座標の代わりには使いません。

宇宙の中央にはルートを含む全階層でワームホールを表示し、ラベルは現在フォルダ名にします。子階層ではダブルクリックで1つ上へ戻り、ルートではワープしません。ラベルとツールチップに親フォルダ名を混ぜないでください。

宇宙表示の右下「視点移動」は利用開始ごとにONです。`SpaceView.vue` から `setAutoSpin()` を呼び、エンジンの通知でトグルとSpaceキー操作を同期します。OFFは自動移動を止め、手動操作は有効のままです。明示的なONは60秒の待機を解除しますが、ファイル選択中の停止は維持します。選択解除や階層移動で利用者のON/OFFを上書きしないでください。

起動時は現在の最終更新ファイルを一度表示します。自動表示中を示す `followedPath` と、最後に到着した `lastFollowedPath` は分け、手動操作やOFFからONへの切替で到着済みの記録を消さないでください。同じパスの通知や再開では再予約せず、移動先のフォルダで彗星軌道へ戻ります。別の最終更新ファイルは引き続き追跡し、手動待機・OFF中の未到着予約も保持します。追跡は直列に実行し、移動中の更新は最新の予約で上書きして、古い対象を開かないようにします。追跡開始時には一覧を再走査し、直前に新規作成されたファイルも取り込みます。プレビューは最後の操作から5分で閉じます。FileViewerのactivity通知（クリック・キー・ホイール・Monacoスクロール・文書内操作）と別ファイルの表示で5分を数え直します。自動消去からの彗星軌道再開では同じ対象を再予約せず、新しい更新を待ちます。`node frontend_ide/scripts/check-autodrive.mjs` で一時プロジェクトと実ブラウザの仮想時計を使ってこれらの遷移を検証し、`temp/autodrive-check/<日時>_<連番>_autodrive-*.png` を撮影します。

ワープの旋回計算は `src/engines/warp-camera.js` にあります。`cameraPosition()` で船体の実座標を復元し、位置を固定して1.1秒で目的地へ旋回した後、正面へ直進します。通常のカメラ補間も `interpolateCamera()` で実座標を補間し、注視点と角度の同時補間による横滑りを防ぎます。ドラッグだけは例外で、`orbitAround()` により中心星を軸に回り込みます。星までの距離を保って船体と視線を一緒に回し、ドラッグ後の実位置・向きを次の航行の出発地点にします。彗星飛行は楕円上の位置と速度を維持し、視線だけは常に現在フォルダの中心へ向けます。再開直後は位置を固定して約1.1秒で中心へ向き直します。計算した軌道線は `auto-orbit.js` の航行と同じ位置計算から385点を採り、新しい軌道の確定時だけ生成します。船は基準軌道点から軌道面の上向き法線へ、基準半径×tan(5度)だけ上げた実座標を飛びます。基準半径をcos(5度)倍して中心からの船体距離を従来どおり保ちます。初回と次軌道の計算では、この高さを含む船体位置が切替前と一致するよう軌道の基底を回転します。`space.js` の `drawOrbitPath()` は基準軌道の座標を原点中心に0.85倍して船の内側へ寄せ、天体と同じ投影で淡い青の線だけを描き、背後の点や軌道の末尾と先頭を結びません。手動操作・ワープ・プレビュー・OFFで航行用の軌道を破棄します。表示用の線は約1.2秒のsmoothstepと軽いぼかしで消し、新しい線も約1.2秒で浮かび上がらせます。遠点では `hiding`（1.2秒の消去）→ `planning`（暗い状態で再計算）→ `aligning`（3.6秒のロール回転）→ `revealing`（1.2秒の表示）→ `flying` の順で進めます。`planning` と `aligning` の間だけ「探索軌道計算中」を表示します。回転は2.7秒で目標角度を最大3度（回転量の15%）だけ越え、残り0.9秒で一度だけ戻して水平に整えます。切替中は船体を遠点に固定し、視線も中心に保ちます。`orbitLevelRoll()` は軌道面の法線から水平になる最短ロール角を求めます。`cam.roll` を天体・遠景の投影へ同じように反映し、軌道面の上側が機体の上になるようロールを合わせます。案内線だけの見かけの回転は行いません。`orbitVisibility` とフェーズを使い、機体回転中には新しい線を出しません。星系が変わった場合は旧線を持ち越しません。進行方向の接線を向くと星系を背にして黒い画面になるため、接近・通過・離脱と次の軌道への切替でも中心注視を保ってください。手動回転の軸は彗星飛行中は現在フォルダの中心、接近後は目的の星です。全体表示は外側の観測位置へ向いて前進し、そこで中心へ向き直ります。フォルダ到着時も船首方向を引き継ぎます。

手動選択・閲覧軌跡・AiDiy検索軌跡・最終更新の自動追跡は `goTo()` を共有します。別フォルダへは共通の親を経由し、1階層ずつ旋回・前進・ワープします。目的フォルダ内のファイル接近には常に `transition:false` を使い、Canvasの拡縮・暗転・ぼかし・放射状のワープ光跡を再生しません。接近済みの同一ファイルの手動再選択は移動を省略します。ビューアの閉じる操作・5分での自動消去は、現在の階層・船体位置・船首方向を保ちます。閉じる操作で移動中なら、その場で航行を取り消します。連続選択でも古い航路が後からプレビューを開かないよう世代番号で無効化します。未選択状態の再走査を「閉じる」操作として扱わないでください。自動追跡が自分の再走査で取り消されてしまいます。

パネル開閉では船体を動かさず、`cockpitLook()` で操縦席から見回す回転を加えます。透視投影面の中心は画面中央に固定し、空き領域へ移すのは船首の見える位置です。平行移動による全景の横滑りや、ビューアが開いた瞬間の中心ジャンプを避けます。`SpaceView.layout({preview})` が返す空き領域の中央とパンくず配置は維持します。航行中は `warpProjection` に視線配置を固定し、フォルダ間のワープでは不可視の間だけ到着時の配置へ切り替えます。

`checks/warp-camera.test.mjs` は実座標・正面への直進・航行の位置固定旋回・手動周回・視線回転の距離/角度保存を確認します。`check-warp.mjs` は実際のエクスプローラー行クリック、同階層の演出なしの接近、深いフォルダ・別枝・選び直し・閉じた時の現在地保持・左右ドラッグ・縦横の配置を検証します。`check-autodrive.mjs` は同階層の自動追跡にもワープ演出がないこと、5分消去、更新追従、予約変更を確認します。ワープ光跡の長さは従来比1.8倍を維持します。

右下の「高速ワープ」は利用開始時OFFです。ONでは `goTo()` による別フォルダのファイル選択（エクスプローラー・閲覧軌跡・AiDiy検索軌跡）を、目的フォルダまで1回の `travelTo()` にまとめます。中間階層を表示せず、到着後に `destinationFile` を新しいworldから引いてプレビューを開きます。到着後のファイル追尾や追加接近を行わず、フォルダ全景を維持してください。同階層の一覧選択は高速ワープのON/OFFに関係なく旋回・接近します。最終更新の自動追跡も高速ワープ設定に従い、フォルダ自体の選択は通常の階層順ワープです。OFFへ戻すと通常の階層順ワープになります。`check-warp.mjs` で既定OFF、深い階層・別枝・親フォルダへの1回の移動、同階層の旋回・直進と接近済みファイルの再選択、選び直しによる取消と到着後の視点固定を確認します。

`frontend_ide/README.md` の起動・検証コマンドを使用します。画面配布更新の際はVue bundleを生成します。VS CodeのCode / Liveにも同じbundleを含めるため、拡張配布には `frontend_ide/host` で `npm run package` を実行します。拡張IDは変更しません。IDEのVS Code拡張は作りません。

実画面では手動開始、バーガー初期閉、5種類の起点プリセット、grepマーク、選択・解除の視点移動、Codeオフライン、WebのLiveタブ終了時の音声停止を確認します。ElectronはCode / Liveの個別終了、IDEの「終了」で子窓を閉じて起動画面へ戻ることを `check-windows.mjs` で確認します。`AIDIY_TEST_CLOSE=title` を環境変数に設定するとウィンドウの×からの全窓終了も検証します。×・Alt+F4はElectronメイン側のcloseイベントで確認し、取消では作業状態を変えません。`check-core-stop.mjs` はOSダイアログの選択だけを代行して、確認文言・取消・承認・重複防止と起動画面からの再利用も検証します。終了中の子窓起動はIDE側のrevisionで無効化し、モード・startedAtが変わった子窓はメインプロセスの監視で破棄します。マイク権限・ソケット・非同期初期化はコンポーネント破棄との競合も確認します。

コアの接続状態と作業セッションの寿命は分けます。利用開始後のコア停止では `connected` だけを落とし、`active`・`mode`・`startedAt`・再接続要求を維持します。コア復帰で起点を更新するとVue画面が再生成され子窓も閉じるため、同じ起点で再接続してください。`node frontend_ide/scripts/check-core-stop.mjs` は利用者のコアを停止せず、検証用サーバーの停止・再起動でIDEのファイル表示とCodeの窓・下書きが残ることを確認します。

## AiDiy検索の変更・検証

## 更新履歴の比較を変更するとき

`file-history.mjs` は `/api/file-history?path=...` で保存版一覧、`version=...` 付きで旧版・現在の全文を返します。プロジェクトとファイルの祖先にある `backup/YYYYMMDD/HHMMSS[.all]` のみを調べ、各保存版の同じ相対パスを照合します。全体のバックアップ内容を再帰走査せず、最大5000保存版で打ち切りを明示します。IDはバックアップ相対パスのSHA-256ですが、取得時にも候補一覧との一致と実パス境界を再検証してください。外部リンク・保存版外のリンクを拒否し、利用状態と既存のHost / Origin検証を通します。比較は各1MBまで、UTF-8 / Shift_JISを読み、切り詰めません。

`FileViewer.vue` はテキスト表示時に履歴を確認し、存在する場合だけボタンを出します。`App.vue` が `FileHistoryDialog.vue` の対象を保持するため、ビューアの5分消去や別ファイルの選択でも比較対象が変わりません。MonacoのDiffEditorを読み取り専用・左右固定・空白差分を無視しない設定で使い、未変更行の位置合わせとスクロール同期を任せます。切り替え時の古い通信を中断し、閉じる際はエディターと両モデルを破棄します。更新履歴は最後の操作から5分で自動消去します。再読み込み・履歴選択・クリック・キー操作・ホイール・ドラッグ・左右Monacoのスクロールで時間を数え直し、単なるマウス移動では延長しません。閉じる際はタイマーとスクロール購読も解除します。

APIとパス境界は `checks/file-history.test.mjs`、実画面は `node frontend_ide/scripts/check-file-history.mjs` で確認します。ブラウザー検証は専用の一時プロジェクト・ブラウザーを使い、横・縦の画像を `temp/file-history-check/` に日時・連番付きで保存します。実利用中のブラウザーのビューポート寸法を固定しないでください。API変更後は対象IDEサーバーを再起動します。

## Code / Live の演出を変更するとき

表示寸法・配色・キーフレームは `frontend_ide/src/chat-presentation.css`、Vueへの送受信連携は `src/engines/chat-arrival.js`、文字送りと枠飛行は `host/src/arrival-effect.ts` にあります。旧画面を参考にするときも `frontend_vscode` を実行時依存にしないでください。

入力は送信時の入力欄位置を予約し、同じ本文が戻ったユーザー発言へ560msで飛ばして白い光とぼかしから表示します。Codeの入力履歴は右側70%以内、回答は左側90%以内です。回答は中央の高さ30vhの黒地・白枠へ文字送りし、全文表示後3秒保持して履歴へ移します。Code / Liveとも後続回答は順番待ちにし、入力通知や後続回答で3秒待機を打ち切りません。Codeで同じ状態を再受信しても再演出せず、同じ発言の本文が更新された場合だけ最新の全文表示から数え直します。保存済み会話の読込では再演出しません。会話切替・切断・破棄・画面非表示では順番待ちを含む飛行、文字送り、タイマーを解除します。`check-chat-effects.mjs` は連続する回答それぞれの文字送り完了から飛行開始までを実ブラウザの時計で計測します。

## 起動・終了

## HTML / SVG の相対参照を確認するとき

## Term（ターミナル）の変更・検証

TermのElectron窓は作業領域の幅2/3・高さ1/2で画面下中央に開き、次の窓を28pxずつ右上へ配置します。親IDEの矩形には合わせず、親と同じディスプレイの作業領域を使います。画面端まで進んだら基点へ戻します。単独Termはsingle-instance lockを使わず、起動ごとの一時Chromiumプロファイルを終了時に片付けます。`term-window-slot.cjs` は127.0.0.1の18440〜18567を操作受付のない排他用ポートとして使い、単独プロセスとIDE子窓で配置番号を共有します。番号は窓終了で解放し、プロセス異常終了でもOSが解放します。Code / Live / IDEの既存窓再利用は維持します。

プロジェクトバーの「tools接続確認」はCodeの `auto-connect` トグルを共用します。既定ON、WebSocketの `tools-check` で切り替え、`tools` 応答の `enabled` / `online` で画面を同期します。OFFは疎通の定期実行を止め、シアン表示を解除して赤いバーにします。ONへ戻すと即時に疎通確認を再開します。シェルの再起動は行わず、端末の再起動でも同じサーバー内の選択を維持します。確認中にOFFへ変わった場合の古い応答は世代番号で無視してください。

Termの入力前はCodeと同じ `TerminalWelcome.vue` とアイコンを使い、実PTYの入力欄を下部へ小さく配置します。xtermの `onKey` とDOMの `input` / `paste` で初回操作を検出し、同じ端末要素を拡張・再fitします。シェルや端末を作り直さず、初回の文字・日本語IME・貼り付けを失わないようにしてください。シェルが自動送信する制御応答を入力開始と誤認しないよう、`onData` だけで判定しません。再起動時は初期表示へ戻し、タブ切替では表示状態を保持します。

CLI補完候補は `TermPanel.vue` でカーソル直後へ薄いグレーの文字として重ねます。xtermのセル寸法・表示中の行位置から配置し、右端で折り返します。端末バッファには候補を書き込まず、Tab確定時だけPSReadLineが入力へ追加します。描画・スクロール・サイズ変更時に位置を更新し、別画面や終了時には表示しません。候補を常設の下部パネルへ戻さず、下部はキー操作の案内だけにします。

タイトルバーはCodeと同じ `StatusBar.vue`、プロジェクトバーは共通の `component-toolbar` を使い、フォルダ名と完全パスのツールチップを表示します。シェルの状態は下部に分け、シアンバーはtoolsの疎通だけで決めます。`terminal.mjs` は `ai-search.mjs` の接続先解決（`PORT_TOOLS`、既定8095）を共用し、`aidiy_code_agents/ping` を3秒ごと・タイムアウト1.5秒で確認します。tools停止でシェルを終了させず、シェルの自然終了後もtoolsの状態通知は維持します。

Windowsの `aidiy_term/powershell-init.ps1` は、その端末セッションだけにPSReadLineのTabハンドラーを設定します。入力が対象CLI名だけでカーソルが末尾なら、`scripts/cli_bat` と同じ権限省略オプションを追加し、実行はEnterに任せます。対象は `codex` / `claude` / `copilot` / `agy` / `grok` / `aidiy_hermes` で、Claudeは既存バッチに合わせて `--chrome` も追加します。モデルは変更しません。それ以外は元のTab処理へ戻します。`src/terminal-completion.js` の `cliCompletions` を候補表示とシェル補完で共用し、履歴予測の斜体表示と確定済み引数を区別します。ユーザーのプロファイルは変更しません。検証では同名の模擬関数で引数を確認し、実CLIを起動しないでください。

`aidiy_term` は `aidiy_term/launch.mjs` → 共通 `launch.mjs` の `--app term` で起動します。IDEのElectron版は「＋ Term」で独立した子窓を複数開き、Web版は `TermPanel.vue` をTermタブに保持します。利用モードはオンライン・オフライン両方で有効です。setup / start / cleanup の表示と処理は Term → Code → Live → IDE の順に揃えます。`aidiy_term/_setup.py` はランチャー、`_start.py` は環境確認・独立起動・プロセス照合、`_cleanup.py` は停止とランチャー解除を担当し、依存物は共通UIにまとめます。

`terminal.mjs` はランダムパス付きのローカルサーバー、`viewer/panels.mjs` は同一公開元への中継です。Host / Origin・IDE利用状態を検証し、シェル・開始フォルダはサーバー側で決めます。入力サイズと端末寸法を制限し、描画完了のACKで出力を制御します。パネル初期化中・終了中のセッション切替では、破棄中のサーバーも完了まで待ちます。

`terminal-process.mjs` は `terminal-worker.mjs` を端末ごとに起動します。ネイティブのPTYと補助スレッドをそのプロセスに閉じ込め、ElectronからもNodeモードで動かします。Windowsの終了はそのworkerのプロセスツリーを停止します。WebSocket切断・ページ再読込・窓終了・IDE終了で停止し、タブ非表示だけでは切断しません。自然終了では末尾のIPC出力を送り終えてからworkerを終了します。ConPTYをIDEメインプロセスで直接保持すると補助スレッドの寿命がIDEに影響するため、この境界を維持してください。

- `node --test frontend_ide/checks/terminal.test.mjs`: 不正接続・寸法・フロー制御、実PTYの日本語、開始フォルダ、リサイズ、Ctrl+C、シェル配下の子プロセスの終了。
- `node frontend_ide/scripts/check-term.mjs`: 専用ブラウザで日本語入力、タブ保持、狭い画面、exit後の再起動、利用終了。WindowsのChrome / Edgeで実行します。
- `node frontend_ide/scripts/check-term-desktop.mjs`: 専用Electronプロファイルで日本語入力、複数窓、個別終了、IDEとの終了連携。
- `node frontend_ide/scripts/check-launcher.mjs term`: プロンプト復帰、同一プロジェクトの複数起動、幅2/3・高さ1/2、右上への配置、個別終了、待機指定、サーバー終了。

画面確認画像は `temp/term-check/` に日本時間の日時付きで保存します。画面の変更を実行中の配信へ反映する場合は共通Vueの配布ファイルを再生成し、サーバー側を変えた場合は対象アプリを再起動します。PTYの依存は `node-pty`、画面は `@xterm/xterm` / `@xterm/addon-fit`。第三者ライセンスを `scripts/build.mjs` の通知生成へ含めます。新規環境の `npm ci` でPTYのビルドが必要になるOSでは、そのOSのC++ビルド環境も用意してください。
