# Vue共通画面変更手順

> 文書: `frontend_ide,Vue共通画面変更手順.md` | 実装: `frontend_ide/src/App.vue`, `frontend_ide/src/components/FileExplorer.vue`, `frontend_ide/server.mjs`, `frontend_ide/vscode-html.ts`

## このメモを使う場面

- Code / Live / IDEの共通画面やファイルエクスプローラーを変更するとき。
- 単独版とVS Code拡張の表示が一致しないとき。

## 変更先の選び方

IDEのElectron版は右上の「＋ Code」「＋ Live」から別ウィンドウを開き、Web版は画面内タブです。切り分けは `window.aidiyWindow` で行います。IPCにはアプリ種別だけを渡し、プロジェクト・モードはメインプロセスでIDEサーバーの状態から取得します。

画面は `frontend_ide/src/components/` を変更します。Code / LiveをIDEへ配置するときも同じVue部品を使用します。ホストと通信プロトコルは `frontend_ide/host`、ファイルAPIとOffice表示資産は `frontend_ide/viewer` に統合しています。親ディレクトリ数を固定して共通設定やHermesを探さず、配置先から親方向へ探索してください。

エクスプローラーは `FileExplorer.vue` 一部品にまとめます。入力はtree/root/selected/current/startedAt/open、出力はupdate:open/select/clear/marksです。検索マークはイベントで宇宙へ伝え、エクスプローラーからCanvas内部を書き換えないでください。利用開始時刻が変わると起点検索を初期化します。

grepは検索ボタンでのみ実行し、入力中は前回の結果を保持します。検索開始時に一覧を先頭へ戻し、展開状態をリセットしてルートを閉じ、「検索中…」を表示します。完了時はルートと一致ファイルの全親フォルダだけを開き、0件ならルートだけ開きます。結果表示後もスクロール位置は先頭にします。再検索・解除・検索方式の切替後に古い応答が展開状態や検索マークを上書きしないことも確認してください。

縦表示（画面の高さが幅以上）では、エクスプローラーを常に上半分（最大幅300px）、ファイルビューアを下半分に配置します。星空の投影中心は横50%、縦位置はプレビュー非表示時50%・表示時25%です。エクスプローラーの開閉では中心を変えません。`SpaceView.vue` のlayoutとCSSのportrait条件を揃え、`space.js` の天体・遠景・ワープ演出は同じ投影中心を使います。プレビューを閉じると縦50%へ戻り、ウィンドウの縦横切替で横表示の左右配置へ戻ることも確認してください。

自動視点は `src/engines/auto-orbit.js`、操作との連携は `space.js` に置きます。軌道形状には遠点起算のケプラー方程式 `M = E + e sin(E)` を使います。遠点の速度は従来の1/3、近点は従来の1/6とし、速度差を圧縮して加速感を残します。接近中は実速度が増え続ける曲線を使い、近点直前で減速へ転じないようにします。物理公式どおりの一定面積速度にはせず、遠点での次軌道への速度の連続性は保ちます。ランダムな軌道面・接近方向の変更は別の滑らかな補間として重ね、中心注視を維持します。ファイル選択・ワープ・ドラッグ・画面非表示では進めず、手動操作の最終時刻から60秒経過してから再開します。ピンチとドラッグ終了時も停止期限を更新し、ファイル選択解除そのものでは期限を延長しません。`checks/auto-orbit.test.mjs` と `scripts/check-orbit.mjs` で軌道の連続性と実画面での停止条件を確認します。

## 検証・配布

星・惑星・銀河の描画寸法はワールド寸法×透視倍率（焦点距離/奥行き）で決めます。最小表示サイズや選択時の上限で距離差を消さず、更新の強調も倍率だけで表現します。遠方は明るさを抑え、カメラ直前は滑らかに消します。銀河中心が背後でも手前に残る星は個別に描画・選択できます。`check-orbit.mjs` は実Canvasの描画呼出しで距離半分ならサイズ2倍となることと、銀河内の描画を確認します。

自動視点の最接近距離は遠点の18〜26%です。初回の軌道計算上の周期は48〜64秒で、実時間では全体の1/3速と近点の追加減速を適用します。星々の分布半径1500より内側まで入り込み、接近・通過・離脱が見える範囲を維持してください。全景の外から眺めるだけの距離に戻さず、`check-orbit.mjs` で実カメラが分布の内側へ入ることを確認します。

宇宙の中央にはルートを含む全階層でワームホールを表示し、ラベルは現在フォルダ名にします。子階層ではダブルクリックで1つ上へ戻り、ルートではワープしません。ラベルとツールチップに親フォルダ名を混ぜないでください。

宇宙表示の右下「視点移動」は利用開始ごとにONです。`SpaceView.vue` から `setAutoSpin()` を呼び、エンジンの通知でトグルとSpaceキー操作を同期します。OFFは自動移動を止め、手動操作は有効のままです。明示的なONは60秒の待機を解除しますが、ファイル選択中の停止は維持します。選択解除や階層移動で利用者のON/OFFを上書きしないでください。

`frontend_ide/README.md` の起動・検証コマンドを使用します。画面配布更新の際はVue bundleを生成します。VS CodeのCode / Liveにも同じbundleを含めるため、拡張配布には `frontend_ide/host` で `npm run package` を実行します。拡張IDは変更しません。IDEのVS Code拡張は作りません。

実画面では手動開始、バーガー初期閉、5種類の起点プリセット、grepマーク、選択・解除の視点移動、Codeオフライン、WebのLiveタブ終了時の音声停止を確認します。ElectronはCode / Liveの個別終了、IDEの「終了」で子窓を閉じて起動画面へ戻ることを `check-windows.mjs` で確認します。`AIDIY_TEST_CLOSE=title` を環境変数に設定するとウィンドウの×からの全窓終了も検証します。×・Alt+F4はElectronメイン側のcloseイベントで確認し、取消では作業状態を変えません。`check-core-stop.mjs` はOSダイアログの選択だけを代行して、確認文言・取消・承認・重複防止と起動画面からの再利用も検証します。終了中の子窓起動はIDE側のrevisionで無効化し、モード・startedAtが変わった子窓はメインプロセスの監視で破棄します。マイク権限・ソケット・非同期初期化はコンポーネント破棄との競合も確認します。

コアの接続状態と作業セッションの寿命は分けます。利用開始後のコア停止では `connected` だけを落とし、`active`・`mode`・`startedAt`・再接続要求を維持します。コア復帰で起点を更新するとVue画面が再生成され子窓も閉じるため、同じ起点で再接続してください。`node frontend_ide/scripts/check-core-stop.mjs` は利用者のコアを停止せず、検証用サーバーの停止・再起動でIDEのファイル表示とCodeの窓・下書きが残ることを確認します。

## Code / Live の演出を変更するとき

表示寸法・配色・キーフレームは `frontend_ide/src/chat-presentation.css`、Vueへの送受信連携は `src/engines/chat-arrival.js`、文字送りと枠飛行は `host/src/arrival-effect.ts` にあります。旧画面を参考にするときも `frontend_vscode` を実行時依存にしないでください。

入力は送信時の入力欄位置を予約し、同じ本文が戻ったユーザー発言へ560msで飛ばして白い光とぼかしから表示します。Codeの入力履歴は右側70%以内、回答は左側90%以内です。回答は中央の高さ30vhの黒地・白枠へ文字送りし、全文表示後3秒保持して履歴へ移します。Code / Liveとも後続回答は順番待ちにし、入力通知や後続回答で3秒待機を打ち切りません。Codeで同じ状態を再受信しても再演出せず、同じ発言の本文が更新された場合だけ最新の全文表示から数え直します。保存済み会話の読込では再演出しません。会話切替・切断・破棄・画面非表示では順番待ちを含む飛行、文字送り、タイマーを解除します。`check-chat-effects.mjs` は連続する回答それぞれの文字送り完了から飛行開始までを実ブラウザの時計で計測します。

初期画面は3行を12秒周期で順に表示し、入力を始めたら全行表示で止めます。入力欄を空にしても再開せず、新しい会話で再開します。Codeの処理中は入力欄上下の1px線を、シアンと白が4.2秒周期で逆方向に通過します。進捗はSTX/ETX/CANで文字送りを開始・終了し、状態通知で同じ文字を二重追加しないようにします。

画像は `host/media` と `host/aidiy_live/media` の元画像を `scripts/build.mjs` から共通・両拡張の配布先へコピーします。画像追加時は `server.mjs` の配信許可一覧も更新してください。検証はREADMEの `check-chat-effects.mjs` と `check-electron.mjs` を使用します。

## 起動・終了

Code / Live / IDEの接続バーは `StatusBar.vue` のclockPulseを有効にし、Webの `_TopBar.vue` と同じ `round(255 * abs(sin(2πt / 9)))` を実時刻から50msごとに計算します。明滅は4.5秒周期で、接続時はシアン、Codeの自動接続OFF・IDEのオフライン時は赤、未接続時は黒です。CSSのopacityアニメーションを重ねず、背景色だけを変えます。

ポートは自動割り当てです。aidiy_code / aidiy_live / aidiy_ideからVue版を起動します。旧aidiy_devの互換起動はありません。cleanupのプロセス照合は起動スクリプトの完全一致とアプリ種別で行い、IDE群の解除が成功してから共通Vue生成物を削除します。

Electronの初期配置は `window-layout.cjs` で画面のworkAreaから計算します。IDEは余白付きの大きな画面、Code / Liveは左右に配置し、IDE連携時は親の境界を基準にずらし、Code / Liveの上端と高さは揃えます。連携窓のタイトルは「AiDiy IDE / Code」「AiDiy IDE / Live」で、単独版のタイトルと区別します。既存窓の再表示では最小化を解除して前面に出すだけにします。単独Electronは種別ごとのsingle-instance lock、IDEのCode子窓は複数起動でき、それぞれ独立したサーバー・会話を持ちます。Live子窓だけ親セッションと初期化中のPromiseで重複を防ぎ、起動中は＋Liveを隠します。子窓の状態はメインプロセスから取得し、閉じたときにボタンを戻します。`checks/window-layout.test.mjs` と `scripts/check-windows.mjs` で画面外にはみ出さない配置・連打・前面復帰・終了連携を確認します。

WindowsでElectronのGUI本体をspawnするときは `windowsHide: false` にします。`true` では初回の画面表示が隠され、URLだけ出て再実行するまで窓が見えない場合があります。バックグラウンドの補助プロセスとは区別し、初回起動時の可視状態を `scripts/check-single-instance.mjs` でも確認します。

## Code / Live の操作・遅延応答を確認するとき

`node frontend_ide/scripts/check-host.mjs` は模擬ホストを実ブラウザから操作し、`nn-audit-*.png` を保存します。履歴の新しい順・更新日時・削除の取消と確定、モデルの自動／既定／直接指定、オフライン固定候補、検証回数の送信・オンライン復帰を確認します。自動接続ONで未接続のバーは黒、接続済みはシアン、手動OFFは赤です。実行モードのHermesフォールバックと、自動接続スイッチの表示判定を混同しないでください。

Liveは接続時のスピーカーON、モデル変更時の音声設定引継ぎ、接続途中のフォルダ変更、モデル保存待ちの停止を確認します。遅れて届いたAPI・保存結果は、開始時のgenerationと一致するときだけ適用してください。モデル変更の再接続では履歴とスピーカーを保持してマイクをOFF、新しい会話ではモデル・音声・スピーカー・マイク設定を引き継ぎます。

`host` 側の既存画面テストだけではVue部品の操作漏れを検出できません。通信基盤のテストに加え、上記Vue画面検証と `check-chat-effects.mjs` を使い分けてください。

Liveの詳細比較では `host/aidiy_live/src/audio.ts`・`protocol.ts`・`visualizer.ts` の共有だけで同等と判断せず、Vue側の制御も確認します。初回接続では開始画面を消し、新しい会話では開始画面へ戻します。モデル再接続中は「再接続中」、マイクON中は「会話中」を表示します。再送時は前の送信エラーを消し、入力・音声認識の再編集でも会話末尾へ追従させます。

`check-host.mjs` は実際の共通AudioWorkletと疑似ホスト入力を使い、PCM送信、マイクONの新規会話への引継ぎ、準備待ちの中断、ホストからのマイク一時停止、音声だけの変更、保存・接続失敗も確認します。実マイクや外部AIには送信しません。`check-chat-effects.mjs` は旧Live CSSとのボタン・入力欄の描画値比較も行います。

Code / Live / IDEの単独起動時は `host/scripts/window-opening.cjs` の750ms拡大演出を使います。その間は `desktop-opening` クラスでVue画面を隠して開始文字送りを止め、演出後にフェード表示します。Electron検証ではこの一時的な演出専用ウィンドウをアプリ本体として数えず、利用者の起動済み画面と分離した一時プロファイルを使ってください。

Code / Live / IDEの単独Electron起動では `launch.mjs` がサーバーを所有するNodeプロセスを分離し、IPCで画面表示完了を受け取ってから呼出元を終了します。Electron自身のIPCはサーバー所有プロセスとの接続を維持し、画面終了でサーバーも閉じます。`--foreground` / `--wait`、ブラウザ版、`--no-open` / `--serve` は分離しません。`scripts/check-launcher.mjs code` / `scripts/check-launcher.mjs live` / `scripts/check-launcher.mjs ide` で、呼出元終了後の継続、再実行での既存窓再利用、×でのプロセス・ポート解放、起動失敗の通知を確認できます。
