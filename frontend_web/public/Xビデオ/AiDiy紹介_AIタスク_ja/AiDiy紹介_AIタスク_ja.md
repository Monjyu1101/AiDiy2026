# AiDiy紹介_AIタスク_ja
テーマ: テーマ: AiDiy の『AIタスク』を、ひとりアバターが紹介するガイド動画を作る。要求を日本語で書くだけで、AI がそれを実行明細へ分解し、依存関係を判断しながら自動実行し、さらに定時実行としてスケジュール運用まで任せられる、という流れを伝える。 【この動画の主役】AIタスク最大の特徴は、要求ごとに『実行開始条件』を持ち、定時実行タスクとして設定できること。一度登録すれば、毎日・毎週・毎月の指定時刻に AI が自分で走り出し、人が居なくても回り続ける。ここを動画の山場として最も厚く扱うこと。 【出典 / 根拠資料】D:/OneDrive/_sandbox/AiDiy2026/backend_taskteam/AGENTS.md, D:/OneDrive/_sandbox/AiDiy2026/AGENTS.md, D:/OneDrive/_sandbox/AiDiy2026/frontend_web/src/components/AIタスク/。記述は現行実装に基づき、実装に無い機能を足さないこと。 【実行基盤】AIタスクは backend_taskteam（ポート 8093）が担当し、API は /task/*。DB は backend_server と同じ _data/AiDiy/database.db を共有する。バックグラウンドでは Task 起動監視が 5 秒間隔、Task 状態監視が 10 秒間隔で回っている。 【実行の流れ（正確に）】(1) Aタスク要求を『準備開始』で仮登録する。(2) Task 起動監視が要求を『準備中』へ進め、task_sub/sub_init.py を起動する。(3) AI が要求を明細へ分解し、開始行・処理行・終了行を本登録する。(4) 先行SEQ がすべて完了した明細を実行可能とし、依存を満たした明細を並行起動する。(5) sub_start.py / sub_proc.py / sub_terminate.py が結果を API へ反映する。(6) 終了明細が完了すると要求が完了になる。 【DAG とフロー図】明細の依存関係はカンバンの固定列ではなく、『先行SEQ』（カンマ区切りで複数指定可）による DAG。直列だけでなく水平の並行分岐を含む自由なタスクフローを定義でき、画面のフロー図は最長経路をクリティカルパスとして配置する。 【実行開始条件（最重要・山場）】Aタスク実行条件はタスクID 単独を主キーに保持し、2 つの軸で指定する。実行区分は『即時 / 時間指定 / 間隔実行 / 定時実行』。間隔実行は間隔区分（分・時・日）＋間隔値、定時実行は定時区分（毎日・毎週・毎月）＋実行曜日 / 実行日 / 開始時刻で指定する。実行条件は『無し / フォルダ変化』で、フォルダ変化は監視フォルダのファイル数と最終更新日時のスナップショット比較で判定する。状態は『準備完了』で条件の充足を待ち、条件が成立すると明細 → 要求の順に『待機』へ戻して再実行する。時間駆動の条件とフォルダ変化の確認は状態監視ループの毎分ゲートで行い、即時だけは 1 分ゲート無しで 10 秒ループの先頭から再実行させる。サーバー停止中に期限を過ぎた条件は、起動時に過去分を一括発火させず次の周期へ更新する。 【操作検証と自動リトライ】処理明細は 1 ステップだけを aidiy_code_agents へ依頼する。『操作検証』を付けた明細は、AI が /task_check_okng へ報告した状態を確認し、書き込みなし・エラーのいずれかなら検証結果を踏まえて 1 回だけ自動リトライする。開始明細は AI を使わず aidiy_backup MCP でプロジェクトの差分バックアップを取る。終了明細は操作検証が false（どの明細もファイル操作なし）なら AI を介さず終了完了、true なら最終検証を依頼する。 【AI モデルの使い分け】TASK_AI_NAME に Code CLI（claude_cli / codex_cli / copilot_cli など）を選び、TASK_AI_MODEL_plan（準備＝AI による明細分解）、TASK_AI_MODEL_do（各ステップの実行）、TASK_AI_MODEL_check（終了時の最終確認）の 3 種を個別に指定できる。計画・実施・確認で別のモデルを割り当てられる点に触れること。 【画面構成】AIタスク画面は 3 パネル構成。左が【タスク要求】一覧（admin限定トグル、新規ボタン、実行有効・状態・PID・開始日時）、中央が【フロー図】（クリティカルパスを下部に表示）、右が【タスク明細】一覧（SEQ・先行SEQ・操作検証・実行有効・状態・PID・開始日時）。要求を選ぶとフロー図と明細が連動して切り替わる。 【実運用例】実際に、毎日 12 時の定時実行で『最新の AI ニュースを収集し、解説動画の HTML ページを自動生成する』14 ステップのタスクが動いている。Grok最新AIニュース調査 → 解説動画設定更新 → Step00初期確認 → Step01フォルダ作成 → Step02シナリオ作成 → Step03HTML修正 → Step04画像生成 → Step05中間確認 → Step06音声生成 → Step07再生時間更新 → Step08最終確認 → Step99完成案内 → 終了、という流れを人が触らずに完走する。この紹介動画自体も同じ AiDiy の仕組みで作られていることを添えること。 【シーン構成】最小構成 7 シーンで生成すること。scene_000（イントロ: 要求を書くだけで AI が手順に分解して自動実行し、しかも決めた時刻に勝手に動き出す、というつかみ）、scene_001（要求を登録する: 要求内容とプロジェクト / フォルダ指定、TASK_AI と plan・do・check の 3 モデル、実行有効）、scene_002（AI が明細へ自動分解: 準備開始から待機までの状態遷移と、開始行・処理行・終了行の役割）、scene_003（依存を判断して実行: 先行SEQ による DAG、並行分岐、クリティカルパス表示のフロー図）、scene_004（★山場: 実行開始条件。即時・時間指定・間隔実行・定時実行と、無し・フォルダ変化。毎分ゲートでの判定と、準備完了から待機へ戻して再実行する仕組み）、scene_005（実運用例と信頼性: 毎日 12 時のニュース解説動画自動生成 14 ステップ、操作検証と 1 回の自動リトライ、開始時の差分バックアップ）、scene_999（まとめ）の計 7 シーン。scene_006 以降は作成しない。 【表現方針】専門用語を並べるのではなく、『要求を書く → AI が手順に割る → 順番と並行を判断して実行する → 決めた時刻に勝手に始まる』という体験の流れで語ること。誇張せず、実装にある機能だけを述べる。定時実行の説明では、朝の情報収集、日次のレポート作成、フォルダに資料が置かれたら処理を始める、といった身近な使いどころを挙げてよい。 scene_999 のまとめ末尾ナレーションには必ず次の 3 要素を含めること: (1) この動画が AiDiy で自動生成された旨の説明、(2) チャンネル登録のお願い、(3) AiDiy を使ってみたくなる誘導。締めの音声は female ボイスにする。 （参考: 生成パイプライン）topic から scenario.js 生成 → 画像生成 → 音声合成 → duration 計測まで全自動。Step 02: scenario.js 生成、Step 03: index.html 更新、Step 04: 画像生成、Step 06: TTS 音声合成、Step 07: duration 計測。
