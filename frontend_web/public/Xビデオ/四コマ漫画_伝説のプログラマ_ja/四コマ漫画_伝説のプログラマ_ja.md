# 四コマ漫画_伝説のプログラマ_ja
テーマ: タイトル『伝説のプログラマ』の四コマ漫画を、一人の語り手がテンポよく読み聞かせる日本語の小話動画を作る。 コピー元は完成済みの『小説解説_AiDiy誕生_ja』とし、index.html、scenario.js、scene HTML、scene-layout.js、scene-overlay.css、short/long narration、short/long audio の mcp 構造をそのまま踏襲する。four-panel-manga-v1 や専用プレイヤーは使わない。 全7シーン構成を厳守する。scene_000=導入、scene_001〜scene_004=漫画の第1コマ〜第4コマ、scene_005=オチの余韻、scene_999=まとめと締め。四コマ本編の順番や台詞を変えず、余分な漫画コマを追加しない。 scene_000 は『伝説のプログラマ』という題名と、どんな難題も一瞬で片づける人物へ依頼が持ち込まれた、という短い導入にする。まだ解決方法やオチは明かさない。 scene_001 は第1コマ。困った依頼者が画面を見せ、『このプログラムのコンパイルエラー消しといて』と依頼する。headline にこの台詞をそのまま入れ、画像は明るい開発オフィスで同じ二人の人物を描く。 scene_002 は第2コマ。伝説のプログラマが落ち着いて『できました。』と報告する。headline にこの台詞をそのまま入れる。解決方法はまだ明かさない。 scene_003 は第3コマ。依頼者が不審な画面を見て、『なんか動きがおかしいんだけど』と指摘する。headline にこの台詞をそのまま入れる。原因はまだ明かさない。 scene_004 は第4コマでオチ。伝説のプログラマが悪びれず、『コンパイルエラーのところ（ソース）消しときました！』と答える。headline にこの台詞をそのまま入れ、エラー箇所ごとソースを消したため動作がおかしくなったことが一目で伝わる漫画絵にする。 scene_005 は四コマの後の短い余韻。依頼者が絶句し、語り手が『エラーを消す』を文字どおり実行した勘違いを一言で振り返る。新しい出来事や第五のコマは追加せず、最後は必ず『ちゃんちゃん。』で締める。 scene_999 は小話全体を短くまとめ、チャンネル登録のお願いと『この動画は AiDiy のビデオページ生成で作りました』という一言だけを添える。四コマの台詞を改変したり、新たなオチを追加したりしない。 各 scene は AiDiy誕生と同じ必須フィールドだけを基本とし、content_type、manga_title、panel_count、panel_layout、panel_number、page_number、display_order、speech_bubbles、dialogue_text、audio、duration_sec、hero_image_focus、background_word など四コマ専用キーを追加しない。 全ページの expression は neutral。chips、metrics、cards、facts、evidence は空配列。version は mcp。assets_policy は AiDiy誕生と同じ構造を維持し、tts_provider は edge:female にする。 画像は横長16:9のオリジナル漫画調イラストにし、同じ依頼者と同じプログラマが全4コマで同一人物に見えるよう、外見・服装・オフィスを統一する。実在人物、企業ロゴ、製品ロゴ、読める文字、吹き出しを画像へ焼き込まない。台詞はプレイヤーの headline 等で表示する。 scene_004 より前では、ソースを削除したというオチを画像・見出し・ナレーションのどこにも出さない。 『ソースを消しときました』は漫画内の架空の出来事だけを意味する。実プロジェクトのソースコードを削除・改変しない。
