# AiDiy Live

現行画面は `frontend_ide` のVue共通部品です。既存の起動コマンドと拡張IDを維持します。共通画面の変更・起動手順は `frontend_ide/README.md` を参照してください。以下には共通基盤と従来実装の説明も含まれます。

`aidiy_live` は AiDiy のライブ会話だけを使う小さな画面です。表示名は **AiDiy Live** です。独立した VS Code 拡張とスタンドアロンを提供し、`backend_server`（8091）へ接続します。さらに開発スペース（`aidiy_ide`）の部品としても動作し、オンライン利用中は IDE の「＋ Live」から同じプロジェクトで開けます。

## VS Code 拡張

`frontend_ide/host` の `npm run package` で `dist/aidiy-live-0.1.0.vsix` を生成します。共通セットアップでこの拡張を配置できます。手動の場合は VS Code の「VSIX からのインストール」で Live の VSIX だけを選択できます。拡張 ID は `aidiy.aidiy-live` です。

Code / Live はどちらも `workspace` の拡張ホストで動作します。Linux への Remote SSH / WSL / Codespaces 接続では接続先へ配置し、同じ環境の `_cleanup.py` で両方を解除できます。AIコアも接続先で起動してください。サイドバーのマイク入力は Windows の拡張ホストに対応しているため、Linux の拡張ホストでは「専用ウィンドウで開く」からブラウザ版を使います。

旧版の Live を接続元の Windows に配置していた場合、Linux 側の cleanup ではその拡張を解除できません。初回だけ Windows 側の拡張機能一覧から AiDiy Live をアンインストールするか、Windows のターミナルで `code --uninstall-extension aidiy.aidiy-live` を実行してください。更新した VSIX は Code と同じ接続先へ配置します。

コマンドパレットの「AiDiy Live: ライブ会話を開く」で右サイドバーに表示します。この拡張は個別に無効化・解除できます。別のタブへ切り替えて Live の画面を非表示にしても、接続と会話は保持します。非表示中はマイクを停止し、戻った後も OFF のままです。マイクを ON にすると音声入力を再開できます。非表示中に受信した会話は戻ったときに表示し、音声はまとめて再生しません。切断・拡張停止時はマイクと通信を終了し、会話欄と入力欄を初期表示へ戻します。「接続」は黒文字で白〜水色の背景が変化し、接続中の「切断」は白背景と黒文字で表示します。

VS Code の Webview はマイク権限を提供しないため、Windows の入力デバイスから Python 標準ライブラリの `ctypes` / WinMM で取り込み、同じ AudioWorklet 音声処理へ渡します。設定 `aidiyLive.pythonPath` が空なら、作業フォルダまたは親フォルダの `backend_tools/.venv/Scripts/python.exe`、次に PATH の `python` を探します。追加の Python ライブラリは不要です。Windows のマイクアクセスを許可してください。入力デバイスがない場合は画面にエラーを表示します。自動減衰は拡張でも共通ですが、ブラウザ標準のエコーキャンセルはブラウザ版のみです。

接続先の指定は不要です。ローカルのAIコアへ接続し、AiDiy配置先（見つからない場合は作業フォルダと親フォルダ）の `_config/AiDiy_key.json` の `PORT_CORE` を自動参照します。配布済み拡張など設定ファイルを参照できない場合は既定ポート8091を使います。「専用ウィンドウで開く」コマンドは、配布済み Live 拡張のファイルだけでブラウザ版を起動できます。Windows 以外でのマイク入力にもブラウザ版を使用してください。

接続時に、開いているワークスペースのフォルダを `connect` パケットの `CODE_BASE_PATH` で渡し、AI 初期化前にセッションへ設定します。選択したモデルと音声も `connect` の `モデル設定` に含め、最初からその設定で開始します。指定がなければバックエンドの既定設定を使います。単独起動では起動時の作業フォルダを使用します。LiveAI とコードエージェントはそのフォルダを参照し、共通設定ファイルには保存しません。接続先のバックエンドからアクセスできるフォルダを使ってください。接続中に別のプロジェクトへ切り替えると会話を切断し、次の接続で新しいフォルダを反映します。

起動時にバックエンドの `_config/AiDiy_key.json` に基づく Live 設定を取得し、接続前から AI 名・モデル・音声を表示します。モデル未指定なら、最後に画面で確定した AI・モデル・音声を復元します。未保存ならバックエンドの既定設定を使います。FreeAI／Gemini／OpenAI の切り替えでは、それぞれの設定済みモデルと音声が初期値になり、候補一覧にない設定値では選び直しを案内します。起動引数で指定したモデルは保存済み設定より優先します。

接続前に「モデル」を開いて AI・モデル・音声を選び、「選択する」で次回の接続設定を確定できます。接続中の変更は「変更して再接続」です。「キャンセル」で変更を破棄できます。確定した選択はユーザーのホームフォルダの `.aidiy/aidiy_live_model.json` に保存し、VS Code 拡張・単独画面で共用します。切断・画面の終了・別プロジェクトでの再起動後も使用します。起動引数やキャンセルでは保存済み選択を上書きしません。保存失敗時はエラーを表示し、現在の設定と接続を維持します。変更すると音声AIへ自動で再接続し、マイクは OFF に戻ります。画面の会話と入力中のテキストは保持し、音声AIの会話を新しく開始します。「専用ウィンドウで開く」は VS Code のビュータイトルまたはコマンドパレットから実行できます。

マイク OFF でもテキストを送信できます。コードエージェントの結果（`output_request`）も会話欄に表示します。Gemini / FreeAI の音声回答を文字で表示するには、音声字幕に対応する現在の `backend_server` へ更新し、Core API を再起動してください。送信失敗は画面にエラーとして表示します。

## 起動

既存の AiDiy バックエンドを起動しておき、プロジェクトルートで実行します。

セットアップ後は `aidiy_live` コマンドで起動できます。

ルートの `python _start.py` で「フロントエンド(live)」を `y` にすると、画面を開いて自動接続します。最後に手動選択したモデル・音声（未保存ならバックエンドの既定設定）を使い、マイクは OFF のままです。単独コマンドで同じ動作にする場合は `aidiy_live --connect` を使います。接続失敗・手動切断の後は画面の「接続」で再接続してください。

ルートの `vscode_live.bat` は FreeAI／Gemini／OpenAI の音声モデルの選択メニューを表示します。**未入力で Enter を押すと、Provider／モデルの起動引数を付けずに起動し、画面の「接続」で接続します。** 番号を入力した場合は、対応する `--provider` / `--model` を渡し、画面の準備後にそのモデルで自動接続します。マイクは OFF のままです。追加の引数はそのまま転送します。起動後も画面の「モデル」から選択できます。`vscode_live.bat --browser` でブラウザ起動もできます。bat だけを別プロジェクトのルートへコピーして使う場合は、コピー先を作業フォルダにしてセットアップ済みの `aidiy_live` を呼び出します。

モデルを起動時に指定する場合は `--provider` / `--model` 引数を使います。Electron / ブラウザとも指定したモデルで初回に自動接続し、最初の接続パケットの `モデル設定` に反映します。接続に失敗した場合は画面に理由を表示します。直接指定する場合:

```powershell
aidiy_live --provider freeai --model gemini-2.5-flash-native-audio-preview-09-2025
aidiy_live --provider openai --model gpt-realtime-2.1-mini --browser
```

Provider は `freeai` / `gemini` / `openai`（内部名の `freeai_live` / `gemini_live` / `openai_live` も可）を指定します。モデル指定時は Provider も指定してください。Provider だけ指定した場合は、保存済み選択と同じ Provider ならそのモデル・音声を復元し、異なる場合はその Provider のバックエンド既定設定を使います。引数なしの `aidiy_live` は最後の手動選択（未保存ならバックエンドの既定設定）で起動します。どちらも接続は画面から行い、保存済みモデルがあるだけでは自動接続しません。`--project "C:\work\project"` で作業フォルダも指定できます。Electron の子プロセスには環境変数、ブラウザ中継の子プロセスには起動引数で設定を渡します。共通設定ファイルは変更しません。

```powershell
.\frontend_ide/host\aidiy_live.cmd
```

または `frontend_ide/host` で実行します。

```powershell
npm run live
```

Electron は既存の `frontend_ide/host/node_modules` の配置済みバイナリを使います。依存が未導入の場合は従来の `python frontend_ide/host/_setup.py` でセットアップしてください。単独起動では画面・接続処理のソースと生成物を照合し、古い生成物が残っている場合は起動前に自動更新します。手動更新は `npm run live:compile` でも実行できます。VS Code 拡張には VSIX の再生成・再配置が必要です。

専用ウィンドウの初期サイズは Code と同じ476×602、最小サイズは360×480です。Electron が未配置、または起動に失敗した場合はブラウザへ自動で切り替えます。Windows では Chrome / Edge があれば Code のブラウザ版と同じ640×820の専用ウィンドウで開きます。通常起動とブラウザ版起動は、起動後に CMD / PowerShell へ戻ります。ブラウザ中継は別プロセスで動き、最後の画面を閉じて約60秒後に終了します。`--foreground` は起動診断用で、サーバーをターミナルで実行します。

ブラウザで使う場合:

```powershell
npm run live:browser
```

ターミナル上で実行したい場合は `npm run live -- --browser --foreground` を使い、Ctrl+C でサーバーを終了します。URL だけを表示する場合は `npm run live -- --serve` を使います。

モデル選択画面に接続先の表示・入力欄はありません。`--backend` と `aidiyLive.backendUrl` は使用しません。ポートを変更する場合は共通設定の `PORT_CORE` を変更し、Core と Live を再起動してください。

AIコアのモデル情報を取得できない場合は、実際の接続先とエラー詳細を表示します。`127.0.0.1:8091` に対する `ECONNREFUSED` なら、そのPCのCore APIが指定ポートで起動しているかを確認してください。これはOpenAIへの接続前の段階です。

## 操作

初期案内は AiDiy ロゴの下に英語の「LET’S START A CONVERSATION」「CONNECT, THEN TURN YOUR MIC ON.」（緑）「YOU CAN ALSO TYPE TO CHAT.」を等幅フォントで順に表示し、各行の文字色のカーソルを点滅させます。Code と同じ12秒周期のタイプ表示（各行の文字送りは1.44秒、次の行まで1.2秒待機）で、文字の入力を始めると全文表示へ切り替えます。

- 上部は「音声会話」「新しい会話」「接続／切断」を1行に並べます。「接続」で新しい専用セッションを開始します。既存 Avatar の会話とは別のセッションです。
- 「音声会話」の横にフォルダ名を表示します。スタンドアロンはコマンドを実行したフォルダ、VS Code は現在のエディターに対応するワークスペース（なければ先頭のローカルフォルダ）を使います。長い名前は省略し、マウスを重ねるとフルパスを表示します。このフォルダは接続時に `CODE_BASE_PATH` としてバックエンドへ渡します（上記「VS Code 拡張」を参照）。
- 未接続時は「接続」ボタンの背景を白と水色の間でゆっくり明滅させます。接続処理中は止め、接続完了後は上部の2pxバーを Code と同じシアン・4.5秒周期で明滅させます。切断するとバーは黒へ戻り、接続ボタンの明滅を再開します。VS Code内では Code と同様に接続状態の文字を含むタイトルバーを省略し、シアンバーを表示します。単独版はタイトルバーを表示します。
- マイクは接続直後 OFF です。「マイク OFF」をクリックすると音声を送信します。初回は OS / ブラウザのマイク許可が必要です。
- スピーカーは未接続・接続処理中・切断後に OFF 表示となり、操作できません。接続完了後に再生設定に応じて ON/OFF を表示し、操作を再生とサーバー側の音声状態へ反映します。
- 背景の円形の音量雲は、AI の発声を水色、マイクを赤色の線で表示します。実音量と周波数に合わせて輪郭が広がり、静かな時は細い輪に戻ります。マイクの周波数は自動減衰前、輪の広がりは減衰後の送信音量を使います。動きを減らす OS 設定では回転・揺れを抑えます。
- 双方向通話中はブラウザ標準のエコーキャンセルに加え、既存 Web 版と同じマイク振幅の自動減衰を行います。AI の実再生音量が `0.01` を超えた場合、入力振幅から「再生音量 × 1.5」を差し引きます。停止・ミュートで解除され、OS のマイク音量は変更しません。
- 文字を入力して「送信」を押すとライブ AI へ送ります。送信ボタンは未接続では灰色、接続済みで空欄・空白だけの入力では白背景・青紫の枠・黒い紙ヒコーキの無効状態で、接続済みかつ送信する文字があるときだけ Code と同じ青紫になり、送信できます。送信後は入力を消して白背景・黒い紙ヒコーキへ戻します。Enter は改行です。
- 会話文字は AIチャットパネルと同じ配色です。手入力（`input_text`）は白 `#ffffff`、音声入力認識（`recognition_input`）は灰色 `#e5e7eb`、通常出力（`output_text`）は緑 `#00ff00`、音声出力認識（`recognition_output`）は淡い緑 `#9ae6b4`、コードエージェントの回答（`output_request`）はシアン `#00ffff` にします。文字送り中のカーソルも本文の色を使い、表示完了後も種別ごとの色を保ちます。
- 入力欄は Code と同じ全幅で、その下に操作説明、接続状態、モデルボタンを並べ、紙飛行機ボタンを右端に置きます。「モデル」で既存サーバーのモデル・音声の候補を開き、未接続時は「選択する」、接続中は「変更して再接続」で切り替えます。共通設定ファイルへの保存やサーバー再起動は行いません。切り替え後のマイクは OFF です。
- 接続中の「新しい会話」は表示と入力をクリアし、同じモデル・音声・作業フォルダの新規セッションへ自動で接続し直します。マイクとスピーカーの ON/OFF は保持します。未接続の場合は表示と入力だけをクリアします。
- 切断・ウィンドウ終了時にはマイクのトラック、再生音声、3つの WebSocket を閉じます。接続断後は「接続」から手動で再接続します。

会話表示は最新100件までです。永続履歴と音声認識は既存バックエンドが担当し、この画面ではローカルへ保存しません。ライブ AI の API キー・モデル設定・音声認識の利用可否も既存バックエンドに従います。現行 AIコア WebSocket / モデル情報 API には JWT を渡す接続仕様がないため、その仕様を使用します。

## 構成

| ファイル | 役割 |
|---|---|
| `src/protocol.ts` | 既存 AIコアの init / input / 0 / audio 接続とパケット |
| `src/audio.ts`, `media/capture.js` | AudioWorklet で入力を16/24kHz PCM16へ変換、24kHz出力を順次再生 |
| `src/visualizer.ts` | 実音声に連動する円形の音量雲を Canvas へ描画 |
| `src/view.ts`, `media/index.html`, `media/style.css` | 会話・音声操作・モデル選択の共通画面 |
| `src/server.ts` | localhost の HTTP / WebSocket 中継。接続先は起動時に固定 |
| `src/extension.ts`, `src/host.ts`, `src/bridge.ts` | 独立 Live 拡張、拡張側の通信、共通画面への IPC |
| `../src/model-preferences.ts` | ユーザーごとの最終手動選択のJSON読込・保存（bundleへ内包） |
| `microphone.py`, `src/microphone-error.ts` | Windows のネイティブマイクを48kHz PCM16で取り込む。マイクエラーの案内文 |
| `desktop.cjs`, `preload.cjs`, `launch.mjs` | Electron の専用ウィンドウと起動処理 |
| `permissions.cjs` | 専用ウィンドウのマイク許可を、専用画面のメインフレームの音声入力だけに限定する |

中継はランダムポート・ランダムURLで `127.0.0.1` にだけ公開し、Host / Origin を照合します。バックエンドへの REST 中継はモデル取得とモデル設定の2経路に限定します。ローカルの `POST model` は Live の AI 名・モデル・音声だけを検証して専用JSONへ保存し、バックエンドへ転送しません。WebSocket は `/core/ws/AIコア` にだけ接続します。

拡張では通信を拡張ホスト側で行い、音声処理・パケット・画面はスタンドアロンと共有します。Live の VSIX に必要な画面、音声処理、マイク補助を含め、Code の VSIX には含めません。

## 検証

### マイクを ON にできない場合

専用ウィンドウの許可判定は URL の `origin` を比較します。Electron が返す末尾 `/` 付きの origin を文字列の完全一致で拒否しないようにし、専用画面のメインフレームからの音声入力だけを許可します。

`Requested device not found` は、実行中の Windows に入力デバイスが見えていない状態です。まず Windows の「設定 → システム → サウンド → 入力」でマイクが選べることを確認します。出力に「リモート オーディオ」があるだけではマイク転送の確認にはなりません。

リモートデスクトップを使う場合は、接続元の「リモート デスクトップ接続」で「オプションの表示 → ローカル リソース → リモート オーディオの設定」を開き、録音側を「このコンピューターで録音する」にして再接続します。接続元のマイクを既定の入力に設定し、接続先のサウンド入力にも現れることを確認してから Live を起動し直します。Windows に入力が見えない状態では、ブラウザ方式でも WinMM 方式でも録音できません。[Microsoft の録音転送手順](https://devblogs.microsoft.com/devops/enable-remote-audio-capture-to-when-testing-or-providing-feedback-on-remote-machines/)も参照してください。

画面には入力デバイスなし、アクセス拒否、録音デバイスを開けない場合を分けて案内します。模擬入力による Electron / AudioWorklet の検証と、実マイクによる確認は区別してください。

`frontend_ide/host` で実行します。

```powershell
npm run live:check
npm run live:test
```

自動検証は模擬バックエンドでセッション、音声パケット、WebSocket 中継、モデル API、切断、Origin 拒否を確認します。実際の会話は、接続後にマイクを ON にし、背景の音量雲・AI音声・会話表示、マイク OFF、スピーカー OFF、音声停止を確認してください。ヘッドホンの使用でスピーカーからの回り込みを抑えられます。

ライブモデル・声の候補と表示順は `_config/AiDiy_live_gemini.json`（Gemini / FreeAI）と `_config/AiDiy_live_openai.json` の `models` / `voices` を基準にします。既存のモデル情報 API から取得し、候補外の保存値や起動指定では接続せず、画面で選び直すよう案内します。声だけの変更も保存・再接続の対象です。候補 JSON の編集後は Core を再起動し、モデル選択画面を開き直してください。

Codespaces のブラウザ版は、ポート転送やブラウザ認証を待てるよう、初回の画面接続までは自動終了しません。一度画面を開いた後は、最後の画面を閉じて約60秒で終了します。起動時は `$BROWSER`（VS Code のブラウザヘルパー）にトークン付き localhost URL を渡し、VS Code にポート転送と外部 URI の解決を任せます。転送先の URL を手で組み立ててヘルパーへ渡さないでください。手動では起動時に表示されるトークン付き URL を開きます。
