# AiDiy IDE（Vue）

Term / Code / Live / IDE の画面をVue 3で共通化します。VS Code拡張はCode / Live、単独実行は4種類です。

## 開発スペース — 宇宙をテーマにした IDE 開発環境

AiDiy IDE は、プロジェクトを宇宙に見立てた **開発スペース** です。フォルダは銀河、ファイルは星・惑星として浮かび、1階層ずつ宇宙を渡り歩いてプロジェクトを把握します。

ソースや文書の星・惑星は、20KB以下で従来の0.5倍、20〜100KBは対数的に拡大し、100KB以上で3倍の大きさにします。画像・音声・動画・3Dファイルは従来の大きさを維持します（1KB＝1024バイト）。

星・惑星・中心星の本体は不透明で、種類をまたいで奥から手前へ描き、重なりで前後関係が分かるようにします。周囲の光は半透明のまま、距離による明暗差も残します。

目指すのは「ソースをほぼ触らない IDE」です。

| 役割 | 開発スペースでの姿 |
|---|---|
| 全体を眺める | 宇宙表示。フォルダの大きさ・ファイルの種類・更新の新しさが、銀河の形・星の色・明るさで見える |
| 正確に辿る | 左上の ☰ で開くエクスプローラー（VS Code 風のツリー）、プロジェクト全体の検索・grep 検索 |
| 中身を読む | 読み取り専用のビューア（コードは Monaco Editor、画像・Office 文書・PDF も表示） |
| 変えてもらう | Code（コード支援チャット）と Live（音声会話）に頼み、変更は AI に任せる |
| 変化を見つける | 起点日時より後に更新されたファイルが明滅し、AI が触った場所がひと目でわかる |

人は書かずに、眺めて・辿って・読んで・頼む。その作業の場を、宇宙という一つの空間にまとめています。

Code / Live は、これまでどおり単独起動（`aidiy_code` / `aidiy_live`）と VS Code 拡張として使えます。そのうえで開発スペースの部品としても動作し、IDE の中から同じプロジェクト・利用モード・セッションのまま呼び出せます（Electron 版は「＋ Code」「＋ Live」で別ウィンドウ、Web 版は画面内タブ）。

| 使い方 | 起動 | 向いている場面 |
|---|---|---|
| 単独起動 | `aidiy_code` / `aidiy_live` | 作業フォルダで AI にすぐ頼みたい時 |
| VS Code 拡張 | セカンダリサイドバー | VS Code でコードを開いたまま頼みたい時 |
| 開発スペースの部品 | `aidiy_ide` の「＋ Code」「＋ Live」 | 宇宙で全体を把握しながら、AI に頼んで変化を確かめたい時 |

同じ部品が3つの場所で動くことで、IDE 開発への応用が広がっています。

## ターミナル（AiDiy Term）

`aidiy_term` は作業フォルダでシェルを開くシンプルな端末です。WindowsはPowerShell、Linux / macOSは `SHELL`（未指定時は `/bin/sh`）を使います。AiDiyコアへの接続は不要です。

- 単独起動: `aidiy_term`。ブラウザなら `aidiy_term --browser`。
- Electron版は画面の作業領域の幅2/3・高さ1/2で、画面下中央に開きます。単独コマンドの再実行も別窓になり、IDEの「＋ Term」と共通で28pxずつ右上へずらします。画面端まで進んだら中央下へ戻ります。
- IDE: 利用開始後の「＋ Term」で別ウィンドウを開きます。複数起動できます。Web版はTermタブです。
- 最初の入力まではCodeと同じアイコン付き初期表示と、画面下部の端末入力欄を表示します。文字入力・貼り付け・キー操作で端末を全体へ広げ、同じシェルと入力を引き継ぎます。「再起動」で初期表示に戻ります。
- ANSIカラー、日本語入力、矢印キー、Ctrl+C、貼り付け、スクロール履歴、ウィンドウサイズへの追従に対応します。文字を選択した状態のCtrl+Cはコピーです。
- 「表示クリア」は端末の表示を消して、アイコン付きの初期画面と下部の入力欄に戻ります。シェルと変数・作業フォルダは維持し、次の入力で再び全体表示になります。`exit`でシェルを終了した後は「再起動」で新しいシェルを開けます。
- タイトルバーとプロジェクトバーはCodeと共通の配置です。「tools接続確認」トグルは既定ONで、tools（既定8095）の応答があればシアンで明滅し、応答がなければ黒になります。OFFでは疎通確認を止め、Codeと同じ赤いバーに切り替えます。端末や実行中のコマンドは維持します。
- Windowsでは下記CLI名だけを入力すると、続きの起動オプションを入力行に薄いグレーで表示します。Tabで確定すると通常の文字になり、Enterで実行します。通常のTab補完は維持し、モデル指定は変更しません。
- Webのタブ切替・パネル非表示ではシェルを維持します。ページ再読込・端末窓の終了・IDEの利用終了ではシェルとその子プロセスを終了します。
- 実行するのはアプリを動かしているPCのシェルです。ファイルビューアの読み取り専用制約とは別で、通常のターミナルと同じ権限でコマンドを実行します。

実装と確認手順は `_AIDIY/knowledge/frontend_ide,Vue共通画面変更手順.md` のTerm節を参照してください。

| 入力 | Tabで追加するオプション（`scripts/cli_bat` 準拠） |
|---|---|
| `codex` | `--dangerously-bypass-approvals-and-sandbox` |
| `claude` | `--dangerously-skip-permissions --chrome` |
| `copilot` | `--allow-all-tools` |
| `agy` | `--dangerously-skip-permissions` |

## 起動

セットアップはリポジトリ直下で `python frontend_ide/_setup.py`。既存の全体セットアップからも共通画面を準備します。
セットアップ済みなら、表示したいフォルダで `aidiy_term`、`aidiy_code`、`aidiy_live`、`aidiy_ide` を実行します。4つのコマンドは共通のVue画面を起動します。IDEの起動名は `aidiy_ide`、アプリ指定は `--app ide` です。

PATH登録なしでも `node <配置先>/frontend_ide/launch.mjs --app ide`（term / code / liveも可）。引数を省略した作業フォルダは実行時のカレントフォルダです。`--project <フォルダ>`、`--browser`、`--no-open`、`--port <番号>`、`--strict-port` に対応します。ポートの既定は0（自動割り当て）。Electronを使えない環境とCodespacesはWebで開きます。Codeの `--offline` はHermesを直接使用します。Liveの `--connect` は初回だけ接続します。

IDEは画面の「AiDiy接続利用」「オフライン利用」で手動開始します。利用開始後にコアとの接続を失っても、ファイル表示・作業起点・Code子窓を維持し、コア復帰時に再接続します。初回接続失敗は手動で再試行します。オフラインではLiveの起動ボタン・タブを表示しません。

宇宙表示の自動飛行は彗星のような楕円軌道を進み、船首は進行方向を向きます。最遠点ごとに接近方向と軌道の傾きを少し変え、星々の内側を通過します。再開時は現在地で進路へ向き直ってから前進します。ファイル選択中・フォルダ移動中は停止し、手動操作後は最後の操作から1分停止します。ドラッグだけは例外として中心星を軸に回り込み、移動後の位置・向きを宇宙船の現在地として扱います。スペースキーで自動飛行の有効・無効を切り替えられます。

Electron版IDEは右上の「＋ Code」「＋ Live」で別ウィンドウを開きます。プロジェクト・利用モード・セッションをIDEに連携させます。「終了」はそこから開いたCode / Liveと各通信を終了し、IDEの起動画面へ戻ります。タイトルバーの×は、利用中（「AiDiy接続利用」「オフライン利用」の開始後）だけ「AiDiy IDE を終了しますか？」と確認し、「終了する」でIDEと子窓をすべて閉じます。「キャンセル」では作業を維持します。初期画面と、「終了」で起動画面へ戻った後の×は確認せずに閉じます。利用セッションの切り替えでも別窓を閉じます。`start`のCtrl+Cによるコア停止では別窓を閉じません。別窓のCodeから接続モードは変更できません。Code / Liveだけを個別に閉じることもできます。Web版・Codespacesは従来通り画面内のCode / Liveタブを使います。

ファイルビューアの見出しには「📌（ピン留め）」と「⟳（更新）」があります。📌 を押すと右側のプレビューは閉じ、同じファイルを宇宙パネルの外の独立ウィンドウ（Electron版はIDEの子ウィンドウ「AiDiy IDE / Viewer - ファイル名」、Web版はブラウザの別ウィンドウ）で開きます。何枚でも開けるので、複数のファイルの内容を並べて見られます。同じファイルをもう一度ピン留めすると既存の窓を前面に出します。Electron版のピン留め窓はIDEの利用終了・セッション切り替えで他の子ウィンドウと一緒に閉じます。⟳ はファイルをキャッシュなしで読み直し、AIが更新した直後の内容を確認できます（画像・Office文書・PDFも再読込）。

星空画面の左下には「フィルター」のスイッチがあり、起動時は毎回 ON です。ON の間は宇宙とエクスプローラーの両方を AiDiy のバックアップ対象のファイルだけにします（ルールは `backend_server/AIコア/AIバックアップ.py` と同じ。`backup`・`_data`・`temp`・`log`・`node_modules`・`dist`・`.` 始まりのフォルダ、`package.json` などのロックファイル、`.pyc`・`.log` などを除外）。OFF では従来の一覧（`backup`・`_data` も含む）に戻ります。エクスプローラーの最下部には、表示中の一覧で最後に更新されたファイルを出します（クリックで開く）。約1分ごとに最新だけを問い合わせ直すので、AI がソースを書き換えると1分以内に表示が変わります（画面が裏に隠れている間は問い合わせません）。

起動するとオープニングのワープ（約1.8秒）で宇宙へ入ります。自動探索が ON なら、続けて起動時点の最終更新ファイル（前日のものでも）へ飛んでいって開きます。その後も自動探索が ON の間に最終更新が新しいファイルへ変わると（フィルター ON の時だけ）、宇宙はそのファイルを追いかけます。自動で開いたファイルを表示中ならビューアを閉じ、宇宙を読み直してから（AI が新しく作ったファイルも星として現れます）共通の親フォルダまで戻り、そこから1階層ずつ「その場で目的地へ旋回 → 正面へズーム接近 → ワープ」で潜って、着いたらファイルを右に表示します。手動操作の直後（1分間）や、自分で開いたファイルを見ている間は追いかけません。この流れで開いたファイルは、閉じても元の階層へ戻らず、その場で自動飛行に戻ります。

ワープは宇宙船に乗った視点で、約1.1秒かけてその場で目的地へ向きを合わせてから、正面を保って前進します。親フォルダへ戻る時もゲートへ向いてから進みます。星の光跡は従来の約1.8倍で、階層切替のフェード中も維持します。エクスプローラーのファイル・フォルダ選択でも同じワープを使います。別の枝へは共通の親を経由して1階層ずつ進み、別階層のファイルは旋回・ズームして到着後にプレビューを開きます。同じ階層のファイル選択は、その場で目的ファイルへ旋回してから直進し、到着後にプレビューを開きます。暗転・ぼかし・拡縮・ワープ光跡は入れません。移動中に選び直すと最後の選択を優先します。自動運転の最後のファイル接近や星の直接選択も、同じ旋回・前進を使います。プレビューを閉じても現在の階層・船体位置・船首方向を保ちます。パネル開閉時は操縦席から見回す回転で空き領域へ中央を合わせ、宇宙全体を平行移動させません。右下の「高速ワープ」は既定OFFで、ONなら別フォルダのファイルへ1回で飛びます。最終更新の自動追跡も同じ航行規則に従います。

自動運転中（自動探索が ON で、彗星の軌道を飛んでいる・最終更新ファイルへ移動中・自動で開いたファイルを表示中）は、右下の「自動探索」スイッチの枠を光がぐるぐる回ります。ON でも手動操作の直後（1分間）や、自分で開いたファイルを見ている間は回りません。

ピン留めしていない右のビューアは、最後の操作から5分で閉じます。クリック・キー操作・スクロール・再読み込みで5分を数え直します。別のファイルを表示した場合も数え直します。自動探索が ON なら、閉じたらすぐ自動飛行（彗星の軌道）を再開します。宇宙表示へ戻った後は最終更新が変わらない限り、同じファイルへは再び飛びません。最後に自動で到着したファイルを利用中は記憶し、手動操作後の1分待機やOFFからONへの切り替えでも同じファイルへは戻りません。手動でルートや別フォルダへ移動した場合は、その場所で彗星軌道を再開します。彗星軌道での航行中は常に星系の中心を見続け、再開時も滑らかに中心へ向き直します。計算した航行ルートは淡い青の軌道線で表示します。船は軌道面の上から中心を約5度見下ろして飛びます。軌道線は基準軌道を中心寄りへ15%縮めて船の内側に描き、点マークは付けません。最遠点ではいったん止まり、旧軌道を約1.2秒で消してから次の軌道を計算します。「探索軌道計算中」と表示し、中心を見たまま約3.6秒かけて機体を回します。新しい軌道の向きを少し通り過ぎて一度戻し、水平になってから軌道線を約1.2秒で浮かび上がらせ、航行を再開します。手動操作・ファイル表示・ワープ・自動運転OFF時も、ぼかしを伴って軌道線を消します。最終更新が別のファイルに変わった場合は、その新しい対象へ移動します。移動中に別の更新が来た場合も、新しい対象を優先します。

`.html`・`.svg`・`.vue` は見出しの「コード / 表示」で、ソースと実際の表示を切り替えられます（HTML/Vueの既定はコード、SVGは表示。最後に選んだ方を種類ごとに記憶）。

- HTML / SVG: IDEのサーバーとは別ポート（別オリジン）の「なんちゃって」静的サーバーで表示します。最初の「表示」で起動し、IDEを閉じると一緒に止まります。ファイルは書き出さないので、閉じてもゴミは残りません。ページのスクリプトはサンドボックスの中で動き、IDEのファイルAPIには届きません。`_config`・`.env` などの隠しファイル・鍵らしいファイル・`node_modules`・`.venv`・`backup` は配りません。SVGも画像の埋め込みではなく文書として開き、`images/…`・`../…` の画像やCSS・外部SVGを元ファイルのフォルダ基準で読み込みます。相対パスはそのまま、`/…` 始まりは `public` フォルダを根として解決します。音声・動画の途中再生（Range）に対応し、Electron版は自動再生を許可します。外部CDNを使うページはネット接続が必要です。
- Vue: `frontend_web/src` の `.vue` は、`frontend_web` の開発サーバー（8090）が動いている時だけ、その部品を使っている画面（ルート）を表示します。部品ならimportをたどって画面を探し、候補が複数あれば選べます。ログインが必要な画面ではログイン画面が出ます（IDEのログイン状態はブラウザと別です）。開発サーバーが止まっている時は理由と起動方法を表示します。

Term / Code / Live / IDEの単独Electron起動は、画面表示後にコマンドプロンプトへ戻ります。サーバーと画面は独立して動作し、×で画面を閉じるとサーバーも終了します。Code / Live / IDEは起動済みなら既存画面を前面へ出し、Termは独立した別窓を開きます。終了までコマンドを待機させる場合は各コマンドへ `--foreground`（または `--wait`）を付けます。`--browser`、`--no-open`、`--serve` は従来どおりサーバーを前面で動かします。

## AiDiy検索と軌跡

AiDiy検索を選んでいる間はファイルツリー・ルート行・最終更新行を隠し、検索入力・履歴・結果にパネル全体を使います。起点検索・grep検索へ戻すとツリーを再表示し、検索結果や軌跡は保持します。

エクスプローラーの「AiDiy検索」に「認証機能に関わるファイル」などを入力し、「AiDiy検索を依頼」を押します。`aidiy_code_agents`（backend_tools）の設定済みエージェントに読み取り調査を依頼し、最大5分間、プロジェクトルートの `temp/yyyymmdd_hhmmss_result.json` を確認します。オフライン利用でもbackend_toolsとコードエージェントが利用できれば検索できます。

有効な結果を受け取ると、ファイルと親フォルダをマークし、エクスプローラー右側の「AiDiy検索軌跡」へ切り替えます。水色の軌跡は各階層の入口から関連フォルダ・ファイルへ繋がります。理由付き一覧や「‹」「›」から指定順に辿れ、「ルート」でプロジェクトの入口へ戻れます。結果の受信だけではワープしません。「閲覧軌跡」に戻してもAI結果は残ります。

AiDiy検索の「履歴」から、検索日時・検索文・件数を確認し、過去の結果へ切り替えられます。選択すると理由一覧・マーキング・AiDiy検索軌跡を復元し、視点は動かしません。「削除」は確認後に履歴だけを削除し、調査対象ファイルとtempの元JSONは残します。検索中は履歴の切替・削除を停止します。

「閲覧軌跡」「AiDiy検索軌跡」のボタンを押すと、その直下にファイル一覧を開きます。閲覧軌跡は最近開いた順、AiDiy検索軌跡は検索結果の順です。ファイル名のクリックや「‹」「›」で移動・表示でき、エクスプローラーを閉じていても使えます。同じボタンの再クリック、一覧外のクリック、Escで一覧を閉じます。

成功結果はプロジェクト内の `_AIDIY/aidiy_ide/file_searches/` に保存するため（旧版の `.aidiy/ai-search/` は初回に自動で移します）、再起動・ポート変更・Electron/Web切替後も同じプロジェクトの履歴を利用できます。最後に選んだ履歴はブラウザごとに覚え、新しいブラウザでは最新の結果を読み込みます。旧版のtemp内に依頼文（`.request`）と有効な結果JSONが揃っていれば、自動で履歴へ取り込みます。削除した履歴は再取込しません。保存後に対象ファイルが消えても検索当時の理由・順序は保持し、一覧にない件数を表示します。

失敗・期限切れでは前回のAiDiy検索軌跡を残します。画面の「依頼文をコピー」でエージェントを手動実行でき、遅れて完成した結果も「結果を再確認」で取り込めます。バックアップ対象フィルターで隠れている関連ファイルは、フィルターをOFFにして確認してください。

結果JSONは `requestId`・`query`・`files: [{path, reason}]`・`route: [path, ...]` を持ちます。依頼文に今回のID・検索文・保存先を記載し、ファイルは相対パス、routeはその全パスを辿る順に1回ずつ指定します。最大500件・1MBで、実在するプロジェクト内ファイルだけを受け付けます。書きかけを読まないよう `.tmp` へ保存してから指定名へ変更します。同秒の依頼との衝突を防ぐ `.request` ファイルには依頼文を残します。

## 更新履歴

ソース表示では、対応するバックアップがあれば「更新履歴」ボタンを表示します。開いた比較画面で保存日時を選ぶと、左に旧版、右に現在のファイルを表示します。未変更行の高さを揃え、左右のスクロールを同期します。比較は読み取り専用で、元のビューアが閉じても比較画面は残ります。

対象はプロジェクト直下と対象ファイルの祖先フォルダにある `backup/YYYYMMDD/HHMMSS[.all]/元の相対パス` です。旧版・現在それぞれ1MBまでのUTF-8 / Shift_JISテキストを比較します。大きすぎるファイルやバイナリは理由を表示し、一部だけの比較は行いません。

## AiDiy解析

ファイルビューア上部の「AiDiy分析」ボタンを押すと解析ダイアログを開きます。上部は編集可能な解析指示、下部は前回の解析本文と日時です。初回はソース類に機能概要、画像類に内容・構図・配色・文字・用途の指示例を表示します。前回の指示があれば、ファイルの種類よりもそちらを優先します。

「解析を実行」で既存の `aidiy_code_agents` に依頼し、最大5分間結果を確認します。指示と最新の成功結果はプロジェクト内 `_AIDIY/aidiy_ide/file_analyses/` にファイルごとに保存し（旧版の `.aidiy/file-analysis/` は初回に自動で移します）、再起動後も復元します。ダイアログを閉じても起動中のIDEサーバーが結果を保存します。再解析の失敗では前回結果を残し、解析後のファイル更新は注意表示します。

検証は `npm test` と、ルートから `node frontend_ide/scripts/check-file-analysis.mjs`。後者は模擬エージェントを使い、日時・連番付き画像を `temp/file-analysis-check/` に保存します。

- 共通テスト: このフォルダで `npm test`。

- Vueホストの操作検証: ルートで `node frontend_ide/scripts/check-host.mjs`（模擬VS Code接続、AI通信なし）。履歴・モデル・検証回数・音声設定引継ぎと遅延応答を確認し、`nn-audit-*.png` を保存します。
- Code / Live の演出確認: ルートで `node frontend_ide/scripts/check-chat-effects.mjs`。初期文字送り、紙ヒコーキ画像、入力枠の飛行、処理中の上下バー、中央回答から履歴への着地、連続受信・会話切替を実ブラウザで検証し、`nn-effects-*.png` を保存します。旧 `frontend_vscode` がある場合は参照画面も読取専用で撮影します。
- 単独窓の二重起動・前面復帰: `node frontend_ide/scripts/check-single-instance.mjs`（実行中の利用者画面とは別の一時プロファイルで確認）。
- Code / Live / IDEランチャーの分離起動: `node frontend_ide/scripts/check-launcher.mjs code` / `node frontend_ide/scripts/check-launcher.mjs live` / `node frontend_ide/scripts/check-launcher.mjs ide`（プロンプト復帰後の画面・サーバー継続、二重起動、×での終了、待機指定、起動失敗の通知を一時プロファイルで確認）。
- IDEの別ウィンドウ検証: `node frontend_ide/scripts/check-windows.mjs`（起動制限・プロジェクト引継ぎ・利用終了・全窓終了・疑似音声）。
- コア停止時の作業継続・IDE終了操作: `node frontend_ide/scripts/check-core-stop.mjs`（検証用コアだけを停止・再起動し、IDEのファイル表示、Codeの窓・下書き、作業起点を維持。「終了」でCode / Liveを閉じて起動画面へ戻り、再利用できることと、×の確認取消・承認・重複防止・後片付けを実Electronで確認。OS確認ダイアログの選択だけはテストで代行）。
- 航行の確認: `node frontend_ide/scripts/check-warp.mjs` と `node frontend_ide/scripts/check-autodrive.mjs`（実ブラウザで旋回・直進・手動ドラッグの周回・自動追跡・5分消去・縦横配置を検証。日時と連番付き画像を `temp/space-layout-check/` と `temp/autodrive-check/` へ保存）。彗星軌道の実座標と進行方向は `frontend_ide` で `npm test` を実行して確認します。
- Electron・音声権限の確認: `node frontend_ide/scripts/check-electron.mjs`（疑似音声デバイス）。
- 同じ Electron 確認で、タイトルバーの最大化／元のサイズへの復元も実ウィンドウで検証します。
- 音声・バックエンドの回帰確認: `frontend_ide/host` の `npm test` / `npm run live:test`、`frontend_ide/viewer` の `npm test`。

全体のsetup・cleanupは「IDE群(Term / Code / Live / IDE)」を一括選択します。startは同じIDE群の中でTerm → Code → Live → IDEを個別に選び、その後にDiscordを選びます。セットアップで稼働中の画面を停止しません。cleanupはTerm → Code → Live → IDE → 共通UIの順に解除し、停止・解除に失敗した場合は共通のnode_modulesとdistを残します。

## ウィンドウ配置

Electron版は現在の画面の作業領域（タスクバーを除く）に合わせ、IDEを余白付きで大きく開きます。Code / Live は幅480 × 高さ600（最小360 × 480、Electronの論理ピクセル）です。寸法は `host/scripts/window-size.cjs` を共用し、収まらない小画面だけ縮小します。単独版は画面上端から8px、Codeを左端から8px、Liveを右端から8pxに開きます。IDEから開くCode / LiveはIDEの左右端から24px内側に置き、上端をどちらもIDEから36px下へずらし、Code / Liveの上端と高さを揃えます。IDE配下のタイトルは「AiDiy IDE / Code」「AiDiy IDE / Live」です。移動済みの窓を再選択しても配置を戻しません。

Code / Live / IDEの単独版は種類ごとに二重起動を防ぎ、起動済みの窓を復元して前面に出します。Termは単独版も複数起動できます。IDEから開いたCode / Liveは常に最前面に表示します。IDE連携の「＋Code」は依頼ごとに別窓を開き、2窓目以降を少しずらして配置します。「＋Live」はオンライン時だけ利用でき、初期化中も含めて1窓に制限します。Live起動後はボタンを隠し、閉じると再表示します。IDEの明示終了に連動して子窓を終了します。
