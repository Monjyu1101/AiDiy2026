# AiDiy 診断

外部プログラムの導入状態を、ソースに記載された利用箇所と一緒に確認します。診断サーバー・インストール確認・キー設定・モデル確認は Node.js 18 以降の標準モジュールで動作します。診断の実行に Python は不要です。通常は Electron ウィンドウで表示し、--browser / Codespaces / GUI のない環境では Web で表示します。AIコア / DB の起動は不要です。

診断本体の起動には Node.js が必要です。一覧は Python、uv、Node.js、npm、npx、Electron の順です。Python はバックエンドで使用します。Python が無くても配置済みランチャー・直接 Node 起動は使えます。全体セットアップは既存方式に合わせ Python を使用します。

## フォルダ構成

ルート直下は公開起動入口とセットアップ・設定・案内だけにします。内部モジュールを追加するときは、担当する機能のフォルダへ置きます。

- `diag_main.mjs` / `aidiy_diag` / `aidiy_diag.cmd`: 外部から使う起動入口。
- `起動/`: Electron ウィンドウ・preload・起動監視・安全な診断ログ。
- `診断/`: インストール確認、MCP 状態、headless 実行、カタログと調査範囲。
- `導入管理/`: 固定 npm / Windows WinGet / Antigravity / Grok Build の明示導入・再導入・削除（項目単位で並行実行）と、終了後の個別確認。
- `モデル情報/`: キー確認、モデル・音声 JSON の合成、公開モデル一覧。`openrouter_models/` はこの機能専用の同梱キャッシュです。
- `runtime/`: モデル判定・通信の TypeScript と配布用 `.mjs`。
- `ui/` / `static/`: Vue ソース・ビルド設定と配布画面。
- `checks/` / `reference/`: 回帰テストとソース調査資料。

Electron の依存物は引き続き `backend_diag/node_modules/`、停止要求・安全ログも従来のルート直下に置きます。診断結果の保存先 `_AIDIY/aidiy_diag/` は変わりません。内部モジュールの移動時は import だけでなく、`import.meta.url` 基準のデータ・実行ファイル・リポジトリ位置とテスト fixture のコピー先も確認します。

画面の機能フォルダ・Vue パネル・状態管理・表示モジュールはタブ名に揃えます。共有のキー状態管理は `ui/src/キー設定共通/` を使います。

| タブ（左から） | 見出し | 主操作 | Vue 機能フォルダ |
|---|---|---|---|
| 導入状況 | 導入状況 | 状況確認・各行の確認・対応項目の導入管理 | `ui/src/導入状況/` |
| モデル一覧 | モデル一覧取得 | 一括取得 | `ui/src/モデル一覧/` |
| 外部連携 | 外部連携確認 | 状況確認（テストできる行を順次確認）・書込 | `ui/src/外部連携/` |
| 設定モデル | モデル動作確認 | 動作確認（全行を順次確認） | `ui/src/設定モデル/` |

外部連携は見出し行の「状況確認」（テストできる行を上から順に）と各行の「テスト」で、読み取り専用の認証確認を明示操作時だけ行います（下記「外部連携の認証確認」）。「書込」は直前の確認結果を `_AIDIY/aidiy_diag/integration_info.json` へ保存します。キー未設定・設定読込不可の行は確認せず、未実施と理由を表示します。設定モデルは見出し行の「再読込」と各行の「テスト」も使用できます。

右上ボタンの一括処理（各画面の状況確認・一括取得・動作確認）が終わると、一覧の1項目目を表示し、一覧・詳細を先頭までスクロールします。各行の「確認」「テスト」や中止では選択を維持します。タブ欄の「全テスト」は、導入状況（状況確認→書込）→モデル一覧（一括取得→書込）→外部連携（状況確認→書込）の順に実行し、実行中の画面へ表示タブを切り替え、終わったら導入状況タブへ切り替えます。外部連携の確認では、直前に読み直した設定を使い、モデル一覧の結果を消しません。API の `モデル試行`・`キー設定`・`診断`、タブ内部ID、保存JSON名は表示名とは別の互換識別子として維持します。

## 起動

```sh
node backend_diag/diag_main.mjs --browser
# ランチャー配置後
aidiy_diag                  # Electron 表示後、コマンドプロンプトへ戻る
aidiy_diag --browser        # ブラウザ起動・foreground
aidiy_diag --foreground     # Electron を foreground で起動（ログ・Ctrl+C）
aidiy_diag --wait           # --foreground と同じ
aidiy_diag --headless       # 画面を開かず全診断を最速で実行し、結果を保存
aidiy_diag --auto           # 画面を開き、保存済みの起動設定で「設定起動」を自動実行
```

`--auto` は表示系の指定（`--browser` / `--foreground` など）と併用できます。画面表示と並行して、システム起動タブの「設定起動」と同じ処理を1回だけ実行します。各機能の環境確認と、Tools 起動前の headless 診断もこの中で行います。直前の停止でポート解放が遅れている間は最大約10秒待って再試行し、それでも稼働中・未確認の機能が残る場合は起動せず、理由をシステム起動タブの通知に表示します。起動後は、Tools が稼働していればアプリ起動・ランチャーからそのまま各アプリを開けます。

`--headless` は Electron・ブラウザ・HTTP 待受を使わず、全診断をコマンドラインで最速実行します（全項目を同時に確認し、結果は一覧順に表示）。全診断はインストール状況とモデル情報です。インストール状況は `_AIDIY/aidiy_diag/install_info.json`（状態・パス・バージョン・説明と集計）へ、モデル情報はテストできるプロバイダごとに `_AIDIY/aidiy_diag/<プロバイダ>_models_info.json` へ保存します。保存は一時ファイルからの置き換えで行い、例外・Ctrl+C・書込失敗など実行に失敗した場合は既存ファイルを更新しません。項目ごとの `未検出` / `ERR` などは診断結果として保存します。終了コードは成功 0、失敗 1、中断 130 です。`--headless` は他の引数と併用できません。

画面では「状況確認」で全項目が「確認中」で回り、確認が終わった項目から結果へ切り替わります（確認中は固定の `GET api/診断/進捗` で完了済みの結果だけを読みます。引数は受け付けません）。応答後は上から順に選択が追従し、最後に1項目目を表示します。確認が終わると「書込」が押せるようになり、このサーバーが直前に確認した結果を `--headless` と同じ形式で `_AIDIY/aidiy_diag/install_info.json` へ保存します（画面から値は送りません）。タブ欄の「全テスト」は、状況確認→書込のあと、一括取得→モデル情報の書込、外部連携の状況確認→書込まで続けて実行します。

各項目の「確認」は、そのプログラムだけのパス・バージョン・状態・確認日時を再取得します。他の行の結果を消さず、押した行の詳細を表示し、完了後も一覧の先頭へ戻りません。実行中に別の項目やタブを選んだ場合も、その選択を維持します。確認中は対象行だけ「確認中」とし、個別確認・状況確認・書込・全テストの重複操作を抑止します。通信失敗時は前の表示を維持し、通知後に再試行できます。

個別確認では自動保存しません。一括確認済みなら、個別更新した結果も次の「書込」に含めます。一括確認していない場合は、今回の起動中に全項目を個別確認するまで書込できません。保存済みの前回結果を表示しているだけの行は、今回確認済みとして扱いません。認証付き `POST api/診断/<登録済みID>` はカタログ内の1項目だけを既存の固定 probe で確認し、本文・クエリ・任意コマンドは受け付けません。

### 各項目の導入・再導入・削除

各項目の1行目は左に名称、右に「確認」と状態を表示します。安全な導入方法と所有元を確認できた項目だけ、2行目の左に「導入」または「再導入」「削除」を表示します。初期表示・全テスト・headless は導入操作を実行しません。

| 対象 | 導入方法・制限 |
|---|---|
| Claude Code / Codex / Copilot / OpenCode | 固定 npm グローバルパッケージ（OpenCode は 2.x の公式名 `@opencode/cli`）。標準 prefix / root と実体・shim を照合します。 |
| FFmpeg 一式 | Windows の `Gyan.FFmpeg`。ffmpeg / ffprobe / ffplay のどの行からもパッケージ操作は1回だけ。終了後は3行を各1回確認します。 |
| Ollama | Windows の `Ollama.Ollama` の新規導入のみ。モデル保持を保証できないため再導入・削除は表示しません。 |
| Chrome | Windows の `Google.Chrome` の新規導入のみ。プロファイル・拡張機能を保護するため再導入・削除は表示しません。 |
| OBS | Windows の `OBSProject.OBSStudio`。標準配置と導入記録を確認できる場合のみ再導入・削除。設定・プロファイル・シーンを保持しますが、OBS 本体内の追加プラグインは再導入が必要になる場合があります。 |
| Antigravity CLI | Windows の公式 `https://antigravity.google/cli/install.cmd`。標準の `%LOCALAPPDATA%\agy\bin\agy.exe` の Google 署名（製品情報がある版はその一致も）または一致する導入記録を照合します。 |
| Grok Build | Windows の公式 `https://x.ai/cli/install.ps1`（stable）。`~/.grok/bin` の grok.exe / agent.exe（配布がある版は grove 系も）の X.AI / X Corp. 署名を照合します。 |

ベース（Python / uv / Node.js / npm / npx / Electron）と VS Code は手動導入とし、導入ボタンを出しません。一覧での表示・確認・バージョン表記はほかの項目と同じです。

WinGet の一覧に出るだけでは所有確認にしません。公式 source、登録されたパッケージ・導入先・実行ファイル・アンインストーラーを照合し、native アプリはこの Diag が導入して記録したものだけを変更します。App Installer の `winget.exe` は実行エイリアスのため、標準位置（`%LOCALAPPDATA%\Microsoft\WindowsApps`）だけ lstat で存在を確認して使います。別の PATH 上の実行ファイル、手動導入、複数 scope、portable / Insiders、リンク・junction・所有不明の場合は再導入・削除を出しません。稼働中の対象・関連プロセスは利用者が終了してから再確認してください。自動でアプリを終了しません。Windows 以外の追加対象は確認だけです。

Grok Build の公式インストーラーは削除用のサブコマンドを持ちません。再導入では所有確認済みの実行ファイルを退避してから実行し、失敗・中止時は元に戻します。公式インストーラーは `~/.grok/config.toml` の `[cli]` installer 行を更新し、ユーザー PATH に `~/.grok/bin` が無ければ追加します。`GROK_*` の環境変数は渡さず、stable と既定の導入先に固定します。削除は署名を確認した実行ファイルだけを対象とし、認証・設定・セッション・PATH・同梱 git（`%LOCALAPPDATA%\grok`）を残します。レビュー済み installer の SHA256 が変わった場合は安全確認の更新まで停止します。

Antigravity の公式インストーラーは既存バイナリがあると何もしないため、再導入では所有確認済みの `agy.exe` だけを退避してから実行し、公式 SHA512 を確認します。失敗・中止時は旧バイナリを復元し、未確認の出力や復旧が必要な退避ファイルを推測で削除しません。公式の `--skip-path --skip-aliases` を指定し、`.gemini/antigravity-cli`・認証・OS 資格情報を保持します。フォルダ全体の削除、共有 staging の削除、PATH の一括編集はしません。レビュー済み installer の SHA256 が変わった場合は安全確認の更新まで停止します。公式の [導入オプション](https://www.antigravity.google/docs/cli/install/) を参照してください。

操作前に対象・一式の範囲・影響・提供元の案内を確認します。npm の再導入は同じ固定パッケージへ `npm install --global` を1回実行して更新し、事前に削除しません。「削除」だけが `npm uninstall --global` を実行します。WinGet の再導入は従来どおり削除後に導入するため、失敗・中止すると本体が未導入になることがあります。WinGet の標準インストーラーが PATH 登録や OS の管理者承認を求める場合がありますが、利用規約への自動同意・権限回避・再起動・任意のコマンド入力は行いません。認証・利用者設定・履歴を削除するコマンドは実行しません。

右パネルは共通の実行コンソールへ切り替わり、完了・失敗・中止後に「確認」ボタンと同じ固定 probe と結果反映を対象ごとに1回実行します。FFmpeg 一式では3行の結果を同じコンソールへ表示します。別項目・タブへ移った場合はその選択を維持し、新しい個別確認結果を古い実行結果で巻き戻しません。自動保存やモデル・認証試験は行いません。

コマンドはサーバーの固定 ID 対応表だけから構築し、本文・クエリ・クライアント指定コマンドは受け付けません。秘密値を継承しない実行環境、1コマンド5分・出力4 MiB、表示ログ120,000文字の上限を使用します。npm は公式 registry と空の一時 npm 設定、WinGet は照合済み公式 source、Antigravity は固定の公式 URL と検証済み installer を使います。導入操作は項目ごとに独立して実行し、別の項目とは並行できます（npm の複数パッケージ導入も `_setup.py` の並列導入と同じ扱いです）。押せなくなるのは、実行中・受付中の項目（FFmpeg は3行一式）のボタンと、診断・書込・全テストだけです。実行中の各項目は導入状況パネル上部に並べて表示し、コンソールは項目ごとに分かれます。同じ Diag の診断・書込と排他し、同じ OS 利用者が起動した別 Diag とは同一導入先の同一パッケージ（項目）単位で排他します。別 OS 利用者との競合は WinGet 自身の制御に従い、共用フォルダの権限は変更しません。停止未確認中はロックを解除しません。

検証は合成プロセス・一時 fixture・Vue イベントで行い、実際のグローバル導入・削除は行いません。実 Windows のインストーラー・UAC・実アプリ・実ブラウザ画面は別途確認が必要です。詳しくは [環境診断運用](../_AIDIY/knowledge/backend_diag,環境診断運用.md#個別確認と導入管理) を参照してください。

### モデル情報ファイル（`<プロバイダ>_models_info.json`）

キー設定画面の「書込」（一括取得の後に押せます）・「全テスト」・`--headless` で、gemini / freeai / claude / openai / openai_oauth / grok / openrt / ollama / local のうちテストしたものを 1 ファイルずつ保存します。用途の分け方は本体の `get_chat_models` / `get_live_models` / `get_code_models` に合わせています。

保存形式は `形式: 2` です。選択候補は用途にかかわらず「区分名 → `{models}`」で取得できます。例: `chat.gemini_chat.models`、`code.claude_sdk.models`、`live.gemini_live.models`。区分名以下は各プログラムへそのまま渡せるよう `models` だけを持ちます。取得元などの説明や詳細情報はその外側に置きます。旧形式のファイルは次回の「書込」または `--headless` で置き換わります。

- `chat`: API から取得し本体と同じ条件で絞り込んだ一覧。`モデル` は作成日・トークン数・モダリティ付きの詳細配列として残します。選択候補は `gemini_chat` など本体の区分名をキーにした要素の `models` に置き、「モデルID: YYYY/MM/DD - モデルID」の一覧（作成日が無いものは `yyyy/mm/dd`、backend_local は固定候補の表示名）にします。詳細・選択候補とも作成日の新しい順です。Claude / Grok は本体に chat の選択区分がないため詳細だけを残し、CLI の選択候補は `code` に置きます。
- `live`（gemini / freeai / openai）: API で取得した live 対応モデル（Gemini は `bidiGenerateContent` 対応、OpenAI は `realtime`）から、`gemini_live` などの区分名をキーにした要素の `models` を直接生成します。Gemini / FreeAI はモデルIDに `native-audio` または `live` を含み、`transcribe` または `translate` を含むものを除外し、モデルIDの文字列降順で並べます。OpenAI は `whisper` または `translate` を含むものを除外し、作成日の新しい順です。表示名は「YYYY/MM/DD - モデルID」で、日付は API / OpenRouter の作成日 → モデル名の日付 → `yyyy/mm/dd` の順に採用します。設定ファイル由来のボイス・設定案・差分は保存しません。
- `code`: `claude_sdk` / `claude_cli` は Claude、`antigravity_cli` は Gemini、`codex_cli` は各ファイルの OpenAI API / OpenAI OAuth、`opencode_cli` は Ollama の取得モデルから `models` を生成します。`codex_cli` は `realtime` を含むモデルを除外し、同じ系列（`sol` / `luna` / `pro` など）は数値として比較した最新バージョンだけを残します。例: `gpt-6.1-sol` があれば `gpt-5.6-sol` は除外します。`-900k` などの別仕様は独立した系列として扱います。`aidiy_hermes` も OpenAI OAuth の取得モデルを使い、モデルIDに `openai_oauth/` を付けます。合成の `aidiy_hermes.models` には、導入済みCLIの `xx/same`（CLI のモデルを維持して呼び出す選択肢）を追加します（下記）。Claude SDK / CLI はモデルIDから `haiku`・`sonnet`・`opus`・`fable` などの名前を抽出してキーに使い、同名は最新の1件へまとめます。表示名は「YYYY/MM/DD - バージョン付きモデルID」とし、最新バージョンを残します。`copilot_cli` は Claude / OpenAI / OpenAI OAuth のファイルに出力し、Claude は系列ごとの最新モデルをバージョン付きIDのキーで保存し、数字間の `-` を `.` に変換します（キー・表示名とも `claude-haiku-5.5` など）。OpenAI / OpenAI OAuth は `codex_cli` と同じ候補で保存します。詳細配列には元のモデルIDを保持します。作成日・並び順は chat と共通です。
- 固定候補は Grok（`grok_cli`）と backend_local（`local_chat`）だけです。aidiy_diag が管理し、本体は合成JSONから読みます。それ以外は取得に失敗した場合に候補を空にし、状態・説明・警告を残します。

Gemini / FreeAI はモデルIDに `lyria` を含むものを詳細・chat・live・code すべての出力対象から除外します。`antigravity_cli` もこの絞り込み後の候補から生成します。

モデル情報の生成・保存は `_config` 上のモデル設定ファイルに依存しません。API 接続用のキー・ログイン情報の読み取りは従来どおりです。保存するのは、このサーバーが直前に取得した結果と Grok / local の固定候補だけで、画面から値は送りません。

プロバイダ別ファイルへ `xx/same` は挿入しません（旧表記 `xx/auto` が残っていても合成時に除外します）。合成の `code_models_info.json` は導入済みCLIの区分だけを出力します（`claude_sdk` もClaude CLIの導入が必要）。`aidiy_hermes.models` だけは特別に、導入済みCLIの `xx/same` をCopilot → Claude → Codex → Antigravity → Grok → OpenCodeの順で先頭へ追加し、その後に取得したモデルを並べます。導入判定はインストール診断と同じ探索先での実行ファイルの存在確認です。

音声候補は `live_voices_info.json` に `{gemini_live: {voices: {...}}, freeai_live: {voices: {...}}, openai_live: {voices: {...}}}` の形式で保存します。固定定義は `モデル情報/voices_info.mjs` で管理します。キーの確認成功と現在の設定状態に合わせて出力し、未設定・確認失敗のプロバイダは含めません。FreeAIの声はGeminiと同じ定義です。個別更新では他の有効な確認済み候補を保持し、キーが無効化された場合は除外します。

Copilot単独契約向けの例外として、Copilot CLIが導入済みで合成後の `copilot_cli.models` が空の場合だけ、指定のClaude / GPT固定8モデルを指定順・指定日付で補います。取得候補が1件でもあれば補わず、プロバイダ別ファイルへは固定8モデルを保存しません。

プロバイダ別ファイルの書込後に、同じ保存先の全プロバイダ別ファイルを読み、`chat_models_info.json` / `live_models_info.json` / `code_models_info.json` も生成します。chat / live の合成時は FreeAI を先頭に並べます。code は Claude / OpenAI 系を前、`antigravity_cli` を最後に並べます。合成ファイルのルートは `gemini_chat` / `gemini_live` / `codex_cli` などの区分名で、それぞれ `{models}` だけを持ちます。詳細配列や診断の説明はプロバイダ別ファイルに残します。同じ区分名・モデルIDはマージし、表示名が重複するときは日付の新しいものを優先します（実日付は `yyyy/mm/dd` より優先）。個別テスト後の書込でも、他プロバイダの保存済み候補を合成に含めます。

`python backend_diag/_setup.py` または全体の `python _setup.py` で `~/.local/bin` にランチャーを作成します。全体セットアップのDiagは `[y]` の表示だけで選択入力はありません。Windows は `aidiy_diag.cmd` で、このフォルダをユーザー PATH に重複なく自動登録します。ターミナルや VS Code を開き直して使ってください。クリーンアップはこの作業コピーのランチャーを解除し、共有フォルダが空になった場合だけ自動追加した PATH 登録も解除します。既存の PATH 登録や他ツールが使う登録は保持します。`backend_diag/aidiy_diag` / `backend_diag/aidiy_diag.cmd` からも直接起動できます。

Electron の初回表示は Code / Live / Term / IDE / Discord と共通の `frontend_ide/host/scripts/window-opening.cjs` を使います。中央55%から750msで拡大し、描画を待ってから本画面を表示、内容を450msでフェード表示します。実ウィンドウを連続リサイズしないため、Windowsの未描画の白い縁を避けます。ブラウザ版・headlessには適用しません。`desktop-opening` 中は内容を隠し、演出完了後に起動済みを通知します。共通演出の仕様を変更する場合は6種類への影響を確認してください。`node --test backend_diag/checks/desktop.check.mjs` で読込・演出・表示通知の順序、演出中の終了・描画失敗と既存IPCの安全境界を確認できます。実OSでの拡大・DPI・最前面表示は別途目視確認が必要です。

上部は Term と同じ高さのタイトルバー・ウィンドウ操作・接続バーです。シアンバーは `frontend_ide/src/共通表示/シアンバー.css` を共有し、Web / Code / Live と同じ正弦波（4.5秒周期、黒→シアン→黒）で明滅します。透明度の `ease-in-out` へ戻さず、標本化したRGB値を `linear` で補間します。共有CSSも配布UIの整合性検証に含みます。シアンの接続バーはWindowsのアニメーション設定がOFF（`prefers-reduced-motion: reduce`）でも明滅を維持します。ブラウザ確認ではreduce / no-preferenceの両条件で、時間経過による色の変化を検査します。シアンの線は Tools の接続成功、黒は未接続を示します（Tools の確認は常に有効で、ON/OFF・再確認の操作はありません）。診断自体の接続とは別です。Tools は `_config/AiDiy_key.json` の `PORT_TOOLS`（省略時8095）に対して、固定 loopback の `/aidiy_code_agents/ping` だけを10秒間隔で確認します。キー・モデル・エージェントの実行は行いません。切断・画面破棄で確認を停止します。

「導入状況」「モデル一覧」「外部連携」「設定モデル」の Vue タブです。導入状況・モデル一覧・外部連携は保存済みの前回結果があれば初期表示し、なければ未確認です。各パネルの実行ボタン左側に「前回実行日時」を表示します。導入状況パネル右上の「状況確認」で検出・更新します。タブ欄右の「全テスト」は、導入状況・モデル一覧・外部連携をそれぞれ確認して書き込みます（前述）。左側でカテゴリを開閉し、項目を選ぶと右側でパス・バージョン・利用機能・参照ソースを表示します。

保存結果の読込は `診断/前回結果.mjs` に集約します。`install_info.json`、プロバイダ別 `*_models_info.json`、`integration_info.json` の結果・確認日時を表示に使います。通常の確認・一括取得ではファイルを自動保存せず、headless または確認後の「書込」（全テスト内の書込を含む）で保存します。未保存で再起動すると、最後に保存した結果へ戻ります。読込だけでは外部APIを再試験せず、保存結果を今回の認証証跡や書込可能な新規結果として扱いません。欠損・不正なJSONは読み飛ばします。

## システム起動タブ

ミニ表示への切り替えはタイトルバーの共通ボタンで行います。システム起動・アプリ起動のページ内には重複した切替ボタンを置きません。設定起動では自動で切り替えず、通常表示では今までどおり起動に合わせてタブとコンソールを切り替えます。ミニ表示を選んだ場合はその表示を保ちます。起動処理中、または1つでもTCPポートが開放されている間は、「起動対象」がONでポートが未開放の機能を赤く脈動させます。ポートが開けば緑の脈動へ戻ります。通常タブとミニ表示で同じ判定を使い、内部再起動中の一時的なポート閉鎖も赤で示します。起動対象外・未確認だけの場合・全停止後は赤くしません。通常表示は約800ms、ミニ表示は約5秒ごとに確認します。

通常の専用ウィンドウ起動では、最初に127.0.0.1の8095番ポートを一度確認します。Toolsのポートが開放されていれば、主画面の作業領域左上から8px内側にミニパネル（幅384px・高さは表示内容に追従）を表示します。未開放・確認不可なら「システム起動」タブを通常サイズで表示します。通常サイズは画面中央ではなく、作業領域の左上から48px内側（ミニの左上角より内側）に表示を始めます。画面は表示前に準備するため、通常サイズの画面を先に出してから縮小しません。「□」で元の通常表示へ戻せます。Local → Tools → Core → Apps → Task / Team → Web の6機能について、設定と専用コンソールを表示します。Avatar 以降と、診断自身を再起動する項目は対象に含めません。

初回の起動対象はルート `_start.py` の auto と共通です。Tools・Core・Apps・Task / Team・Web が ON、Local は OFF。各機能の「起動対象」「自動再起動」と、Web の「ブラウザで開く」を変更できます。変更は `_config/AiDiy_diag_start.json` へ自動保存され、次回の設定起動にも引き継ぎます。ルートの通常起動の質問・auto は共通の既定値を使い、Diag の保存設定は Diag からの起動に適用します。

Web の「ブラウザで開く」は初期値 ON です。ON の場合、Web の HTTP 正常応答が20秒間続いてから Tools / MCP の `aidiy_chrome_devtools` でページを開きます。一括起動のブラウザ表示にも Tools / MCP が必要です。OFF なら画面を開かず Web のみ起動します。ブラウザの種類を選ぶ項目は設けません。待機中は停止ボタンで取り消せます。HTTP 応答が90秒以内に安定しない場合は起動を中止します。Tools に接続できない場合や Chrome のページ作成に失敗した場合は、コンソールに理由を表示して Web の稼働を続けます。

チェック欄の右側の「手動で開く」は、Tools / MCP と Web のTCPポートが両方とも開放されている場合だけ押せます。チェック欄がOFFでも使え、Chrome MCP経由で `http://localhost:8090/` を開きます。停止中・未確認・処理中は押せません。サービスの起動・再起動や設定の保存は行いません。通常表示でも全6機能のポートを確認し、Diag以外から起動したサービスも判定します。APIでも押下時に両ポートを再確認します。

タイトル欄の「ランチャー表示」で、どのタブからでも6アプリ・利用可能なCLI・6機能の稼働状態を表示する小さな画面へ切り替えられます。ミニのタイトルは「AiDiy ランチャー」です。専用ウィンドウでは幅384pxへ縮小し、高さは表示内容に追従します。タイトル31px・シアン線3px・タイトル文字13pxは通常表示と共通です。タイトルバーの「□」（元のサイズに戻す）で現在のフォーム左肩を保ったまま元の通常サイズに戻ります。通常・ミニとも最前面ピンは OFF で起動し、「ー □ 📌 ×」の📌で最前面表示を切り替えます。OFF は沈んだ表示で、ON のときだけ最前面を維持します。ミニ／通常の切替は現在のピン状態を保持します。ミニ表示中の「□」は元の通常表示へ戻り、通常表示中は最大化／最大化解除を行います。ピン ON の窓が複数ある場合は、最後に選択した窓を前面にし、フォーカスを奪い返しません。ミニ表示中は約5秒ごとに6サーバーのTCPポートを確認し、開放は緑、未開放・未確認は灰色で表示します。別の `_start.py` から起動したサーバーも反映します。各機能にマウスを重ねるとポート番号と開放状態を確認できます。機能名を押すとそのコンソールへ戻れます。切替によるプロセスの起動・停止はなく、ミニ表示中も状態を更新します。通常表示への復帰では元のタブを保持し、サービス名を押すとシステム起動のコンソールへ、未選択の電光掲示板をクリックするかEnter・Spaceで操作するとアプリ起動パネルへ移ります。ブラウザ版は同じタブ内のコンパクト表示です。ポート確認で検出した外部サーバーをDiagの管理対象には追加しないため、Diag終了時の停止対象にはなりません。

右上は、全6機能が未起動のときだけ「設定起動」を押せます。1つでも稼働中、または起動処理中なら「強制停止」に切り替わります。未確認のポートがある場合は設定起動を無効にします。「強制停止」は起動対象のチェック状態にかかわらず、Web → Task / Team → Apps → Core → Tools / MCP → Local の逆順に稼働中の機能を停止します。起動途中の後続処理と自動再起動を抑止し、別の起動方法で動く同機能も既存の停止処理で停止します。停止中は連打を防ぎ、失敗した機能はコンソールに残して他の機能の停止を続けます。全停止後に「設定起動」へ戻ります。「設定起動」は選択した機能をタブの順に起動します。各機能は環境確認、旧インスタンスの停止、新インスタンスの起動の順です。Core / Apps は個別に停止できます。Tools は通常の `_start.py` と同じく、headless 診断の成功を確認してから起動します。失敗時はそのコンソールに理由を表示し、後続の起動を中止します。各機能の「再起動」ボタンでは、その機能だけを再起動できます。

起動処理が次の機能へ進むたびに、対象のタブとコンソールを自動表示します。起動中に別のタブを手動選択した場合は、次の機能の起動が始まるまでその表示を保ちます。完了・失敗時は最後の起動対象を表示し、同じ機能を再度起動した場合も自動でそのタブを表示します。ミニ表示はそのまま維持します。

個別の「再起動」を受け付けたら、その機能の古いログをクリアして今回のログを表示します。ログは折り返さず、長い行は横スクロールで表示します。ログが追加されたら常に最下部を表示します。過去のログへ手動でスクロールしていても、新しいログが届くと最下部へ戻ります。

ログの文字を選択し、**Ctrl+C**（Mac は **⌘C**）でコピーできます。キーボードの Ctrl+C では停止しません。「停止（Ctrl+C）」ボタンからその機能へ割り込みを送り、終了処理を待って停止します。5秒で終了しない場合や割り込みを送れない場合は、残ったプロセスを強制停止します。自動再起動 ON でも明示停止した機能は復活させません。タブ切替・ページ再読込ではプロセスは継続し、Diag 自体の終了時にはその Diag が管理するプロセスを停止します。コンソールはログ表示用で、任意のシェルコマンドを実行する画面ではありません。

Electron の終了ボタンや OS のウィンドウを閉じる操作では、閉じる直前に管理中のプロセスを確認します。起動準備中・稼働中のプロセスがあれば「停止して閉じる」「キャンセル」で確認し、何も管理していなければそのまま閉じます。起動画面以外やミニ表示から閉じる場合も同じです。状態を取得できなければ確認を表示し、既定の選択はキャンセルです。ブラウザ版はタブを閉じても Node.js サーバーを停止しないため、この専用窓の確認は対象外です。

macOS の上部メニューは「AiDiy 診断 → 閉じる」のみです。⌘Q / ⌘W と Dock に追加した「閉じる」も同じ終了確認を通ります。標準の編集メニューを表示せず、⌘C / ⌘X / ⌘V / ⌘A / ⌘Z などの入力操作を維持します。Dock のアイコンは診断用を使います。OS が管理する Dock のアプリ名は、開発用 `Electron.app` のままでは Electron と表示されることがあります。上部のメニュー名とは別で、完全な名称変更は Mac 用アプリバンドルの配布設定で行います。

起動管理には Python 3 と各機能のセットアップが必要です。診断・headless は引き続き Python なしで使えます。システム起動タブは Tools の稼働を必要としません。ページを開く、タブを選択する、全テストを実行するだけでは、サービスを起動しません（`--auto` 指定時の設定起動を除く）。

Windows では、Tools の事前 headless 診断や各機能の環境確認・ポート整理・停止処理のコマンド画面を非表示で実行します。ログは機能別コンソールに表示し、停止ボタンからの Ctrl+C も利用できます。

実装・検証の入口は [_AIDIY/knowledge/backend_diag,環境診断運用.md](../_AIDIY/knowledge/backend_diag,環境診断運用.md) の「起動管理」です。

`--headless` はこの初期ミニ判定・画面表示・HTTP待受を行わず、従来どおり診断と結果ファイルの書込だけを行います。初期ミニ表示は起動時だけ判定し、後からToolsが起動しても通常画面を自動で切り替えません。

## アプリ起動タブ

各アプリの既存アイコンを同梱し、通常画面のカードとミニ表示の起動ボタンで表示します。ミニの「○ / ○ 稼働中」の集計行は表示しません。ミニの起動ボタンはアイコンのみとし、重複する機能名の文字を表示しません。名称はマウスを重ねると確認できます。ミニ表示は通常画面で選択したプロジェクトを共用します。プロジェクト未選択時は英語の案内「SELECT YOUR PROJECT ▸▸ READY FOR LAUNCH」を赤い電光掲示板風（黒い格子線で縦12マスのドット文字）で右端から左端へ15秒かけて流し（titleは「プロジェクト選択してね」）、6種類すべての起動ボタンを無効にします。通常画面のプロジェクト欄も、未選択時は赤い枠と赤いフォルダ選択ボタンで選択を促します。稼働中のサービスは、ミニでは項目全体、通常画面ではタブの下線を緑で非線形に明滅させます。周期は約4.5秒で、項目ごとに4.32〜4.68秒とわずかにずらし、表示のたびに小さな揺らぎと開始位置（0〜周期）を乱数で加えて、そろわず同じ模様も繰り返さないようにします。明るさはタイトルバーのシアン帯と同じ |sin(πt)| の非線形で変化させ、ポート確認が未確認（タイムアウト）のときは直前の表示を保ちます。ミニのサービスを押すと、通常画面のシステム起動タブでその機能を選んだ状態に戻ります。「□」で通常表示へ戻り、アプリ起動タブでフォルダを選ぶと、ミニ表示のボタンも有効になります。ミニ表示からの起動も同じ重複確認・非同期起動を使い、定時監視は増やしません。起動ボタンをクリックして起動要求を受け付けると、アイコンの枠を光が一周します（受付の表示で、起動完了は表しません）。光は IDE の自動探索と同じ conic-gradient の彗星状（暗い尾→シアン→白い先頭、発光付き）で、真下から時計回りに約0.9秒で一周し、加速しながら真下へ戻って消えます。シアンバーと同じく、Windows のアニメーション設定が OFF でも省略しません。

上部の「フォルダ選択」でプロジェクトフォルダを指定し、Avatar / IDE / Term / Code / Live / Discord を個別に開きます。未選択では全アプリの起動ボタンが無効です。Electron は OS のフォルダ選択、ブラウザ版は診断サーバー側のフォルダ一覧を使います。選択したフォルダはタブを移動しても保持し、ページを開き直すと未選択に戻ります。

Avatar は AiDiy 本体のパスから起動します。他の5種類は、選択したフォルダを作業パスとして既存ランチャーへ渡します。別プロセスとして非同期に起動するため、Diag の終了やシステム起動タブの停止でこれらのアプリは停止しません。各アプリの画面から終了してください。起動要求を受け付けたことと、アプリの表示完了は区別します。表示されない場合はカードの「起動ログの保存先」に表示するファイル（`_AIDIY/aidiy_diag/アプリ起動/`）を確認してください。

Avatar・Live・Discord は、ボタンを押した時だけ OS の実行中タスクを確認します。起動済みなら追加起動しません。確認に失敗した場合も追加起動せず案内します。アプリの状態を定期監視しません。IDE・Term・Code は同じプロジェクトでも別の画面を開けます。Diag の IDE / Code 起動では `--new-window` を使い、通常の `aidiy_ide` / `aidiy_code` の既存窓を再利用する動作は維持します。Live / Discord / Avatar の既存ランチャーの排他も維持します。

全テスト・headless・初期画面表示ではアプリを起動しません。検証は `node --test backend_diag/checks/app-launch.check.mjs backend_diag/checks/desktop.check.mjs frontend_ide/checks/project-instance.test.mjs`、実ブラウザの画面確認は `node backend_diag/checks/app-launch-browser.mjs` です。アプリを実際に起動せず、合成タスク・合成プロセスで起動先、重複防止、定時監視なし、画面幅、フォルダ選択を確認します。終了独立性のテストのみ無害な Node.js プロセスを起動し、必ずテスト内で回収します。

## 認証と安全範囲

- 起動ごとに一時認証キーを作成し、API は Bearer 認証を必須とします。認証 URL は他人に共有しないでください。
- キーはブラウザのメモリ内だけに保持し、URL fragment は読込直後に履歴から除去します。再読込時は認証 URL を開き直してください。認証キーをファイル・Storage・アクセスログには保存しません。
- 診断 API は登録済み項目 ID 以外の引数・任意パス・任意コマンドを受け付けません。一括は4 並列、個別は1項目、各 5 秒、出力 16 KiB 上限です。結果には抽出したバージョン番号だけを表示し、生のコマンド出力は表示しません。
- 子プロセスには秘密を含み得る環境変数を渡さず、HOME・作業ディレクトリを一時領域に隔離します。POSIX ではプロセスグループ、Windows では直接起動したプロセスを停止します。Windows で子孫プロセスまでの停止は保証しません。固定の version 引数でも、PATH 上の実行ファイル自体の信頼性や全副作用を保証するサンドボックスではありません。信頼できる環境で使ってください。
- バージョン確認の NG / ERR は、サーバー側の標準エラーへ `[aidiy-diag:probe]` の JSON として出します。項目 ID・固定の version 引数・失敗分類・OS エラーコード・終了コード・シグナルだけを含め、生の子プロセス出力、フルパス、設定・環境変数・キー値は出しません。起動時の OS エラーコードは画面にも表示します。モデル API の通信エラー本文はログに出しません。
- 通常のデスクトップ起動では、NG / ERR と Electron 異常終了の安全な分類を `backend_diag/.desktop-errors.log` に保存します（書込み可能な場合、最大64 KiB、次の追記で容量超過分をリセット）。認証URL・キー・生stderrは保存しません。`aidiy_diag --foreground` では従来どおりターミナルの標準エラーも確認できます。
- GUI、内部ランチャー、安全な version 引数が確認できないものは存在確認のみです。Windows の `.cmd` / `.bat` / `.ps1` はシェル実行しません。npm / npx は既知の隣接 `node_modules/npm/bin/npm-cli.js` / `npx-cli.js` が確認できる場合だけ、Node から固定 `--version` で確認します。対応する実体がない shim は ERR とし、その他のラッパーは存在確認に限定します。
- PATH と登録済みの標準パス・プロジェクト内配置を検出対象とし、API キー・設定 JSON・環境変数の値は表示しません。個別設定による独自パスや venv 内のみにある実行ファイルは、PATH に載っていなければ検出されない場合があります。
- 判定は未確認・未検出・OK・NG・ERR の 5 種類です。OK に含める存在確認は起動試験ではありません。判定の定義は末尾の「状態インジケーター」を参照してください。
- Python / npm のライブラリ依存と外部プログラムは別です。この初期機能は外部プログラムを対象とします。

## 終了・解除

通常の Electron 起動は表示確認後にコマンドプロンプトへ戻ります。Electron 版のウィンドウは1つだけで、起動中にもう一度 `aidiy_diag` を実行すると、新しいウィンドウ・サーバーは作らず既存のウィンドウを前面に表示して終了コード 0 で戻ります（Electron の単一インスタンスロック。ブラウザ版・headless は対象外）。ウィンドウを閉じると HTTP・診断子プロセスも終了します。`--foreground` / `--wait`、`--browser` / `--no-open`、Codespaces・GUI のない環境では起動ターミナルの Ctrl+C で終了します。キーも失効します。`python backend_diag/_cleanup.py` または全体クリーンアップで、この作業コピーのランチャーだけを解除します。別コピーのランチャーは削除しません。全体起動 `python _start.py` では、最初の質問「Diag : 開始しますか? [y]/n」で y（既定）を選ぶと、後続の質問をすべて省き、Code / IDE 以外の AiDiy プロセスを停止してから `aidiy_diag --auto` を起動して終了します。n を選んだ場合は従来どおり機能ごとに起動を選択し、Tools の起動前に `aidiy_diag --headless` の完了を待ってモデル合成JSONを生成します。診断の実行・保存に失敗した場合はサービス起動を中止します。単独ランチャーで起動した診断も、同じ作業コピーのクリーンアップで終了します。停止通知は `.stop-request` の短いランダム識別子のみで、PID・認証キー・診断結果は保存しません。

### 起動時の公開モデル取得

HTTP サーバーの起動後、匿名の公開 OpenRouter モデル一覧を一度だけ非同期で取得します。この操作は設定ファイルを読み取らず、Authorization も送りません。取得に失敗した場合も画面・インストール確認・他の個別テストは使えます。

パネル見出しに「公開モデル一覧取得:」として、ネットワーク取得は「OK」、同梱キャッシュは「キャッシュ利用」、ほかに「取得中」「失敗」「未取得」を 1 か所だけ表示し、個別キーの未実施 / OK / NG とは混ぜません。「再取得」ボタンはキャッシュ利用時だけその右に表示する明示操作で、同時要求は1回にまとめます。設定状況更新では公開キャッシュを消しません。

キャッシュは起動中の Node メモリだけに置き、再起動で破棄して再取得します。元の Python 判定を移植した処理で日付絞り込みした時点のスナップショットです。個別テストはこの整形済み公開情報を同じ Node プロセス内で参照し、OpenRouter を毎回再取得しません。時間が経った情報を更新したい場合は再取得してください。共通システムへの結果保存はありません。

- 実 SDK 契約確認: Tools と同じ `mcp>=2,<3`・FastAPI・uvicorn を持つ Python を環境変数 `DIAG_TEST_PYTHON` に指定し、`node --test backend_diag/checks/model-trials-sdk.check.mjs` を実行します。実際の Chat / Code ツール登録と MCP SDK の初期化・セッション・SSE・文字列結果、実 Live 内部 HTTP ルートを一時 loopback サーバーで検証します。モデル実行と Live アダプターだけを合成し、キー・有料 API・稼働中の Tools は使いません。環境変数未指定時はこの契約テストをスキップします。
- 行別ボタンと配色は `node --test backend_diag/checks/status-badge.check.cjs backend_diag/ui/src/設定モデル/checks/設定モデル.check.cjs` で確認します。実ブラウザの任意確認は `node backend_diag/checks/model-trials-browser.mjs`。既存 Chrome / Edge（必要なら `CHROME_PATH`）を使い、合成データで1回だけの実行・共有表示・見出し配置・狭幅を確認し、`temp/diag-trial-browser/`（`DIAG_SCREENSHOT_DIR` で変更可）へ画像と結果を保存します。

## Predictionの手動試行

設定モデルとAIモデルの両方で、Liveの次にPrediction、その次にDecisionを配置します。AIモデルの「動作確認」／「一括試行」は Chat → Live → Prediction → Decision → Code の順で、各タブの「テスト」はその種類だけを実行します。

- 同じプロバイダ・実行モデルのChat試験が現在の条件で成功した場合だけPredictionを実行します。OAuth、FreeAI、Gemini、OpenAI APIは別の方式として扱い、Googleのキー補完があっても成功結果を共有しません。autoは予測候補と設定から先に解決します。
- 判定はDiagサーバーが保持します。ブラウザからChat成功の申告や履歴本文は受け付けません。設定・候補・OAuth認証の変更、再取得／再読込、手動入力の変更で成功条件を無効化します。Chatの再試行開始時も以前の成功を破棄し、失敗・中止時には流用しません。
- 固定loopbackの `POST /internal/prediction_llms` へ、`X-AiDiy-Diag: model-trial`、解決済み方式・モデル、CODE_BASE_PATHから解決した絶対project_pathを送ります。相対CODE_BASE_PATHは通常履歴と同じbackend_server基準で、未設定時に別プロジェクトへ補完しません。MCPとして公開しません。
- Chatは `aidiy_chat_llms` の `chat_llms_run`、Code系は `aidiy_code_agents` の `code_agents_run` を使い、Predictionと同じ絶対 `project_path` を渡します。実際に送信した入力と成功応答は通常のMCP側でA会話履歴へ保存され、Diagは `history_saved: true` まで確認して成功とします。Chat成功後の1往復は、Predictionが同一プロジェクトの直近2時間・最新最大10ターンを読む通常経路で参照できます。Predictionの試行は、Chat試行でOKになったモデル（予測モデルと同じでなくてよい）で「昔々、あるところに」「おじいさんと」の2ターンをChatとして送り、両方の履歴保存を確認してから予測する。非空の応答はOK、「おばあさん」を含めば `予測評価: 完璧`。1行の期限は通常の2倍。AIモデルタブでは実行中に `GET api/モデル試行/<実行ID>/経過` を1秒ごとに読み、「昔々、あるところに」「おじいさんと」の送信と予測の各段階（状態・秒数）を出力欄に表示する。完了後は結果の `経過` を表示する。テストボタンは入力欄の見出し右側に置く。保存失敗・未確認ではPredictionを解禁せず、診断用の合成履歴や専用APIは使いません。
- Predictionは `status: OK` の非空応答なら `!`／`！` や説明文も合格とします。空・NG・通信失敗・タイムアウトは合格にしません。予測本文は履歴へ保存せず、画面へ返す既知の秘密値は伏せます。
- 検証では実AI・利用者DBを使わず、モックと一時DBで実際のChat入力・応答の保存と通常Prediction参照、4方式の厳密な成功条件、auto解決、失敗後の無効化、認証・本文制限、空／NG／!応答、UIの順序と無効ボタンをmockで確認します。UI変更後は配布物を再生成しmanifest照合を行います。旧fixtureに15行・4種類の固定値がある場合は、新しい16行・5種類へ合わせてから全体回帰を実行してください。

## 予測用モデル一覧

`モデル情報/prediction_info.mjs` が `_AIDIY/aidiy_diag/prediction_models_info.json` を生成する。判断用の生成関数を共用し、低コスト候補・スキーマ・認証条件を `decisions_models_info.json` と揃えたうえで、OpenAI APIの区分だけ実行先に合わせて `openai_decisions` から `openai_chat` へ置き換える。予測JSONに `openai_decisions` は出力しない。

- 出力方式は `openai_oauth` → `freeai_chat` → `openai_chat` → `gemini_chat`。各区分は `{models: {モデルID: 表示名}}`。現在の候補はOpenAI両方式が `gpt-6-luna`、FreeAI/Geminiが `gemini-3.5-flash-lite`。共通の `DECISION_MODEL_CANDIDATES` を使い、別の固定候補は持たない。
- 認証済みの取得一覧に含まれるモデルだけを出力する。表示名は `YYYY/MM/DD - ID`、日付不明時は `yyyy/mm/dd - ID`。候補がない方式は省略し、全方式が空なら `{}` を保存する。公開・固定・旧保存候補からの補完はしない。
- 既存の水色の `一括取得` → `書込`、または headless / 全テスト内の共通モデル書込で更新する。保存先一覧では `prediction_models_info.json` を `decisions_models_info.json` の直前に含める。独立した取得APIや生成試行は追加しない。
- `AiDiy_key.json` の `PREDICTION_AI_NAME` と方式別 `PREDICTION_OPENAI_MODEL` / `PREDICTION_OAUTH_MODEL` / `PREDICTION_GEMINI_MODEL` / `PREDICTION_FREEAI_MODEL` / `PREDICTION_CODEX_CLI_MODEL` / `PREDICTION_COPILOT_CLI_MODEL` / `PREDICTION_AIDIY_HERMES_MODEL` は、方式とChat系4モデルが `auto`、CLI系が `gpt-6-luna`（Hermesは `openai_oauth/gpt-6-luna`）を初期値とする。試行行のモデルは方式に対応するキーを使い、方式autoの行はモデルもautoで送る。CLI方式の候補は合成済みの `code_models_info.json` から `auto` / `same` を除いて載せ。試行はChat試行でOKになったモデルで2ターンを送ってから予測する。候補の書込では設定値を変更せず、予測も実行しない。設定はWeb / AvatarのAI設定画面で変更する。
- 内部RESTの `aidiy_prediction_llms`（`POST /internal/prediction_llms`、MCP非公開）はこのJSONを参照する。方式も `auto` なら、候補が存在する `codex_cli` → `copilot_cli` → `aidiy_hermes` → `openai_oauth` → `freeai_chat` → `openai_chat` → `gemini_chat` の順で1方式を選ぶ。判断側の候補区分・選択順は変更しない。
- 内部RESTは `project_path` を必須指定し、同じプロジェクトの過去会話から次のユーザー入力を返す。候補取得・書込だけでは予測を実行せず、Diagでは設定モデル／AIモデルの明示試行から呼び出す。Code画面の自動提案も同じ内部RESTを使い、トグルは初期OFFとする。履歴非保存などの仕様は [backend_tools 構成](../_AIDIY/knowledge/backend_tools,構成.md#次のユーザー入力予測) を参照する。

## 判断用モデル一覧

`モデル情報/decisions_info.mjs` が `_AIDIY/aidiy_diag/decisions_models_info.json` を生成する。既存の `*_models_info.json` 命名を使用し、`desisions_model_info.json` は作成しない。スキーマは `{openai_oauth: {models: {モデルID: 表示名}}, openai_decisions: ..., freeai_chat: ..., gemini_chat: ...}`。表示名は `YYYY/MM/DD - ID`、取得日が不明なら `yyyy/mm/dd - ID`。認証付き一覧を取得できた方式だけを含める。

- 既存のキー確認と同じGET・ページング・proxy/TLS・制限時間・キャンセルを使い、追加の生成API試行は行わない。判断用の元一覧は公開補完前に分離する。OpenAIは既存の240日・廃止モデル除外、OAuthはAPIが返した表示対象IDのみ、GoogleはgenerateContent対応モデルから候補を作る。明らかな音声・画像・Live・埋込などの専用モデルを除く。JSON/Decisions対応の保証ではなく、実行可否はToolsの既存起動チェックで確認する。
- 公開OpenRouter一覧・同梱キャッシュ・OAuthの固定候補・将来版や900kの合成候補・設定モデルからの補完は行わない。認証の証跡は実行中のメモリだけに保持し、キー値や指紋をJSONへ保存しない。
- 書込時に現在のキー（OpenAIは組織も）またはOAuthトークン・アカウントが取得時と一致することを確認する。キー変更・削除、一覧取得失敗、旧JSONだけが残っている状態は候補にしない。個別確認後は同じDiag実行内で保持する他方式の有効な取得結果を使うが、再起動や設定再読込後は再確認が必要。
- FreeAI/Geminiは判断実行と同じ優先キーを使い、優先キー未設定時だけ他方の認証付き取得結果を代用する。キーが設定済みで認証に失敗した場合は代用しない。
- 空の方式は省略し、全方式が空なら `{}` を保存する。設定・autoの選択順・方式別既定値は書き換えない。生成確認済みの利用可能モデルとこの候補一覧を混同しない。
- headlessと画面のモデル書込は共通処理で生成し、保存先一覧にもファイル名を含める。Pythonの読込口は `conf_models.get_decisions_models()`。Web/Avatar設定画面もこの一覧を利用し、取得済み候補と設定保持値を区別して表示する。
- モック検証: `node --test backend_diag/checks/decisions-info.check.mjs`。4方式、認証変更、公開/固定/旧保存候補の排除、キー代用、失敗・空一覧、共通書込とheadlessの保存先を確認する。

### 判断系4方式の候補管理（2026-10-18）

autoの優先順は `openai_oauth` → `freeai_chat` → `openai_decisions` → `gemini_chat`。起動チェックに成功した方式だけを優先対象にする。

判断系の低コスト方針は `backend_diag/モデル情報/decisions_info.mjs` の `DECISION_MODEL_CANDIDATES` で書き出す候補を絞って管理する。現在はOpenAI両方式が `gpt-6-luna`、FreeAI/Geminiが `gemini-3.5-flash-lite`。将来別モデルへ変更するときはこの候補配列を調整し、認証付き一覧を再取得・書き出しする。実行側や画面にモデル固定・恒久的な選択禁止は置かない。

[Google公式alias説明](https://developers.googleblog.com/en/continuing-to-bring-you-our-latest-models-with-an-improved-gemini-2-5-flash-and-flash-lite-release/) でIDを確認した。最新への追従はGoogle側のalias更新を利用し、番号を推測・並べ替えしてモデルを生成しない。[公式モデル一覧](https://ai.google.dev/gemini-api/docs/models) では現時点の安定版Flash-Liteは `gemini-3.5-flash-lite`。latestは安定版専用aliasではなくプレビュー等を指す場合もあるため、現在の解決先バージョンはこの実装で断定しない。

Diagは認証付きGET一覧に候補配列のIDそのものがある方式だけを掲載する。GoogleはgenerateContent対応を要求する。公開一覧・設定値・別バージョンから候補を捏造しない。未取得・認証なし・失敗・対象ID不在なら方式を省略し、全方式が空なら `{}`。モデル一覧は実行の許可リストではなく、設定画面の候補として扱う。

## OpenCode / Copilot のCode候補

`code_models_info.json` の `opencode_cli.models` はCodex用に合成した候補を共通元とし、OpenCode側のIDと表示名のモデル部分に `openai/` を付ける（例: `openai/gpt-6.1-sol`）。日付・順序は保持し、既存の接頭辞は二重に付けない。Codex候補が0件ならCopilotと同じ `COPILOT_FALLBACK_MODELS` の規定8モデルに同じ `openai/` を付けて補完する。Copilot側の取得候補・規定値は変更しない。OpenCodeの出力条件は自身の導入検出だけで、Codex / Copilotの導入には依存しない。補完はモデル候補の書き出しだけで、認証・実行成功を意味しない。検証は `checks/models-info.check.mjs` で行う。

`aidiy_hermes` / `opencode_cli` のように「プロバイダ/モデル」で渡す方式は、表示名のモデル部分も渡す値そのままにする（例: `"openai_oauth/gpt-6.1-sol": "yyyy/mm/dd - openai_oauth/gpt-6.1-sol"`）。先頭の日付・仮設定表示は保ち、保存済みの古い表示名も合成時にそろえる。

## 判断モデルの手動試行

設定モデル動作確認のLIVE直後に `DECISION / 挨拶の丁寧さ` を表示する。個別「テスト」と全体「動作確認」の両方で、既存MCP `/aidiy_decisions_check/mcp` の `decisions_check` を呼ぶ。HTTP `/check` への代替直結は行わない。Tools接続中の明示操作に限定し、headless・起動・全診断では実行しない。

`DECISION_AI_NAME` と方式別 `DECISION_OPENAI_MODEL` / `DECISION_OAUTH_MODEL` / `DECISION_GEMINI_MODEL` / `DECISION_FREEAI_MODEL` が不足時はauto。方式が明示されている試行行は対応する方式別値を使う。方式autoの行はモデルもautoで送り、Toolsで方式とモデルを解決する。autoの方式順はOAuth → FreeAI → Decisions API → Gemini。結果には実効モデルを表示し、設定ファイルへは書き戻さない。

入力は「おはよう」、質問は挨拶としての丁寧さ、choice名は `politeness`、選択肢は `high / medium / low`。3値すべてを正常な選択として受け付け、特定値を正解とはしない。MCPのJSON内のstatus、回答名・型・選択値、3候補の確率分布・合計、confidenceを検証する。不正JSON・欠落・未知選択肢・通信エラーはNG。結果詳細に選択値と検証済みJSON、実際の実行モデルを表示する。

Chat/Live/Codeと判断結果は共有しない。MCPの初期化・セッション破棄、設定変更による結果破棄、既存のタイムアウトを共用する。判断の行期限を超えた場合はNGと理由を表示し、その全体実行を終了する。ユーザーによる中止は従来の中止表示を維持する。

検証は `checks/decision-trials.check.mjs`、既存モデル試行/API/音声/UIテスト、`DIAG_TEST_PYTHON` を指定する実MCP SDK fixtureで行う。fixtureの生成APIはMockTransportへ置換し、外部の生成サービスを使わない。Web/Avatarの設定画面とDiag試行UIは同じ候補と通常のモデル解決を使う。


## AIモデルの手動試行

「AIモデル」はChat / Live / Decision / Codeの4画面です。初期値はconfigのCHAT・LIVE・DECISION各設定とCODE1を使います。Decisionの方式autoはモデルもautoとしてTools側で解決します。入力の「おはよう」とDecisionのpoliteness / high・medium・lowは `モデル試行/defaults.mjs` を既存設定モデル試行と共用し、手動画面では自由に編集できます。

候補は `_AIDIY/aidiy_diag/{chat,live,decisions,code}_models_info.json` と `live_voices_info.json` の保存済み内容だけです。画面初期読込・再読込は認証付きローカルDiag APIを使い、外部モデル取得は行いません。プロバイダ変更は画面内で候補を連動し、一覧外の設定保持値を未確認として残します。候補の存在は認証・モデル利用成功の保証ではありません。選択や入力をconfigへ書き戻しません。

試行はTools接続中の明示操作だけです。既存 `モデル試行/trials.mjs` のMCP初期化・呼出し・セッション終了、逐次実行ロック、設定変更検知、期限、音声保存を共用します。Chatは `chat_llms_run`、Codeは `code_agents_run`、Decisionは `decisions_check` をHTTP MCPで呼び、Liveだけは既存 `/internal/live_model_check` へ明示した方式・モデル・音声・入力を渡します。Liveの接続後15秒待機・送信後最大60秒待機とアダプター終了処理は共通です。空JSONの従来Live試行は従来のconfigと固定挨拶を使います。

AIモデルタブのタイトルバー「一括試行」は4画面の入力を開始時に固定し、Chat→Live→Decision→Codeを1実行として順に呼びます。NG・行タイムアウトでも次へ進みます。連打は抑止し、入力変更・実行中の画面移動・Tools切断で中止して古い結果を破棄します。全診断・headless・起動ではAI試行しません。設定モデルの15項目試行とAIモデルの4種試行は別の操作です。

Decisionは1問ずつpredicate / choice / scoreを選び、質問名・質問文と、必要な選択肢／段階（2〜32件、重複不可）を編集します。戻り値全体はJSONを読めればインデント付き、読めなければ元文字列を安全なテキストとして表示します。表示できることと回答スキーマの成功判定は別です。既知の秘密値は伏せます。

Liveの応答テキストと1秒以上のWAVを表示し、受信時に認証付き音声APIからBlobを自動取得してネイティブプレーヤーで再生できる状態にします。自動再生しません。AIモデル・設定モデルとも、完了後のタブ移動では再生だけを停止し、結果と取得済み音声を保持します。再実行・設定再読込・切断・終了ではObject URLを解放します。通常は音声再読込の操作を求めず、取得・再生失敗時だけ「音声取得を再試行」を表示します。短い音声・音声なしは明示します。

検証は実AIを使わず、`checks/manual-models.check.mjs`、`ui/src/AIモデル/checks/manual-state.check.mjs` を使います。`DIAG_TEST_PYTHON` をTools依存環境のPythonへ設定すると `checks/model-trials-sdk.check.mjs` が実MCP SDKと合成AIで経路・Liveの15秒待機を確認します。`checks/manual-models-browser.mjs` は既存Chrome/Edgeの隔離プロファイルで4画面・幅1280/720/390・合成音声再生・破棄・一括試行・非JSON表示を確認します。UI変更後は依頼に応じて `backend_diag/ui` のビルドと `node backend_diag/ui/verify.mjs` で配布物を同期します。


## ミニ表示からCLIを開く

タイトル欄左側の「ランチャー表示」は、接続中はどのタブからでも使えます。ミニ内の上段にAiDiy6アプリと導入済みHermes、下段に実行ファイルが見つかったClaude / Codex / Copilot / Agy / Grok / OpenCodeを表示します。外部CLIが0件なら下段ごと非表示にし、ある場合はAiDiyと同じ幅のボタンを中央寄せします。更新ボタンは置かず、ミニ表示時・再接続時に存在確認を自動更新します。表示・確認ではCLIを実行せず、インストールやログインも行いません。存在確認は認証成功・動作保証ではありません。

「アプリ起動」で選択中のプロジェクトフォルダを共有します。フォルダ未選択・切断中は起動できません。ミニのアプリ・CLIアイコンは起動確認ダイアログを出さず、1回のクリックで起動します。CLIは同じフォルダを作業ディレクトリとした `aidiy_term` を開き、従来の自動承認モードで対話CLIを開始します。プロンプトやモデル引数は付けず、CLI自身の既定モデルと既存ログインを使います。起動成功後の説明はミニに表示せず、失敗時のエラーと処理中の表示は残します。選択中のフォルダと未選択時の案内は引き続き表示します。ファイル変更・コマンド実行が自動承認され、Codexではサンドボックスも解除されるため、信頼できるプロジェクトだけで使用してください。CLIの契約や設定によって利用料金が発生する場合があります。

固定起動定義は `frontend_ide/aidiy_term/cli-launch.mjs` をTermとDiagで共用します（2026-10-20 公式資料確認）。

- Claude: `--dangerously-skip-permissions`。[公式CLI参考](https://code.claude.com/docs/en/cli-reference)
- Codex: `--dangerously-bypass-approvals-and-sandbox`。[公式CLI参考](https://developers.openai.com/codex/cli/reference/)
- Copilot: `--yolo`（ツール・パス・URLを含む `--allow-all` 相当）。[GitHub公式参考](https://github.com/github/docs/blob/main/content/copilot/reference/copilot-cli-reference/cli-command-reference.md)
- Antigravity (`agy`): `--dangerously-skip-permissions`。[公式CLI利用方法](https://antigravity.google/docs/cli/using)
- Grok: `--yolo`。[xAI公式参考](https://docs.x.ai/build/cli/reference)
- OpenCode: `--auto`。[公式TUI参考](https://opencode.ai/docs/cli/#tui)、[自動承認の範囲](https://opencode.ai/docs/permissions/#auto-mode)
- AiDiy Hermes: `--yolo`。ローカルの `command_hermes/cli_main.py` が対応しています。provider / model は渡さず、対話CLIの前回選択、未保存ならHermesの自動解決を使います。PATHまたは `~/.local/bin` に配置済みのランチャーが対象です。

組織の禁止・denyルール・初回の信頼確認・ログインなど、CLI側で保持する制約は解除しません。古いCLIが固定フラグに未対応ならTermにそのエラーを表示し、勝手に別フラグや通常モードへ切り替えません。Windowsのnpm `.cmd` は文字列としてシェル実行せず、許可したパッケージの安全な `bin` を検証してNodeから引数配列で開きます。任意のコマンド・モデル・実行ファイル・シェル本文はDiag APIへ渡せません。

Hermes・外部CLIは、同じDiag・同じプロジェクトでもクリックごとに独立したTerm窓を開きます。起動途中や別窓の稼働中も追加起動でき、既存窓を再利用・前面化しません。各窓は別のサーバーポート・端末セッション・起動ログを持ち、1つを閉じても他の窓は続行します。確認付きの呼出しでは確認ダイアログだけを重ねず、承認後の起動は並行して受け付けます。通信の再接続・重複startはその窓が所有する同じCLIに戻り、終了済みCLIを勝手に再実行しません。Diag終了ではTermは終了せず、Term窓・所有サーバーを閉じるとその窓のCLIだけが停止します。ブラウザタブの一時切断は再接続のため30秒だけプロセスを保持し、戻らなければCLIと所有サーバーを終了します。初回の端末接続が表示後30秒以内に始まらない場合も終了し、次回のクリックで再起動できます。既存CLIの全OS横断検出は行いません。Avatar・Live・Discordの単一起動制限と、その他アプリの起動中の排他は変更しません。

アイコンの出典・ライセンス・引用メモは保存先の `ui/src/アプリ起動/CLIアイコン/LICENSE_ICONS.md` に集約し、配布先にも同名の `static/LICENSE_ICONS.md` を同梱します。CopilotはGitHub Octicons、Grokはx.ai公式ブランド配布、OpenCodeは公式リポジトリ、Codex / Claude CodeはLobeHubのMIT素材です。各素材の形状・色を保持し（Copilotは記録済み単色変更）、外部CLIとHermesは白い帯・黒い名称を含む120×120pxの自己完結SVGとして表示します。PNG派生物も同梱します。Hermesは既存AiDiy画像にHERMESの帯を組み合わせ、AgyはAntigravity公式サイトの山形マークです。AiDiy6アプリは名称入りの既存画像を使い、いずれもHTMLで名前を重ねません。アイコンは上段のAiDiy6アプリ＋Hermesと、下段の外部CLI6種の計2行です。CLIは利用可能なものだけを並べます。全アイコンを名称帯込みの40px枠・40px表示へ揃え、元の縦横比を維持します。稼働インジケーター6件は1行で表示します。再生成方法と原本の場所は同フォルダのREADMEを参照してください。

素材の著作権ライセンスとブランド・商標の条件は別です。Codex / Claude Code画像はベンダー公式配布ではなく第三者のLobeHub素材です。AiDiyは各社・各開発チームの提供・承認・提携を示しません。MIT等の全文と素材ごとの制約は `LICENSE_ICONS.md` に保持し、商標利用の包括的な許諾とは記載しません。

自動検証は `checks/cli-launch.check.mjs`、`checks/cli-launch-state.check.mjs`、`checks/mini-cli-ui.check.cjs`、`frontend_ide/checks/cli-launch.test.mjs`、`frontend_ide/checks/cli-terminal.test.mjs`、`frontend_ide/checks/cli-parallel-lifecycle.test.mjs` を使います。合成プロセス・WebSocket fixture・Vueイベントで全タブの切替、ミニの確認なし起動、成功説明の非表示、連続・同時起動、部分失敗、個別終了、ポート・セッション分離、引数と作業パスを検証し、実CLIの認証・有料API・自動作業は実行しません。実Windows窓・DPI・実CLIバージョンとの互換性は別途確認してください。


## アイコン化ランチャー

通常画面の左上は「ランチャー表示」「アイコン化」の2ボタンです。ランチャー表示の左上にも「アイコン化」があり、接続済み・プロジェクトフォルダ選択済み・表示切替中でない場合だけ選べます。

- 通常・ランチャー表示（ミニ）・アイコン化の全切替は、現在のフォームの左肩（左上座標）を引き継ぎます。フォームを移動した後も、その位置から右下へ拡大・縮小します。画面全体の左上や以前の通常位置には戻しません。最大化からミニ／アイコン化へ移った場合も、復帰時は現在位置で通常寸法へ戻します。中央画像40px、展開中はDIAG入りです。中央の下にプロジェクトフォルダ名を表示し、展開中も表示したままにします（展開中は2行まで、全文はツールチップ）。画像自体に枠を付けず、明るい2pxの虹色二重四角を回転させます。二重四角は64px四方で、Codeの開始表示（枠88px・画像54px）と同じ比率です。回転中も四角が画像に掛からず、名前は回転した角の下（中心+48px）に置きます。回転線はぼかさず、背後のダーク背景と影だけを柔らかく広げます。
- 中央クリックで6アプリと利用可能なCLIを均等角度で順番に展開します。有効数をNとして半径は max(80, ceil(58 / (2 sin(π/N)))) px（Nが0〜1なら80px）。最小円周は約503px、隣接中心間隔58pxで40px正方形画像の重なりを避けます。6〜8個は半径80px、10個は94px、13個は122pxです。処理中の一時無効化では数を変えません。
- 収納窓は幅128px、高さは名前の折り返しに合わせて138px以上（1行で138px）、展開窓は半径の2倍+76px（最小236px、13個320px）。表示とネイティブ窓は同じ円周配置の計算を使い、展開中の有効数変更にも追従します。画面端では作業領域の内側に展開し、上中央なら下へ広がります。収納後は元の位置へ戻し、展開中の移動量を引き継ぎます。
- 表示画像40px、操作領域48px。全アイコンに中央と同じ56px四方のダーク背景・8pxのぼかし・影を敷き、外側へ自然に薄くします。CLIだけの硬い黒背景は付けません。丸い囲み枠、内側のサーバー表示、下部の追加マークはありません。
- アイコンは正立したままゆっくり回転し、外周アイコンへのマウスオーバー・キーボードフォーカスで停止します。中央付近にカーソルがあっても回転します。基本操作は中央クリックでの開閉です。10分間操作がなければ自動で収納します。
- 中央を普通にドラッグして移動できます（移動4pxでクリックと区別、長押し不要）。ダブルクリックでランチャー表示へ戻り、途中の通常画面は見せずに切り替えます。Escは展開中なら収納、収納中なら通常画面へ戻ります。
- アイコン化中は無条件で最前面に固定します。解除時は元のピン状態へ戻ります。透明部分は背後へクリックを通します。Web版ではOSの最前面・クリック透過・窓寸法変更は対象外です。

実装上、Windowsのアイコン表示は専用の最前面レベルを設定し、表示切替完了時にも実際の最前面状態を確認します。解除時は共通ピンの選択へ戻します。ドラッグの起点はメインプロセスのマウス押下で記録し、IPC到着前にポインターが動いた場合も最初の移動量を保持します。素早い解放時も最後の位置を反映して終了します。
- アプリとCLIの起動状態・フォルダは既存状態を共有します。CLIから開くTermは作業領域中央に約800×600pxで表示します。

画面は backend_diag/ui/src/アプリ起動/マイクロランチャー.vue / .css、共通寸法は同フォルダの 円周配置.cjs、窓制御は backend_diag/起動/マイクロ表示.cjs です。回帰確認は node --test backend_diag/checks/micro-window.check.mjs backend_diag/checks/icon-drag.check.mjs backend_diag/checks/desktop.check.mjs。配布画面を更新するときは npm --prefix backend_diag/ui run build と npm --prefix backend_diag/ui run check を実行します。

### 再読込時の認証

認証済みの起動キーは、同じタブ・ウィンドウの同じ公開元とパスの `sessionStorage` にだけ保持し、Ctrl+Rでも再接続します。URLのキーは従来どおり表示履歴から除去し、永続的な `localStorage` には保存しません。新しい起動URLや手入力は古いキーを置き換え、401応答では破棄します。サーバー再起動後は新しい認証URLまたはキーが必要です。ストレージを利用できない環境では従来のメモリ保持に戻り、再読込後は再入力が必要です。

### VS Code ランチャー

アプリ起動・ミニ・アイコン化の外部ランチャーに VS Code を表示します。導入タブと同じ実行ファイル探索を使用し、未導入時は通常画面で無効、ミニ・アイコン化では非表示です。選択した実在プロジェクトフォルダを `--new-window` で開きます。Term・AI CLI・自動承認は使用せず、フォルダ未選択・削除済みの場合は別フォルダへ代替しません。Windows の `code.cmd` は同梱 `Code.exe` を直接起動し、パスをシェル文字列に展開しません。呼び出し元のプロキシ環境変数を引き継ぎ、Diag 終了時にも VS Code は独立して継続します。

公式原画を保持したうえで、表示用は青帯・白字 VSCODE を含む SVG と120px PNGに合成しています。出典・利用条件は `ui/src/アプリ起動/CLIアイコン/LICENSE_ICONS.md`、コマンド仕様は https://code.visualstudio.com/docs/configure/command-line を参照してください。
