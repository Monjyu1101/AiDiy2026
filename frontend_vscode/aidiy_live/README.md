# AiDiy (Live)

`aidiy_live` は AiDiy のライブ会話だけを使う小さな画面です。表示名は **AiDiy (Live)** です。独立した VS Code 拡張とスタンドアロンを提供し、既存の `backend_server`（8091）へ接続します。バックエンドの変更は必要ありません。

## VS Code 拡張

`frontend_vscode` の `npm run package` で `dist/aidiy-live-0.1.0.vsix` を生成します。通常のセットアップでは Code / Live の両方を配置します。手動の場合は VS Code の「VSIX からのインストール」で Live の VSIX だけを選択できます。拡張 ID は `aidiy.aidiy-live` です。

コマンドパレットの「AiDiy (Live): ライブ会話を開く」で右サイドバーに表示します。Code 拡張への依存はなく、それぞれ個別に無効化・解除できます。別のタブへ切り替えて Live の画面を非表示にしても、接続と会話は保持します。非表示中はマイクを停止し、戻った後も OFF のままです。マイクを ON にすると音声入力を再開できます。非表示中に受信した会話は戻ったときに表示し、音声はまとめて再生しません。切断・拡張停止時はマイクと通信を終了します。

VS Code の Webview はマイク権限を提供しないため、Windows の入力デバイスから Python 標準ライブラリの `ctypes` / WinMM で取り込み、同じ AudioWorklet 音声処理へ渡します。設定 `aidiyLive.pythonPath` が空なら、作業フォルダまたは親フォルダの `backend_tools/.venv/Scripts/python.exe`、次に PATH の `python` を探します。追加の Python ライブラリは不要です。Windows のマイクアクセスを許可してください。入力デバイスがない場合は画面にエラーを表示します。自動減衰は拡張でも共通ですが、ブラウザ標準のエコーキャンセルはブラウザ版のみです。

接続先は `aidiyLive.backendUrl`（既定 `http://127.0.0.1:8091`）で設定します。「専用ウィンドウで開く」コマンドは、配布済み Live 拡張のファイルだけでブラウザ版を起動できます。Windows 以外でのマイク入力にもブラウザ版を使用してください。

## 起動

既存の AiDiy バックエンドを起動しておき、プロジェクトルートで実行します。

セットアップ後は `aidiy_live` コマンドで起動できます。

```powershell
.\frontend_vscode\aidiy_live.cmd
```

または `frontend_vscode` で実行します。

```powershell
npm run live
```

Electron は既存の `frontend_vscode/node_modules` の配置済みバイナリを使います。依存が未導入の場合は従来の `python frontend_vscode/_setup.py` でセットアップしてください。ライブ画面の変更後は `npm run live:compile` で更新します。

Electron が未配置、または起動に失敗した場合はブラウザへ自動で切り替えます。Windows では Chrome / Edge があれば420×650の専用ウィンドウで開きます。通常起動とブラウザ版起動は、起動後に CMD / PowerShell へ戻ります。ブラウザ中継は別プロセスで動き、最後の画面を閉じて約60秒後に終了します。`--foreground` は起動診断用で、サーバーをターミナルで実行します。

ブラウザで使う場合:

```powershell
npm run live:browser
```

ターミナル上で実行したい場合は `npm run live -- --browser --foreground` を使い、Ctrl+C でサーバーを終了します。URL だけを表示する場合は `npm run live -- --serve` を使います。

接続先を変える場合:

```powershell
npm run live -- --backend http://127.0.0.1:8091
```

## 操作

初期案内は英語の「CONNECT, THEN TURN YOUR MIC ON.」「YOU CAN ALSO TYPE TO CHAT.」を等幅フォントで順に表示し、シアンのカーソルを点滅させます。Code と同じ8秒周期のタイプ表示で、文字の入力を始めると全文表示へ切り替えます。

- 上部は「音声会話」「新しい会話」「接続／切断」を1行に並べます。「接続」で新しい専用セッションを開始します。既存 Avatar の会話とは別のセッションです。
- 「音声会話」の横にフォルダ名を表示します。スタンドアロンはコマンドを実行したフォルダ、VS Code は現在のエディターに対応するワークスペース（なければ先頭のローカルフォルダ）を使います。長い名前は省略し、マウスを重ねるとフルパスを表示します。Live の会話処理へフォルダは送信しません。
- 未接続時は「接続」ボタンをシアンでゆっくり明滅させます。接続処理中は止め、接続完了後はタイトル行の下の2pxバーを Code と同じシアン・4.5秒周期で明滅させます。切断するとバーは黒へ戻り、接続ボタンの明滅を再開します。VS Code 拡張でも同じ表示です。
- マイクは接続直後 OFF です。「マイク OFF」をクリックすると音声を送信します。初回は OS / ブラウザのマイク許可が必要です。
- スピーカーは未接続・接続処理中・切断後に OFF 表示となり、操作できません。接続完了後に再生設定に応じて ON/OFF を表示し、操作を再生とサーバー側の音声状態へ反映します。
- 背景の円形の音量雲は、AI の発声を水色、マイクを赤色の線で表示します。実音量と周波数に合わせて輪郭が広がり、静かな時は細い輪に戻ります。マイクの周波数は自動減衰前、輪の広がりは減衰後の送信音量を使います。動きを減らす OS 設定では回転・揺れを抑えます。
- 双方向通話中はブラウザ標準のエコーキャンセルに加え、既存 Web 版と同じマイク振幅の自動減衰を行います。AI の実再生音量が `0.01` を超えた場合、入力振幅から「再生音量 × 1.5」を差し引きます。停止・ミュートで解除され、OS のマイク音量は変更しません。
- 文字を入力して「送信」を押すとライブ AI へ送ります。送信ボタンは未接続では灰色、接続済みで空欄・空白だけの入力では白背景・青紫の枠・黒い紙ヒコーキの無効状態で、接続済みかつ送信する文字があるときだけ Code と同じ青紫になり、送信できます。送信後は入力を消して白背景・黒い紙ヒコーキへ戻します。Enter は改行です。
- 入力欄は Code と同じ全幅で、その下に操作説明、接続状態、モデルボタンを並べ、紙飛行機ボタンを右端に置きます。「モデル」で既存サーバーのモデル・声の候補を開き、「この会話に適用」で切り替えます。共通設定ファイルへの保存やサーバー再起動は行いません。切り替え後のマイクは OFF です。
- 「新しい会話」は現在の接続を閉じ、表示をクリアします。次の接続で新規セッションを作ります。
- 切断・ウィンドウ終了時にはマイクのトラック、再生音声、3つの WebSocket を閉じます。再接続は手動です。

会話表示は最新100件までです。永続履歴と音声認識は既存バックエンドが担当し、この画面ではローカルへ保存しません。ライブ AI の API キー・モデル設定・音声認識の利用可否も既存バックエンドに従います。現行 AIコア WebSocket / モデル情報 API には JWT を渡す接続仕様がないため、その仕様を使用します。

## 構成

| ファイル | 役割 |
|---|---|
| `src/protocol.ts` | 既存 AIコアの init / input / 0 / audio 接続とパケット |
| `src/audio.ts`, `media/capture.js` | AudioWorklet で入力を16/24kHz PCM16へ変換、24kHz出力を順次再生 |
| `src/visualizer.ts` | 実音声に連動する円形の音量雲を Canvas へ描画 |
| `src/view.ts`, `media/index.html`, `media/style.css` | 会話・音声操作・モデル選択の共通画面 |
| `src/server.ts` | localhost の HTTP / WebSocket 中継。接続先は起動時に固定 |
| `src/extension.ts`, `src/host.ts`, `src/bridge.ts` | 独立 Live 拡張、拡張側の通信、共通画面への IPC |
| `microphone.py` | Windows のネイティブマイクを48kHz PCM16で取り込む |
| `desktop.cjs`, `preload.cjs`, `launch.mjs` | Electron の専用ウィンドウと起動処理 |

中継はランダムポート・ランダムURLで `127.0.0.1` にだけ公開し、Host / Origin を照合します。REST はモデル取得とモデル設定の2経路に限定します。WebSocket は `/core/ws/AIコア` にだけ接続します。

拡張では通信を拡張ホスト側で行い、音声処理・パケット・画面はスタンドアロンと共有します。Live の VSIX に必要な画面、音声処理、マイク補助を含め、Code の VSIX には含めません。

## 検証

### マイクを ON にできない場合

専用ウィンドウの許可判定は URL の `origin` を比較します。Electron が返す末尾 `/` 付きの origin を文字列の完全一致で拒否しないようにし、専用画面のメインフレームからの音声入力だけを許可します。

`Requested device not found` は、実行中の Windows に入力デバイスが見えていない状態です。まず Windows の「設定 → システム → サウンド → 入力」でマイクが選べることを確認します。出力に「リモート オーディオ」があるだけではマイク転送の確認にはなりません。

リモートデスクトップを使う場合は、接続元の「リモート デスクトップ接続」で「オプションの表示 → ローカル リソース → リモート オーディオの設定」を開き、録音側を「このコンピューターで録音する」にして再接続します。接続元のマイクを既定の入力に設定し、接続先のサウンド入力にも現れることを確認してから Live を起動し直します。Windows に入力が見えない状態では、ブラウザ方式でも WinMM 方式でも録音できません。[Microsoft の録音転送手順](https://devblogs.microsoft.com/devops/enable-remote-audio-capture-to-when-testing-or-providing-feedback-on-remote-machines/)も参照してください。

画面には入力デバイスなし、アクセス拒否、録音デバイスを開けない場合を分けて案内します。模擬入力による Electron / AudioWorklet の検証と、実マイクによる確認は区別してください。

`frontend_vscode` で実行します。

```powershell
npm run live:check
npm run live:test
```

自動検証は模擬バックエンドでセッション、音声パケット、WebSocket 中継、モデル API、切断、Origin 拒否を確認します。実際の会話は、接続後にマイクを ON にし、背景の音量雲・AI音声・会話表示、マイク OFF、スピーカー OFF、音声停止を確認してください。ヘッドホンの使用でスピーカーからの回り込みを抑えられます。
