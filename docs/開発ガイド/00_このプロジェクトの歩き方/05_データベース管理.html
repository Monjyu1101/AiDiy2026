05. データベース管理

SQLiteの概要

このプロジェクトではデータベースにSQLiteを使用しています。

この章で学ぶこと
  • SQLiteデータベースの基本
  • スキーマの確認方法
  • テーブル構造の変更手順
  • データベースのリセット方法
ポイント: SQLiteの特徴

SQLiteはファイルベースのデータベースです。サーバー不要で動作します。
_data\AiDiy\database.db が実体ファイルです。
サーバー起動時にModelの定義からテーブルが自動作成されます。

どこを見るか

確認したいこと ファイル / 場所
テーブル定義 backend_server/core_models/ および backend_server/apps_models/
テーブル作成の流れ Modelの定義 → database.db にテーブル自動生成 → サーバー起動時に実行
DBファイルの場所 _data\AiDiy\database.db
DB接続設定 database.py を参照

スキーマ変更手順

このプロジェクトではAlembic等のマイグレーションツールは使用していません。
現行実装ではModelを更新し、既存DB向けの差分SQLを backend_server/core_crud/init.py または backend_server/apps_crud/init.py の起動時処理へ冪等に追加します。

1. Modelファイルを編集

backend_server/core_models/ または backend_server/apps_models/ のModelファイルを編集します。

# 例: backend_server/core_models/C利用者.py
class C利用者(Base):
 __tablename__ = "C利用者"

 利用者ID = Column(Text, primary_key=True)
 # ↓ 新しいカラムを追加
 メールアドレス = Column(Text)

2. 起動時の差分処理を追加

inspect() でテーブルとカラムの存在を確認してから、必要な場合だけ ALTER TABLE などを実行します。再起動しても同じSQLを重複実行しない形にしてください。

if inspector.has_table("C利用者"):
 columns = [column["name"] for column in inspector.get_columns("C利用者")]
 if "メールアドレス" not in columns:
  db.execute(text('ALTER TABLE "C利用者" ADD COLUMN "メールアドレス" TEXT'))
  db.commit()

3. サーバーを再起動

サーバーを再起動すると、新規テーブルは create_all()、既存テーブルは上記の起動時差分処理で反映されます。

cd workspace/AiDiy2026
python _start.py
注意事項
  • 本番データや検証データを残す場合、database.db を削除しないでください
  • カラム削除、複合主キー変更、テーブル再作成を伴う処理は必ず事前バックアップを取って検証してください
  • 初期データはSQLiteのテーブル作成時に自動投入されます
初期データの投入条件

初期データ（admin等のアカウント）は「adminが未存在」の場合のみ投入されます。
既存DBにadminが存在する場合、初期ユーザーは重複投入されません。初期値を変更したい場合は、対象レコードを明示的に更新してください。

補足情報

モデル変更だけでは既存テーブルへ差分が入りません。
詳細な判断と確認方法は _AIDIY/knowledge/backend_server,スキーマ変更手順.md を優先してください。DB削除によるリセットは、データ破棄が許可された開発環境に限る最終手段です。

構造確認の方法

データベースの構造を確認するには以下の方法があります。

方法1: Modelファイルを読む

Modelファイルを直接読むのが最も確実な方法です。

  • backend_server/core_models/ - C系・A系テーブル
  • backend_server/apps_models/ - M系・T系・V系・S系テーブル

方法2: SQLiteのGUIツール

GUIツールを使うと視覚的にテーブル構造を確認できます。

  • DB Browser for SQLite (https://sqlitebrowser.org/) - 無料のGUIツール
  • VS Code拡張機能 - SQLite Viewer 拡張機能をインストール

_data\AiDiy\database.db を開いて確認できます。

方法3: SQLコマンドライン

# SQLiteコマンドラインを起動
sqlite3 workspace/AiDiy2026/_data\AiDiy\database.db

# テーブル一覧を表示
.tables

# テーブル構造を表示
.schema C利用者

# 終了
.quit

データベースリセット

リセット手順

データベースを初期状態に戻すには以下の手順を実行します。

# 1. サーバーを停止 (Ctrl+C 推奨)

# 2. データベースファイルを削除
del workspace/AiDiy2026/_data\AiDiy\database.db

# 3. サーバーを再起動してDBを再作成
cd workspace/AiDiy2026
python _start.py
重要

リセットすると全データが失われます。必要に応じてバックアップを取ってください。

バックアップと復元

データベースファイルをコピーするだけでバックアップできます。

# バックアップ
copy workspace/AiDiy2026/_data\AiDiy\database.db workspace/AiDiy2026/backup\database_20260214.db

# 復元
copy workspace/AiDiy2026/backup\database_20260214.db workspace/AiDiy2026/_data\AiDiy\database.db

ID採番の仕組み (C採番)

本プロジェクトではAUTOINCREMENTを使用せず、C採番テーブルでIDを管理しています。

  • 各テーブルの最終番号をC採番テーブルに記録
  • 新規レコード作成時にC採番から次のIDを取得
  • トランザクション保護でID重複を防止

C採番テーブルの確認・編集は管理画面の「C採番」メニューから行えます。

トラブルシューティング

問題1: テーブルが見つからない

エラー: OperationalError: no such table

対処法: Modelのexportと core_main.py / apps_main.py の create_all(tables=[...]) 登録を確認し、サーバーを再起動します。新規テーブル追加だけならDB削除は不要です。

問題2: カラムが見つからない

エラー: OperationalError: no such column

対処法:

  1. Modelファイルにカラム定義があるか確認
  2. core_crud/init.py / apps_crud/init.py に対象差分の冪等処理があるか確認
  3. バックアップ後にサーバーを再起動し、SQLiteの実カラムを確認

問題3: データベースロック

エラー: OperationalError: database is locked

対処法:

  1. 他のプロセスがデータベースを使用していないか確認
  2. タスクマネージャーで python.exe プロセスを確認
  3. taskkill /F /IM python.exe で強制終了
  4. サーバーを再起動
