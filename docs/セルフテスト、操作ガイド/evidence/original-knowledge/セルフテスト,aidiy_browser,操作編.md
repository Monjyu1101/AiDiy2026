## 始める前に

DiagでToolsを起動し、作業フォルダを選びます。[システム起動編](./セルフテスト,aidiy_diag,システム起動編.md)と[ランチャー編](./セルフテスト,aidiy_diag,ランチャー編.md)を参照してください。Code／Liveへ渡す場合は、同じ作業フォルダで渡し先も起動します。

## 1. Browserを開く・Webページを操作する

1. Diagのランチャーで「Browser」を押します。作業フォルダから `aidiy_browser` でも起動できます。
2. 「AiDiy Browser」が開き、接続表示が「ブラウザ」になることを確認します。
3. アドレス欄へURLまたは検索語を入力し、「開く」またはEnterで移動します。

   日本語配列キーボードを遠隔操作するときは、入力後にURLの `:` と `/` を確認します。記号が違う場合はURLを貼り付けてから移動します。
4. アドレス欄の左側で、戻る・進む・再読込・停止・ホームを操作します。

   履歴移動を確認する場合は、見た目の違う安全なページをA、Bの順に開き、「戻る」でA、「進む」でBへ移ることをURLと本文の両方で確かめます。2026-11-01の実演では、ローカルの `X自己紹介/index.html` と `Xテトリス/index.html` を素材に往復しました。ゲームの開始などページ内の操作はしていません。全画面では上端の操作パネルを表示し、📌で常時表示にして矢印とアドレス欄を確認できます。透明なパネルと本文が重なる場合は、URLの読み取りを終えてから移動します。 履歴移動だけを紹介する場合は、通常窓のまま矢印・アドレス・本文見出しを同時に見せると、全画面パネルとの重なりを避けられます。静止素材には `docs/開発ガイド/_index.html` と `docs/開発ガイド/00_このプロジェクトの歩き方/01_はじめに.html` を使えます。この順に開き、後者から戻る・進むを1回ずつ操作し、「AiDiy2026 開発ガイド」と「01. はじめに」の見出し、および各ファイルURLを照合します。2026-11-02の実演でこの往復を確認しました。ページ内リンクや送信は操作していません。

## 2. FHD・縦表示・全画面を切り替える

開発中のWebページを横長・縦長の画面で動作テストするための表示切替です。FHDの横画面（1920×1080）を基準に、ヘッダーなどの操作欄に使う高さ135pxを差し引き、Web本文の表示領域を確保します。

| ボタン | Web本文の表示領域 | 開発時に確認すること |
|---|---|---|
| FHD（横） | 1920×945 | 横長画面でのレイアウト、一覧や入力画面の収まり |
| 縦表示 | 1080×1785 | 縦長画面での折り返し、並び替え、スクロール |

縦表示はFHDを縦にした1080×1920から、同じ135pxを差し引いた高さです。寸法はヘッダー・アドレス欄を除くWeb本文のCSSピクセル数で、窓全体の寸法ではありません。ページの表示倍率は100%に戻ります。

画面に収まらない場合もWeb本文を縮めず、操作欄のある窓の左上を画面内に残します。縦表示はスマートフォンの端末エミュレーションではなく、Webページを縦長の表示領域で確認する機能です。

Windowsの表示倍率によって、物理画面上の窓の寸法は本文のCSSピクセル数と異なります。縦表示で下端が画面外へ出たときは、上端の操作欄からF11で全画面へ切り替えられます。表示を切り替えるたびにボタンの現在位置を確認してください。 FHDでも表示倍率により右端の操作欄が画面外へ出る場合があります。その場合はF11キーで全画面にし、上端へマウスを移して現れるパネルから縦表示などを選べます。2026-11-02の実演ではこの経路で縦表示へ切り替え、同じローカルページの見出し・一覧と、画面外へ続く窓の下側を確認しました。本文に `max-width` がある素材では、折り返しより周囲の余白が変わるため、表示領域の変化とページ側のレイアウトを分けて観察します。

「F11」ボタンまたはF11キーで全画面にし、もう一度F11で元の窓へ戻します。全画面では上端へマウスを移すと操作パネルが現れます。パネルの📌をオンにすると常時表示、オフにすると収納します。再表示はマウスをいったん離してから上端へ合わせます。

パネルの背景やタイトルを0.5秒長押しすると移動でき、📌も自動でオンになります。通常の窓の📌は最前面表示、全画面パネルの📌はパネルの常時表示です。


透明な操作パネルと本文が重なる場合は、操作欄を見る場面と本文を読む場面を分けます。常時表示がオフの状態でマウスを上端から離し、パネルが収納された実画面を確認してから本文を案内します。2026-11-02の実演では、F11による全画面化、上端でのパネル表示、マウスを離した収納、F11で通常窓への復帰を確認しました。素材ページの本文位置も途中で変わったため、パネルの出入りとページ側の移動を同じ動作として説明しないでください。

静止素材で位置を確認する場合は、既存の `docs/開発ガイド/_index.html` をファイルURLで開けます。スクリプト・外部リソース・CSSアニメーションのない素材で、読込後に見出しと一覧の位置が落ち着いていることを先に確認します。2026-11-02の短い撮り直しでは、通常窓で約20秒観察した後に全画面へ切り替え、「ガイド一覧」と先頭項目がパネル表示・収納の前後で同じ位置に残ることを確認しました。全画面切替で操作欄がなくなる際の配置変化と、同じ全画面状態でのパネル出入りを分けて見ます。今回の素材では、前回の継続的な本文位置の変動は観測しませんでした。

## 4. URLと画像をCode／Liveへ渡す

1. 同じプロジェクトでCodeまたはLiveを起動します。
2. Browserの「Code / Liveへ」を押し、渡し先を選びます。
3. 「下書きへ追加」を押し、渡し先の入力欄を確認します。

Browserのセッション名・タブID・URLを既存の下書きへ追記します。撮影から60秒以内なら画像の絶対パスも添えます。撮影がない場合や60秒を超えた場合は画像を添えません。候補がなければ同じプロジェクトのCode／Liveを起動し、一覧を更新します。

連携先がない場合は「連携先: 未選択」と起動を促す案内が表示され、「下書きへ追加」は押せません。渡し先を用意して「最前面を再選択」で確認するか、選択画面を開き直します。「Code 1」などの連携先名を確認してから追加し、渡し先の入力欄にURL等が追記されたことを見ます。

AIへの送信は渡し先で行います。「下書きへ追加」だけではAIを実行しません。

画像なしで試す場合は撮影せず、安全なページのURLを渡します。アドレスを自動入力するときは貼り付け後に記号も含めて照合してから開きます。渡し先を選ぶと案内の行数によってボタン位置が変わるため、選択後に「下書きへ追加」の位置を確認します。

渡し先に「Code 1」を選択した状態です。複数候補があれば「最前面を再選択」で選び直せます。

## 5. Browserを終了する

右上の「×」でBrowserを閉じます。MCPから使う場合は、そのBrowserのセッションを指定して `close_session` でも終了できます。終了した窓と専用セッションが残らないことを確認します。

撮り直しや連携実演で開き直した窓も、使い終わった時点で確認します。全画面では上端へマウスを寄せ、Browserの操作パネルの「×」を押します。起動前には既存窓を再利用できるか確認し、終了時は自分が開いた対象だけを閉じます。利用者の別窓やDiag・サーバーは終了しません。

### 長押しドラッグの実機確認（2026-11-02）

Windows実機で `mouse_long_press_drag`（保持0.8秒、移動0.6秒。Browser全画面は移動0.8秒）を使用。直前の画面から対象を同定し、移動後の実画面とOSの窓位置を照合します。入力欄・ボタンの除外判定は下記の実施対象に限定します。位置は画面座標の (x,y) です。

標準窓の背景移動、アドレス入力欄の移動抑止、全画面ヘッダーの長押し移動とピンON・ポインター退避後の常時表示を実機確認。標準窓は (265,86) → (325,126)、全画面ヘッダーは (460,0) → (460,829)。静止した既存ローカルHTMLを使用。独立したミニ／アイコンモードは対象外。
