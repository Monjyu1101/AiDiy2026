Aタスク要求、Aタスク明細 TK00001002 は自動ビデオ生成タスクです。
そのタスクは、いつも何かしらのエラーで停止していることがあります。
このタスクは、そのタスクを監視、異常時は改善と途中から再開させるためのタスクです。
エラーとなっている場合のみ、次回のイレギュラー停止をゼロに近づけるため、
以下の処理を行ってください。

対象は TK00001002 に固定です。他のタスクIDには一切手を触れないでください。


【明細構成】

分岐が無いので、次の3明細だけにしてください。

  SEQ 0     開始        先行SEQ なし   操作検証なし   予測分数 1
  SEQ 1     確認と処理  先行SEQ 0      操作検証あり   予測分数 30
  SEQ 9999  終了        先行SEQ 1      操作検証あり   予測分数 5

状態の確認と復旧はすべて API で行います。DB を直接更新しないでください。
TaskTeam API: http://127.0.0.1:8093/task


【SEQ 1 確認と処理】

■ 手順1 停止検査

  POST http://127.0.0.1:8093/task/タスク要求/停止検査
  Content-Type: application/json
  {"タスクID": "TK00001002"}

読み取り専用の API です。DB は変更されません。
応答の data.items[0] に次が入っています。

  停止                  止まっているか
  停止理由              止まっている内訳（複数）
  復旧可能              true なら手順3の停止復旧で戻せる
  再開SEQ               復旧後に再開する明細SEQ
  進捗                  状態ごとの明細件数
  エラー明細            応答内容つき。原因追及はこれを使う
  実行有効オフ明細      未完了なのに実行有効が外れている明細
  タイムアウト超過明細  実行中のまま制限を超えた明細（経過分 / 制限分つき）

分岐は次の3つだけです。

  (a) 停止 = false
      改善も復旧も行わず「停止なし。処理不要」と報告して完了する。

  (b) 停止 = true かつ 復旧可能 = false
      実行中の明細が打ち切り時間を超えているだけで、まだ生きている可能性がある。
      勝手に止めず、監視ループの打ち切りを待つ。
      該当明細の 明細SEQ / 経過分 / 制限分 を報告して完了する。

  (c) 停止 = true かつ 復旧可能 = true
      手順2へ進む。

■ 手順2 改善内容

Aタスク明細のエラー内容を分析、原因を追究し、改善を行ってください。
スクリプト改善は、
backend_tools\aidiy_automations\ビデオページ生成\ビデオページ生成_解説.py
に行ってください。類似のロジックを持つ同フォルダ内のpythonも改善しておいてください。

エラー内容は手順1の応答の エラー明細[].応答内容 にあります。
応答内容が空でも、予測分数に対して実績分数が2倍を超えている明細は
タイムアウトで強制停止されたものとして原因を追ってください。
ログは backend_taskteam/temp/task/ 配下にあります。

原因が特定できても安全に直せない場合は、直さずに原因だけを報告してください。
推測で直さないでください。

■ 手順3 停止復旧

  POST http://127.0.0.1:8093/task/タスク要求/停止復旧
  Content-Type: application/json
  {"タスクID": "TK00001002"}

この1回で次がすべて行われます。個別に明細を戻す必要はありません。

  ・Aタスク要求と全明細の 実行有効 を 1 にする
  ・エラーの Aタスク要求 を 待機 に戻す
  ・エラーの Aタスク明細 を 待機 に戻し、PID・開始日時・終了日時・実行回数・実績分数を初期化する
  ・完了済みの明細はそのまま残す（だから最初からではなく、止まった所から再開する）

■ 手順4 復旧の検証

手順3の応答が status=OK でも、それだけで完了報告しないでください。
手順1と同じ停止検査をもう一度呼び、次をすべて満たすことを確認します。

  1. 停止 = false
  2. 要求状態 = 待機、要求実行有効 = 1
  3. 進捗にエラーが 0 件

すべて満たしたときだけ task_check_okng に 完了 を報告してください。
1つでも満たさない場合は、満たさなかった項目と実際の値を書いて エラー を報告してください。
検査応答の該当部分を報告本文に必ず貼ってください。


【SEQ 9999 終了】

SEQ 1 の結果を踏まえて報告してください。

  ・停止の有無と、止まっていた場合はその原因
  ・修正したファイルの一覧（修正なしの場合は「修正なし」）
  ・復旧後の 要求状態 / 要求実行有効 / エラー明細件数 / 再開SEQ

復旧できていない場合は完了報告せず エラー を報告してください。


【禁止事項】

・TK00001002 以外のタスクの状態を変更しない
・DB を直接 UPDATE しない（必ず API を使う）
・停止検査で 停止 = false のときに停止復旧を呼ばない
  （実行中のタスクを巻き戻して二重起動させる恐れがある）
・停止復旧の 強制 オプションは使わない
・原因が不明なまま「改善しました」と報告しない
・手順4の検証を省略しない
